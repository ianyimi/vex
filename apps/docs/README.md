# VexCMS Docs

This is the VexCMS documentation site — [Starlight](https://starlight.astro.build)
on [Astro](https://astro.build), with the API reference generated from
source JSDoc via [`starlight-typedoc`](https://github.com/HiDeoo/starlight-typedoc).

## Structure

- `src/content/docs/` — hand-written pages (`.md`/`.mdx`, kebab-case
  filenames). Sidebar groups: Introduction, Roadmap, Guides (autogenerated
  from `guides/`), Fields (autogenerated from `fields/`), and API Reference
  (autogenerated by the typedoc plugin — never hand-edit
  `src/content/docs/api/**`, it's generated and gitignored).
- `astro.config.mjs` — sidebar structure and the typedoc `entryPoints` list
  (one per documented `@vexcms/*` package).

## Run locally

From the repo root:

```
pnpm --filter docs dev       # http://localhost:4321
pnpm --filter docs build     # production build to apps/docs/dist/
pnpm --filter docs preview   # preview the production build
```

Or from `apps/docs/` directly: `pnpm dev` / `pnpm build` / `pnpm preview`.

## Zero-warning contract

`astro.config.mjs` sets `typeDoc.treatWarningsAsErrors: true`. Any broken
`{@link}`, undocumented referenced type, unknown tag, or malformed
`@example`/`@param` in a documented package's JSDoc fails
`pnpm --filter docs build`. Keep it green — see
`.agent/docs/standards/docs/jsdoc-conventions.md`.

## Adding content

- New field type page → `src/content/docs/fields/<name>.mdx`.
- New guide → `src/content/docs/guides/<name>.mdx`.
- Both sidebar groups are autogenerated from their directory; no
  `astro.config.mjs` change is needed to register a new page in either.
