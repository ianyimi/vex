title: text field
description: Stores short single-line string values — titles, slugs, URLs, email addresses, and status labels.

A `text()` field stores short, single-line string values. It is the most common
field type in VexCMS — used for titles, names, slugs, URLs, email addresses,
and any other short text value.

## Config options

| Option | Type | Default | Description |
|--------|------|---------|-------------|
| `label` | `string` | `""` | Display label in the admin panel. Inferred from the field key by `defineCollection` when left empty. |
| `required` | `boolean` | `false` | When `false`, the field is wrapped in `v.optional(…)` in the schema and the form allows leaving it empty. |
| `defaultValue` | `string` | `""` | Pre-filled value shown in the admin form when creating a new document. |
| `min` | `number \| [number, string]` | — | Minimum character length constraint. Bare number, or a `[value, customError]` tuple for a custom error message. |
| `max` | `number \| [number, string]` | — | Maximum character length constraint. Bare number, or a `[value, customError]` tuple. |
| `index` | `string \| { name, additionalFields?, draftStatus? }` | — | Convex index name (generates `.index(name, [fieldKey])`), or the object form for a compound index. See [Compound indexes](#compound-indexes) below. |
| `searchIndex` | `{ name: string, filterFields: string[] }` | — | Full-text search index on this field. The field becomes the `searchField`. |
| `description` | `string` | — | Helper text shown below the field input. |
| `admin.hidden` | `boolean` | `false` | Hides the field from the admin edit form entirely. |
| `admin.readOnly` | `boolean` | `false` | Renders the input as non-interactive — value is visible but cannot be changed. |
| `admin.position` | `"main" \| "sidebar"` | `"main"` | Column in the admin edit layout where this field appears. |
| `admin.width` | `string` | `"100%"` | CSS width of the field in the edit form (e.g. `"50%"`, `"240px"`). Meaningful as a child of `row()`; below a narrow form column every field renders full width regardless. |
| `admin.cellAlignment` | `"left" \| "center" \| "right"` | `"left"` | Horizontal alignment of the value in the list-view table cell. |
| `admin.placeholder` | `string` | — | Placeholder text shown when the input is empty. |
| `admin.description` | `string` | — | Helper text displayed below the field input. |
| `admin.condition` | `(props: { data, siblingData }) => boolean` | — | Shows the field only while this returns `true`. A throwing condition counts as met. Hidden fields skip `required`/`validate` on the server too. See the [Conditional fields & masks guide](/guides/conditional-fields-and-masks/). |
| `admin.mask` | `string \| string[] \| { mask, storeMasked?, options? } \| false` | — | An opt-in `use-mask-input` pattern, or `false` to opt out of a project-wide default set via `fields.inputMasks.text`. See the [Conditional fields & masks guide](/guides/conditional-fields-and-masks/). |

## Compound indexes

The object form of `index` declares a compound index led by the field it's set on: `author`'s
`index` names `status` as `additionalFields`, so the generated index covers both fields in order.

```ts
author: relationship({ collection: users, index: { name: "by_author_status", additionalFields: ["status"] } })
// .index("by_author_status", ["author", "status"])
```

A field-level `index` wins over a collection-level `indexes` entry of the same name — every field
setting wins over its collection's. Pass the collection slug and the field's own key as generics
to type `additionalFields` against the collection's other fields:

```ts
author: relationship<"articles", "author">({ collection: users, index: { name: "by_author_status", additionalFields: ["status"] } })
```

For an index that does not lead with a single field's own key, declare it in the collection's
`indexes` instead.

## Nullable values

Every data field accepts a top-level `nullable: boolean` option (default `false`), independent
of `required`. It describes a Convex `v.nullable(X)` column — distinct from `required: false`,
which describes `v.optional(X)` (the key can be absent). The two compose:

| `required` | `nullable` | Schema output | TS type |
|---|---|---|---|
| `false` (default) | `false` (default) | `v.optional(v.string())` | `string \| undefined` |
| `true` | `false` | `v.string()` | `string` |
| `false` | `true` | `v.optional(v.nullable(v.string()))` | `string \| null \| undefined` |
| `true` | `true` | `v.nullable(v.string())` | `string \| null` |

Clearing a nullable field's input writes `null`, not an empty string/`undefined` — this is how
an adopted table's existing `null` rows round-trip through the admin form. Fields with no
natural "empty" input state — every container (`group()`, `array()`, `blocks()`, `json()`,
`richtext()`, `keyValue()`, `variant()`) and `checkbox()` — render a **Null** switch in the
label row instead; flipping it to on hides the field's own input and writes `null` on save.

Sending `null` for a field's key in the `data` passed to `create`/`update`/`saveDraft`/
`publish`/`globals.upsert` behaves differently depending on the field: for an optional,
non-nullable field it **removes** the key (the stored document behaves as if it was never
set); for a nullable field it **stores** `null`; for a required, non-nullable field it fails
validation, naming the field. This only applies to top-level keys of the `data` argument — a
`null` nested inside a container's own value is just that container's own stored value, not an
unset signal. See [Writing: create, update, remove](/guides/local-api/#writing-create-update-remove)
and [Draft, publish, unpublish](/guides/versioning-and-drafts/#draft-publish-unpublish).

## Schema output

```ts
// Optional (required: false — default)
title: v.optional(v.string())

// Required with length constraints
slug: v.string()

// With a database index
slug: v.string(),
.index("by_slug", ["slug"])

// With a search index
title: v.string(),
.searchIndex("search_title", { searchField: "title", filterFields: ["status"] })
```

## Usage

```ts
import { defineCollection, text } from "@vexcms/core";

const posts = defineCollection({
  slug: "posts",
  fields: {
    // Minimal — label inferred from key ("Title")
    title: text(),

    // Required slug with length validation and a database index
    slug: text({ required: true, min: [3, "Slug too short"], max: 100, index: "by_slug" }),

    // Author name with a placeholder hint
    authorName: text({
      required: true,
      admin: { width: "50%", placeholder: "e.g. Jane Smith" },
    }),

    // Pre-filled default for a canonical URL
    canonicalUrl: text({ defaultValue: "https://example.com" }),
  },
});
```

## Admin UI

The text field renders as a single-line `<input type="text">` in the edit form.
`placeholder` and `description` are displayed inline. In the list-view table, the
raw string value is shown (left-aligned by default). When a field is designated
as `useAsTitle`, its cell renders as a clickable link to the document edit page.
