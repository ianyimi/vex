## Commit — 2026-06-29 22:46

feat(media): implement media collection system with upload field and RSC-safe config boundary

Add the foundational media collection system across `@vexcms/core`, `@vexcms/file-storage-convex`, `@vexcms/react`, and `@vexcms/next`.

The core change is the storage adapter architecture: `convexFileStorage()` now accepts explicit `mediaCollections` (each built by `defineMediaCollection()`) instead of being a stub. `defineMediaCollection` injects the required base fields (`alt`, `filename`, `mimeType`, `size`, `storageId`, `deleted`, `convexUrl`, `width`, `height`) while letting user-provided fields override labels and descriptions. Every collection is tagged `meta.storageAdapter: "convex"` so the admin and schema generators can route correctly.

The admin panel gains three new pieces: `MediaCollectionListView` (list view for media), `CreateMediaModal` with `react-dropzone` upload UI, and `UploadFieldInput`/`UploadFieldCell` registered in the React adapter for the new `upload` field type. A `StorageAdapterContextProvider` threads the client-side `uploadFile` functions down to leaf components without polluting the serializable config.

`NextAdminLayout` is refactored from a client component into a server component. It now calls `sanitizeConfigForClient` — which strips storage adapter class instances and functions — *before* passing the config as a prop to the new `NextAdminLayoutClient` leaf. This fixes the RSC serialization crash ("Classes or null prototypes are not supported") that occurred when the raw config crossed the server→client boundary. The same sanitize is applied in `AdminLayout` and `NextAdminPage` for defense in depth. `VexConfigContext` is typed to `ClientVexConfig` throughout.
