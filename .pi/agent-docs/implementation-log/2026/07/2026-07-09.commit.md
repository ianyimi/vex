## Commit — 2026-07-09 20:16

feat(media-ui): implement media collection upload field with modal picker and SSR safety

## Summary

Completed comprehensive media collection UI system with new React components for media selection, preview, and upload. Includes upload field refactoring (string[] value type), FilePreview component for media thumbnails, MediaUploadForm with TanStack Form adapter, and critical DND system improvements for server-side rendering safety.

## What Changed

### Core Types & Media Utilities
- Updated media validator and collection utils to support `max` option for multi-select control
- Added `MediaFieldValue` type for consistent media document representation
- New `media/utils.ts` for common helper functions

### React Components — Media UI
- **FilePreview** — Renders actual images/videos from storage adapters with type-specific fallback icons
- **MediaUploadForm** — TanStack Form–powered dropzone with file upload via storage adapter
- **MediaLibraryGrid** — Searchable media document list with pagination support
- **MediaFieldValue** — Display component for single/multi-select resolved media values

### Upload Field Refactoring
- Changed value type from `string | undefined` → `string[]` (arrays, where max=1 is single-select)
- Split Input into `EmptyInput` (no media selected) and `FilledInput` (display selected media) for cleaner state management
- Field-local modals controlled by nuqs URL params — only relevant field's picker renders at a time
- New `InputTag` component for displaying selected media tags

### Button Component Enhancement
- Added icon support with optional `icon` prop (LucideIconName)
- Configurable icon size and position (left/right)
- Icon inline with text using mb-0.5 and mr-1 spacing

### DND System — SSR Hydration Safety (Critical Fix)
- Added explicit `mounted` state to DndContext to track client-side mount
- DragHandle, Draggable, Droppable now return simplified no-op rendering before hydration completes
- Prevents hydration mismatches on server-rendered pages with drag-and-drop zones
- All DND operations disabled on server → enabled post-mount on client

### Design & Standards Updates
- Updated developer-preferences.md with form pattern observations
- Cleaned up media design docs; new UPDATE-media-create.md for upload modal reference
- Deleted obsolete UPDATE-upload-field.md

### Dependencies
- Bumped @tanstack/react-form from ^1.27.7 → ^1.33.0
- Added @tanstack/zod-form-adapter ^0.42.1 for form validation integration
- Updated pnpm-lock.yaml for new transitive dependencies

## Why These Changes

The media collection system required robust UI components to allow users to browse existing media, upload new files, and select media for assignments (single or multi-select). Upload field value type changed to `string[]` to support both single-select (max: 1) and multi-select use cases consistently. DND improvements address a critical SSR issue where drag handles and droppable zones were incorrectly rendering server-side, causing hydration mismatches. The `mounted` flag ensures all drag-drop logic is disabled until the component hydrates on the client.
