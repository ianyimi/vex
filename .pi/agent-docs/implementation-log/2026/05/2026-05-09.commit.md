feat(core): Vex API server/client split with typed populate narrowing (Spec 23 Step 2)

Implements the `@vexcms/core/server` and `@vexcms/core/client` export paths with
fully split server-only and client-only functions for `find`, `get`, `search`,
`create`, `update`, and `remove`. Adds `queryApi`/`mutationApi` Convex factory
functions exported from `@vexcms/core/convex`.

Key design decisions:

Conditional return types eliminate the `Id<"posts">[] | Post[]` union that Payload
CMS forces users to handle. `find({ ctx, collection: "posts" })` returns `Post[]`
(raw IDs for relationship fields); `find({ ctx, collection: "posts", populate:
{ parent: true } })` returns `{ ...Post; parent: Post[] }[]` (populated). This
required three components: `const TPopulate` generic to preserve literal types,
`[TPopulate] extends [Record<string, never>]` discriminator to branch on populate
presence, and `Prettify<T>` to force eager evaluation of the mapped conditional type
for IDE display.

`find` exposes the full Convex query chain as optional args (`filter?`, `order?`,
`withIndex?`) so users don't need to bypass the API for complex queries. This is the
foundation for mandatory hook interception in a future spec.

Convex reactivity fixed by moving `ConvexReactClient`, `ConvexQueryClient`, and
`QueryClient` to module-level singletons so `connect()` fires synchronously before
any React render. The previous `useState` + `useEffect` approach left a timing gap
where queries added during first render missed the `"added"` cache event and never
got a WebSocket subscription.

TanStack Form updated to v1.28 generic counts (10 new type parameters on
`ReactFormExtendedApi`, `FieldApi`, `FormOptions`).
