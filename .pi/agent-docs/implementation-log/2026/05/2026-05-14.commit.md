## Commit — 2026-05-14 18:00

feat(core,better-auth,react): auth adapter system with collection merge and depth-populate test coverage

Introduces the `VexAuthAdapter` interface and `betterAuthAdapter()` — an
adapter that introspects Better Auth's schema via `getAuthTables()` and
converts each table into a standard Vex `CollectionConfig`. Auth
collections are merged into `defineConfig()` via `mergeAuthCollections()`,
which respects `protected` at the collection level and `meta.locked` on
individual fields so auth system fields cannot be accidentally overridden.

All field types (`BaseField`, `AdminField`, every concrete field builder
and its Input/Output types) now accept a `TMeta` generic so auth adapters
can attach field-level metadata like `locked`. Collections gain a parallel
`TFieldMeta` / `TCollectionMeta` pair threaded through
`CollectionConfigInput` → `CollectionConfig`.

The `get()` server function now resolves the table slug at runtime from
both `__tableName` (materialised in some DX tooling) and the
`"{random};{tableName}"` format used by `convex-test`, instead of only
checking the phantom brand. Depth auto-populate degrades silently when
neither strategy yields a slug.

Adds depth-populate integration tests for `get()`, `find()`, and
`search()` covering depth 0/1/2, missing docs, and the no-config guard.
Client-side mutation helpers (`create`, `update`, `remove`) receive
expanded JSDoc with full `useMutation` examples and cross-import
references.

React/Next admin shell gains `AdminUser` (name/email/image) threaded
through `AdminLayout` → `AppSidebar`, and the edit view now shows the
document's title field in the heading. The `www` app wires Better Auth
via the adapter, adds auth Convex tables (user, session, account,
verification, apikey, jwks) and a `pages` collection.
