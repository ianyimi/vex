### Patterns extracted → standing rules

- **Re-export every core config function from framework packages** → `developer-preferences.md` "Framework Adapter Architecture" + `1-dev-spec.md` standing rules block. Users import config functions from `@vexcms/next` (or `@vexcms/react`), never from `@vexcms/core` directly. Keeps core framework-agnostic.
- **User-supplied component slots in core use `ApplyComponent<F, Props>`** → same. Core never imports `react`. Framework packages bind `F = ReactHKT` at the boundary. New rule for every future field/collection slot accepting components.
- **Workspace package tsconfigs need `customConditions: ["source"]`** → `developer-preferences.md` "Workspace Packaging". Without it, package-internal LSP follows standard module resolution to a possibly-missing `dist/index.d.ts` and silently widens all imported types.
- **Peer-only deps mirror in devDependencies for typecheck** → same section. `peerDependencies` alone don't get pnpm-symlinked into a package's `node_modules` for typecheck.
- **PostCSS comment apostrophe quirk** → `debug-hierarchy.md` "Known Fragile Areas". Avoid apostrophes/quotes/backticks in CSS comments; split `{ts,tsx}` brace expansion into separate `@source` lines. Symptom: `CssSyntaxError: Unclosed string` and the entire stylesheet rejected.
