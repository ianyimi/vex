## Commit — 2026-05-03 04:51

feat(core,react): implement relationship field type end-to-end

Relationship field is now fully wired from definition to Convex schema to
admin UI. `packages/core` gains `fields/relationship/` (types, config,
validator, inputSchema). `schemaGen.ts` is replaced by `validator.ts`,
which accepts the full `VexConfig` and auto-generates FK indexes
(`by_<fieldKey>`) and search indexes (`search_<useAsTitle>`) for every
collection pointed to by a relationship field elsewhere. A new `search`
Convex query powers the picker combobox — falling back to recency order
when no query string is given.

On the React side, `RelationshipFieldInput` (MultiSelect combobox),
`RelationshipFieldCell`, and `relationshipFieldToColumnDef` are registered
in the adapter and field index. `AdminTopNav` adds a breadcrumb header that
resolves the active document's title from Convex at runtime. `Icon` is a
new Lucide-icon-by-name utility, exported from `@vexcms/react`.

The `posts` collection in `apps/www` is updated end-to-end as a real-world
exercise: `parent` relationship field added to the collection config, the
generated `vex.schema.ts` updated with `v.optional(v.array(v.id("posts")))`
and `.index("by_parent", ["parent"])`, and the hand-written `Post` interface
extended with `parent?: Id<CollectionSlug>[]`. JSDoc added to `RootLayout`
and `ConvexClientProvider` in the same pass.

Supporting changes: dark-mode design tokens overhauled to the Stark × Ember
palette in both `globals.css` and `styles.css` with explicit OKLCH values;
`sanitizeConfigForClient` added for safe RSC→client config serialization;
Convex provider initialization moved from module scope to React state to fix
SSR/HMR issues; number field now guards min ≥ max at config time and clamps
its default value to the configured range; sidebar nav links fixed to use
`addLeadingSlash(config.basePath)`.
