## Deviations from spec

- **Factories in `server.ts` not `index.ts`**: Spec called for a separate `api/index.ts` for `queryApi`/`mutationApi`. User put them in `server.ts` alongside the barrel exports. Package exports updated: `@vexcms/core/convex` now maps to `src/api/server.ts`.
- **`slug` → `collection` rename**: All API function args use `collection:` not `slug:`. Spec code samples updated.
- **`find.server.ts` extended with full query chain**: Added `filter?`, `order?`, `withIndex?` args mapping to Convex's `ctx.db.query().filter()`, `.order()`, `.withIndex()` chain. Not in spec; user requested this as a capability for mandating API use in future hook enforcement.
- **`Prettify<FindReturnItem<...>>` conditional return pattern**: All three query server functions (`find`, `get`, `search`) use a conditional return type that branches on whether populate is given. No-populate returns `DocumentBySlug[TSlug]` (concrete named type); with-populate returns `Prettify<Populated<TSlug, TPopulate>>` (eagerly evaluated mapped type). This eliminates the `Id<"posts">[] | Post[]` union that Payload CMS forces users to handle — VexCMS narrows the type based on the populate config passed. Required three components working together: `const TPopulate`, `[TPopulate] extends [Record<string, never>]` discriminator, and `Prettify<T>`.
- **`as CollectionSlug` not `as never`**: Initial implementation used `as never` casts at factory boundaries where `string` (from `v.string()`) needed to satisfy `CollectionSlug`. Corrected to `as CollectionSlug` / `as GenericId<CollectionSlug>` which preserves type inference instead of collapsing it to `never`.
- **TanStack Form v1.28 generic count update**: `ReactFormExtendedApi`, `FieldApi`, `FormOptions` all gained 10 new type parameters. `AnyFormApi`, `TypedFieldApi`, and `useCollectionForm` updated to pass all generics as `any`.
- **`useRelationshipPickerOptions` list→find**: `vexConvexApi.list` no longer exists; migrated to `vexConvexApi.find`.
- **Convex reactivity fix**: Module-level singletons for `ConvexReactClient`, `ConvexQueryClient`, `QueryClient` so `connect()` is called synchronously before any React render. The `useState` + `useEffect` approach caused a timing gap where queries added to the cache during first render missed the `"added"` event and never got a Convex WebSocket subscription.
- **`vexConvexApi.list` → `vexConvexApi.find` in spec 22**: Downstream spec updated.

## Decisions made

- **`as CollectionSlug` at factory boundaries** rather than `as never`: `as never` collapses `TSlug` inference to `never` propagating through conditional return types. `as CollectionSlug` preserves the semantics (this IS a valid slug at runtime) without breaking inference.
- **Factories in `server.ts`**: Keeps the server barrel and factory in one file under `@vexcms/core/server`. The `@vexcms/core/convex` export is an alias to the same file. No separate `index.ts` needed.
- **`populateDocs` returns `Populated<TSlug, TPopulate>[]`**: Added `TPopulate` generic to `populateDocs` so callers get the narrowed type without their own casts. Single `as unknown as` cast inside `populateDocs` at the runtime/type boundary.
- **`filter`/`order`/`withIndex` on `find`**: User wants to enforce use of the `find` function (not raw `ctx.db.query`) for future hook interception. Exposing these args makes the API competitive with direct Convex queries.
