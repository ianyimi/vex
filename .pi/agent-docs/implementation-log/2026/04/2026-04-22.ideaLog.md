### Deviations from spec

**`select` field:**
- `defaultValue` changed from `""` to `[]` — select stores an array even in single-select mode (consistent with `hasMany`)
- `options` no longer accepts string shorthand `"value"` — only `{ label, value, badgeColor? }[]`. Simpler dispatch logic; `badgeColor` enables badge color display in the cell
- `hasMany: boolean` was added (not in spec). `false` = single-select, `true` = multi-select. The `MultiSelect` component is used for both modes via `single={!fieldDef.hasMany}`
- `optionInterfaceName?: string` was added for TypeScript union type generation in the CLI
- Convex validator generates typed `v.array(v.union(v.literal(...), ...))` — not the spec's generic `v.string()`. This ensures schema generation produces tight Convex validators

**`url` field:**
- Renamed from `imageUrl` to `url` everywhere (function, types, React components, directory, ADMIN_FIELDS key)
- Image preview and load validation removed entirely — the field is now a generic URL input. No `<img>` preview on blur, no `onError` field error, no block-save behavior
- Input is `type="text"` (not `type="url"`) to avoid browser-native URL validation interfering with Zod-controlled validation at submit time
- Cell renders as `VexLink` (not `<img>` thumbnail). For title fields: edit-page link. For non-title fields: direct URL link, truncated at 77 chars

### Decisions made

- Made `url()` generic rather than image-specific: the image preview adds UI complexity and a different failure mode (image load vs URL format). A generic URL field is more composable; image preview can be added as a future field option if needed.
- `select` defaultValue is `[]` even for `hasMany: false` (single-select). Keeps the type contract consistent — components always work with `string[]` and don't need to branch on `hasMany` to determine value shape.
- String shorthand options removed from `select`: the `badgeColor` extension made the shorthand ambiguous. Requiring the object form is more explicit and easier to extend.

### Known issues / follow-ups

- `select` validator currently always generates `v.array(v.union(...))` regardless of `hasMany`. When `hasMany: false`, the Convex schema allows multi-value arrays even though the UI enforces single selection. Tightening this (e.g. `v.union(...)` for single-select) is deferred until the relationship between `hasMany` and schema generation is finalized.
- `url` field in the better-auth user collection was updated from `imageUrl()` to `url()` in the spec (Part 2 table), but Part 2 is not yet implemented.
