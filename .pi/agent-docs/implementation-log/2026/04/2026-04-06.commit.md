feat(packages): add Convex data layer, React admin UI, and Next VexAdminPage

Implements spec 01 across core, react, next, and the www app. Adds the full
admin panel foundation: generic Convex collection CRUD, TanStack Query view
components with SSR initialData, shadcn UI primitives, AdminLayout/AppSidebar,
and the VexAdminPage async server component.

Adds `packages/core/src/convex.ts` with `VexDocument` (base document type) and
`vexConvexApi` — typed `anyApi` references to `vex.collections.*` Convex
functions. Framework adapter authors import these to call the right query without
threading the generated `api` object through props or context. Updates
`framework.ts` view props to include `initialData` and `documentId` so
VexAdminPage can pass SSR-preloaded data to view components.

Adds TypeScript source navigation across the monorepo: `customConditions: ["source"]`
in `packages/tsconfig/base.json` and `"source": "./src/index.ts"` in each
package's exports. The LSP now resolves workspace imports to `.ts` source files
so `gd` in neovim jumps to source instead of dist. Also annotates `reactAdapter`
with `FrameworkAdapterInput<ReactHKT>` to fix the "cannot be named" declaration
emit error.

Builds out `@vexcms/react` with shadcn primitives (button, input, label, table,
badge, card), `cn()` utility, `AdminLayout` (sidebar shell), `AppSidebar`
(collection nav), `TextInput` (shadcn Label + Input), `TextCell` (80-char
truncation), and three view components using TanStack Query + convexQuery with
initialData hydration: Dashboard (collection card grid), CollectionListView
(data table), CollectionEditView (dynamic field form pre-populated on edit).

Adds `VexAdminPage` to `@vexcms/next` — an async Next.js 15 server component
that awaits params, calls fetchQuery for SSR initial data, and routes to the
correct view wrapped in AdminLayout. Routes: /admin → Dashboard, /admin/:slug →
CollectionListView, /admin/:slug/new → empty edit form, /admin/:slug/:id/edit →
pre-populated edit form.

Replaces the old www convex architecture with the new generic CRUD functions
(`list`, `get`, `create`, `update`, `remove`) using dynamic TableNamesInDataModel
casting — no per-collection functions needed. Adds 10 convex-test tests covering
all functions including edge cases. Replaces the old 11-table schema with a
simple posts table matching vex.config.ts.

Auth and form submission mutations are deferred to future specs.
