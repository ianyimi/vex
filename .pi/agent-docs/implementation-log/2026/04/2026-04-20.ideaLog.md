## Deviations from spec

- **`tsType` → `interfaceType`**: Every `ADMIN_FIELDS` entry uses `interfaceType` instead of `tsType`. The derived `AdminFieldTsType` type reads `["interfaceType"]`. All field config functions (`text()`, `number()`, etc.) now copy `ADMIN_FIELDS[type].interfaceType` onto the resolved field object directly — so type generators read `field.interfaceType` instead of looking up `ADMIN_FIELDS[field.type].tsType`.
- **`interfaceName` on `CollectionConfig`**: `defineCollection` now resolves and stores `interfaceName` (PascalCase slug + "Document") on the config. The spec had `collectionConfigToInterface`/`generateVexTypes` compute it on the fly; storing it on the config avoids repeating the derivation everywhere.
- **`slugToPascalCase` in `collections/utils.ts`** (not `schema/generateVexTypes.ts`): Moved so `defineCollection` can use it at resolve time.
- **`collections/schema.ts` → `collections/schemaGen.ts`**: Renamed to distinguish the per-collection helper from the top-level schema module.

## Decisions made

- Chose to store `interfaceType` on field objects at config time rather than reading from `ADMIN_FIELDS` at generation time — this means user-defined overrides could be added to a field in the future without changing the generators.
- `slugToPascalCase` is now also exported from `collections/typeGen.ts` for use by the type generator tests (Step 3 in progress).
