## Commit — 2026-04-17 01:19

feat(fields): implement select field type across core, react, cli, and tests

Adds the `select` field to the full stack. In `@vexcms/core`: `SelectField`
type, `ADMIN_FIELDS.select` constant, `selectFieldToValidator` (generating
`v.array(v.union(v.literal(...)))` for both required and optional, with
`hasMany` support), `selectFieldToInputSchema`, and `SelectField` added to the
`AdminField` union. A `default: throw` guard was added to both
`adminFieldToValidator` and `adminFieldToInputSchema` to make unregistered
field types fail loudly instead of silently.

In `@vexcms/react`: `SelectFieldInput` (combobox using `cmdk`, supporting
single and multi-select), `SelectFieldCell`, and `selectFieldToColumnDef` are
all wired into `fieldInputComponents`, `fieldCellComponents`,
`getCollectionColumnDefs`, and `reactAdapter`. The `cmdk` package was added as
a dependency.

Four integration test files are added covering `adminFieldToValidator`,
`adminFieldToInputSchema`, `getCollectionInputSchema`/`getCollectionDefaultValues`,
and the CLI schema/file generators — each with a comprehensive test that
exercises every registered field type in a single collection.

Also fixes `getCollectionDefaultValues` to fall back to `fieldDef.defaultValue`
when `document[fieldKey]` is `undefined` (previously any existing document
would suppress the default for fields not yet present on it). Minor: adds
`"use client"` to `DateFieldCell`, removes `max-w-2xl` cap from the edit form,
updates `add-vexfield.md` to require integration test updates for new fields.
