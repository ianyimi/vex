## What was built

This log documents the spec design — implementation is manual (developer-led).

- `packages/core/src/convex.ts` — `VexDocument` base type + `vexConvexApi` using `anyApi` with
  typed `FunctionReference` casts. Paths fixed to `vex.collections.*` so consumers don't need to
  pass the generated `api` object through props or context.

- `packages/core/src/framework.ts` — Updated view prop interfaces to include `initialData` and
  `documentId`. `CollectionListViewProps` gets `initialData?: VexDocument[]` for SSR hydration.
  `CollectionEditViewProps` gets `documentId?: string` + `initialData?: VexDocument | null`.

- `packages/tsconfig/base.json` — Added `customConditions: ["source"]`. Each package's
  `package.json` exports gains a `"source": "./src/index.ts"` condition. Together these make the
  LSP resolve workspace packages to their `.ts` source files instead of `.d.ts` dist files,
  enabling `gd` in neovim to jump to source across packages.

- `packages/react/src/` — Full React admin package:
  - `lib/utils.ts` — `cn()` utility (clsx + tailwind-merge)
  - `components/ui/` — shadcn primitives (button, input, label, table, badge, card)
  - `components/AdminLayout.tsx` — sticky sidebar + scrollable main content shell
  - `components/AppSidebar.tsx` — collection nav with active state highlighting
  - `fields/text/Input.tsx` — `TextFieldInput` with shadcn Label + Input, placeholder + description support
  - `fields/text/Cell.tsx` — `TextFieldCell` with 80-char truncation + em-dash for null
  - `views/DashboardView.tsx` — `DashboardView` collection card grid, links to `/admin/:slug`
  - `views/CollectionListView.tsx` — TanStack Table with `convexQuery` + `initialData`
  - `views/CollectionEditView.tsx` — dynamic field form with `useQuery` for edit pre-population
  - `adapter.ts` — `ReactHKT` + `reactAdapter` with all three views, annotated with
    `FrameworkAdapterInput<ReactHKT>` to fix the "cannot be named" LSP error

- `packages/next/src/VexAdminPage.tsx` — Async Next.js 15 server component. Awaits `params`
  (Next 15 async params), calls `fetchQuery` from `convex/nextjs` for SSR initial data, wraps
  every view in `AdminLayout`.

- `apps/www/convex/schema.ts` — Replaced old 11-table schema with just the `posts` table matching
  `vex.config.ts`.

- `apps/www/convex/vex/collections.ts` — Replaced old permission-aware CRUD (`listDocuments`,
  `getDocument`, etc.) with simple generic CRUD (`list`, `get`, `create`, `update`, `remove`)
  using dynamic table name casting via `TableNamesInDataModel<DataModel>`.

- `apps/www/convex/vex/collections.test.ts` — 10 convex-test tests covering all 5 functions,
  including edge cases (limit, null id, patch leaves unspecified fields unchanged, delete from list).

## Deviations from spec

- **Spec uses existing component names:** The repo had stubs with names `TextFieldInput`,
  `TextFieldCell`, and `DashboardView`. The spec was updated to match these existing names rather
  than renaming them. `DashboardView` maps to the `Dashboard` key in `ViewComponentMap` as
  `views: { Dashboard: DashboardView, ... }`.

- **Old convex files need full replacement:** `apps/www/convex/vex/collections.ts` had a complex
  auth/permission architecture from the pre-rebuild. The new generic functions are simpler by
  design — auth will be added in a future spec.

- **`adapter.ts` version:** Spec correctly uses `"0.1.0-alpha.1"` to match `package.json`.

## Decisions made

- **`anyApi` with type casts over passing `api` through props:** The Convex functions always live
  at `vex.collections.*` — this is a fixed contract users must follow. Using `anyApi` avoids
  threading the generated `api` object through view props or context, keeping view components
  simple. Breakage (if a user moves the functions) is runtime, not compile-time — acceptable given
  the path is documented.

- **`initialData` over `usePreloadedQuery`:** Next.js server component calls `fetchQuery` (gets raw
  data) and passes it as `initialData` to TanStack Query. Simpler than the Convex `preloadQuery` /
  `usePreloadedQuery` pattern, and sufficient for SSR hydration without a loading flash. The
  components still subscribe to live Convex updates via `@convex-dev/react-query`.

- **`AdminLayout` in `@vexcms/react`, used by `@vexcms/next`:** Layout shell lives in the react
  package so non-Next framework adapters can use or fork it. Next package's `VexAdminPage` imports
  it from `@vexcms/react`.

- **Simple generic Convex functions (no auth in spec 01):** Auth and RBAC are deferred to a future
  spec. The simple functions make testing with `convex-test` straightforward and the admin panel
  functional without auth setup.

- **`customConditions: ["source"]` in base tsconfig:** A monorepo-wide change so all packages
  benefit. Each package adds `"source": "./src/index.ts"` to its `package.json` exports. This
  resolves the LSP navigation issue where `gd` was jumping to dist files.

## Known issues / follow-ups

- Form submission (create/update mutations) is not wired in spec 01 — the Save button is a no-op.
  Wiring form submit to `vexConvexApi.create` / `vexConvexApi.update` is a future spec task.
- Pagination in `CollectionListView` is not implemented — the `list` query has a `limit` param
  but the UI doesn't expose pagination controls yet.
- Auth/RBAC on the generic Convex functions is deferred — currently any user can read/write any
  collection via the admin panel.
- `vitest.convex.config.ts` requires `convex-test` and `@edge-runtime/vm` to be installed in the
  www app before tests can run.
