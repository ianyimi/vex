## Deviations from spec

- **`boolean` renamed to `checkbox`** — function name, type string, and TypeScript interfaces all use `checkbox`. The spec called for `boolean()` matching the data type, but `checkbox` better describes the UI widget. This naming convention — field type names match the UI control — is now a project-wide preference.
- **`checkbox` `admin.width` stays `"full"`** — the spec proposed overriding to `"half"`, but the code keeps the base default and lets users opt in.
- **`number` `admin.cellAlignment` stays `"left"`** — the spec proposed overriding to `"right"`, but the code keeps the base default.
- **`date` `defaultValue` is `undefined` not `0`** — empty start is more intuitive than epoch (1970-01-01).
- **`date` `time` option is a config object, not a boolean** — `time?: { hidden?: boolean; use12HourFormat?: boolean; timePicker?: { hour, minute, second } }`. Defaults are deeply merged in `date()` so all keys are always present on `DateField.time`. This lets `DateFieldInput` drive all `<DateTimePicker>` props directly from `fieldDef.time` without conditional logic in the component.
- **`date` input uses `<DateTimePicker>` not `<input type="datetime-local" />`** — drives `hideTime`, `use12HourFormat`, and `timePicker` from `fieldDef.time`. `modal` prop removed. `clearable` is always passed.
- **`date` cell uses `toLocaleDateString()` not `date-fns`** — no extra dependency; browser locale API is sufficient for basic date display.
- **`checkbox` cell renders `"Yes"`/`"No"` not icons** — avoids an icon import and is always readable regardless of font/icon loading.

## Decisions made

- Field type names describe the UI widget (`checkbox`, `select`, `date`) rather than the data type. The Convex validator and TypeScript type are separate from the field type identifier.
- `DateTimePicker` is the canonical date input across all fields that store timestamps. No `<input type="datetime-local" />` usage.
- `textarea.tsx` UI primitive and `select`, `imageUrl`, `password`, `json`, `relationship` field types are deferred to the next implementation session.
- Part 2 (auth adapter) not started — waiting for remaining field types first.
