## Commit — 2026-04-11 (first)

feat(fields): add checkbox, number, and date field types with React components

Implements three new field types in @vexcms/core and @vexcms/react following
the pattern established by the text field reference implementation.

The boolean field from the spec was implemented as `checkbox()` — the field
type name describes the UI widget, not the data type. The Convex validator
remains `v.boolean()` and the TypeScript value type is `boolean`, but the
field function and type string are both "checkbox". This naming convention is
now the project standard: field type names match their input widget.

`checkbox()` renders a <Checkbox> with the label to the right and displays
"Yes"/"No" in data table cells. `number()` accepts optional `min`/`max`
constraints mirroring the text field pattern. `date()` adds a `time` config object (not in the original spec):
`{ hidden, use12HourFormat, timePicker }` with deep default merging so all keys
are always present on the resolved `DateField`. This lets `DateFieldInput` drive
all `<DateTimePicker>` props from `fieldDef.time` directly with no conditional
logic in the component. `DateField` also accepts optional `min`/`max` timestamp
constraints. The date cell uses `toLocaleDateString()` rather than date-fns to
avoid an extra dependency for basic locale date display.

Also adds `checkbox.tsx` and `select.tsx` UI primitives to @vexcms/react.
`textarea.tsx`, and the remaining field types (select, imageUrl, password,
json, relationship) plus the @vexcms/better-auth adapter are deferred.

## Commit — 2026-04-11 23:15

feat(fields): refactor date time config to object, move searchIndex to text

Replace `date()`'s boolean `time` option with a config object
`{ hidden, use12HourFormat, timePicker }`. `date()` deeply merges defaults
so all keys are always present on the resolved DateField — no conditional
logic needed in DateFieldInput. DateField also gains optional `min`/`max`
Unix ms timestamp constraints for range validation.

Move `searchIndex` from BaseFieldInput/BaseField to TextFieldInput/TextField.
Full-text search is a text-only Convex feature — other field types cannot
be search-indexed and should not expose the option in their config.

Update JSDoc throughout: DateFieldInput defaults block now shows the full
time object with inline comments on each key; all time sub-properties have
hover docs; date() config function examples use the new object form.

Sync spec 20 to reflect all implementation deviations; encode date field
patterns in dev-spec.md and developer-preferences.md.
