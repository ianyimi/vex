feat(core,react,next): module augmentation for type-safe collection slugs

Implements TypeScript module augmentation so that `vex generate` narrows
`CollectionSlug` and `DocumentBySlug` in `@vexcms/core` to the user's
actual collections — zero config changes required. After generation,
`relationship({ collection: "invalid" })` is a compile-time error;
passing a document from the wrong collection to `useCollectionForm` is
also caught.

`generateVexTypes` now emits `import type { Id } from
"@convex/_generated/dataModel"`, `import type { VexDocument } from
"@vexcms/core"`, and a `declare module "@vexcms/core"` block at the end
of `vex.types.ts`. Generated collection interfaces extend `VexDocument`
and use `Id<"tableslug">` for `_id` instead of plain `string`, giving
proper Convex branded ID types and structural compatibility with
`VexDocument` throughout the framework.

`useCollectionForm`, `CollectionEditView`, `CollectionListView`,
`CreateDocumentModal`, and `NextAdminPage` are all made generic over
`TSlug extends CollectionSlug = CollectionSlug`. TypeScript infers the
slug from the collection prop at call sites — no explicit annotation
needed from users. The Next.js dynamic route casts the runtime-looked-up
collection to `CollectionConfig<CollectionSlug>`, which is safe because
`.find()` only searches registered collections.

The url field `defaultValue` is corrected to `undefined` (matching the
date field pattern) since an empty string is not a valid URL. The
workspace catalog is fully consolidated — all shared dependencies across
packages now reference `catalog:` with version decisions resolved: zod
v4, `@tanstack/react-form` v1, `better-auth` ^1.5.0, `@types/node` v20.
Per-package ESLint configs are added for `@vexcms/react` (Vite React) and
`@vexcms/next` (mirrors www), with the root config updated to exclude
those packages from double-processing.

docs(product): add v0.1.0 launch roadmap and update document prompt

Adds `.pi/agent-docs/product/v0.1.0-launch-roadmap.md` — a detailed
milestone-based plan (M1–M8) covering everything remaining to get from
the current rebuild branch to a v0.1.0 npm release. Roadmap includes per-
milestone deliverables, implementation order, and a revised timeline
estimate calibrated against the master branch reference implementation.

The `/document` prompt is updated to make docs-site page generation a
built-in step (Step 5). After writing JSDoc, the agent now creates or
updates the corresponding Starlight MDX page in `apps/docs/src/content/docs/`
using per-symbol page location rules and MDX templates. This removes the
docs site as a sequential launch phase — documentation is built
progressively alongside each feature rather than written by hand at the
end.

The CLI shutdown sequence is also fixed: `killConvexDev` is now async and
kills the entire process group via `process.kill(-pid, "SIGTERM")` so that
`pnpm exec convex dev` children are not left as orphans. The shutdown
path in `devCommand` awaits both `killConvexDev()` and `watcher.close()`
in parallel instead of fire-and-forget.
