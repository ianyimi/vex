## Commit — 2026-04-21 (first)

feat(core): implement generateVexSchema and generateVexTypes with schema/types config split

Implements Steps 1, 2, 3, and partial Step 5 of spec 21 (dev tools schema generation).
generateCollectionQueries (Step 4) remains a stub — not yet implemented.

schemaGen.ts converts a CollectionConfig to a defineTable() source string with chained
.index() and .searchIndex() methods. generateVexSchema wraps this into a full vex.schema.ts
file string, returning { update, contents } so the CLI can skip writes when content is unchanged.

interfaceGen.ts (renamed from typeGen.ts) converts a CollectionConfig to a TypeScript interface
string. Select fields generate typed option subtypes (e.g. `type StatusOption = "draft" |
"published"`) rather than plain string[] — the spec deferred this but the developer implemented
it immediately. generateVexTypes assembles the full vex.types.ts output with CollectionSlug
and DocumentBySlug types, plus ESLint disable comments for perfectionist sort rules.

Config design changed from spec: typesOutputPath was extracted from SchemaConfigInput into a
separate TypesConfigInput at VexConfigInput.types. Default output path for vex.types.ts is
/src/vex.types.ts (placed next to vex.config.ts), not /convex/vex.types.ts.

schema/migrate.ts adds stubs for diffSchema/makeFieldsOptional/planMigration. These are
out-of-scope for spec 21 but the CLI lib already imports them from @vexcms/core — stubs
allow removing @ts-nocheck from the CLI lib without breaking the build.

@ts-nocheck removed from commands/generate.ts and commands/deploy.ts.

## Commit — 2026-04-21 02:35

feat(core,cli): wire interfaceType metadata, sync formatter, --cwd flag

Spec 21 continued. This commit wires field-level type metadata into all field configs and
adds CLI improvements that make monorepo development work when vex.config.ts lives in src/.

`interfaceType` stamped onto every field config function (text, number, checkbox, date,
select) and added to BaseField; ADMIN_FIELDS entries carry it as a const. `interfaceName`
is derived from slug by defineCollection (as `{Slug}Document`) and overrideable via config —
posts overrides to "Post". `optionInterfaceName` added to SelectField so select fields can
control their generated option subtype name.

`generateAndWrite` now takes a `configPath` argument so vex.types.ts always resolves next
to the config file, not cwd. The async Prettier import is replaced by synchronous
`execFileSync` that auto-detects Prettier vs Biome from the project's `format` script.

`devCommand` gains `--cwd` so the CLI can run from the monorepo root targeting a sub-app.
`resolveConfigPath` now searches src/ too. `buildAliasFromTsconfig` walks up the tree to
find tsconfig.json. `traceImports` follows pnpm symlinks so local package changes trigger
a re-run without touching vex.config.ts.

`apps/www` schema.ts now imports posts from the generated vex.schema.ts instead of defining
the table inline — first end-to-end proof that the generation pipeline works.
