# ADR-004: pinned deny posture and a server-only per-call access seam

- Status: accepted
- Date: 2026-08-29

## Context

Server API functions hardcoded the permission verb they checked, so declared
`customActions` had no runtime consumer and versioning had no way to request
`readDrafts`. Designing the per-call selector exposed a compounding hazard:
`defaultPermissionMode` defaulted to `allow`, and measurement showed an action or
subject nothing declared resolved to `true`. Any client-controllable action selector
would therefore have been a read-anything hole — a nonsense action name fell through
every rule and wildcard to the permissive default. The setting also applied at two
different fallthrough points (a declared subject's missing action never consulted the
role wildcard), making it an invisible global grant that no one could audit per role.

## Decision

1. **The undeclared-permission posture is always `deny`.** `defaultPermissionMode` is
   removed from `VexAccessConfigInput`; `defineAccess` pins the resolved value. An
   allow posture is written as a role-level `"*": true` — per-role and greppable. The
   resolved field and its branch survive (`@internal`) so the semantics stay testable.
2. **Per-call access overrides are server-side only.** `access: { action?, bypass? }`
   exists on the raw server functions and `vexServerApi` output — never in a
   client-callable Convex `args` validator. Enforcement is single-seam:
   `resolveAccessCall` resolves `{ access, action, resource }` once per call, and
   `bypass` returns `access: undefined`, reusing the documented RBAC-off path so no
   second enforcement branch can drift.
3. **Slug-aware action typing comes from the generated registry.**
   `CustomActionsBySlug` is emitted beside `IndexFieldsBySlug`;
   `QueryCallActionFor`/`MutationCallActionFor` are permissive pre-generation and
   exact post-generation, with app-side `*.typecheck.ts` pin files enforcing the
   strict unions on every `tsc` run.

## Consequences

- A typo'd or undeclared action now denies instead of over-permitting; the seam's dev
  warnings are diagnostics for "why was I denied", not security controls.
- Client-facing draft reads must be a closed toggle (`drafts: boolean` mapping to
  `readDrafts`) or a dedicated endpoint — never a raw action string. Deferred to the
  versioning spec, whose inherited-decisions section records the analysis.
- Every role must now declare (or wildcard) everything it grants; www already followed
  explicit-deny style, so no behaviour changed there.
