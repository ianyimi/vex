# ADR-001: Re-enable starlight-typedoc with a zero-warning docs contract

- Status: accepted
- Date: 2026-08-08

## Context

`starlight-typedoc` was disabled on 2026-04-07 (commit ee798b2, "core types not yet
complete") — the plugin import was commented out in `apps/docs/astro.config.mjs` and the API
Reference sidebar was hand-listed. It stayed disabled unnoticed for ~4 months. The docs
system's intended design is: eslint-plugin-jsdoc forces JSDoc on every export, and
starlight-typedoc renders that JSDoc into the docs site's API Reference. With the plugin off,
the second half of that pipeline was dead and the `apps/docs/src/content/docs/api/**` output
was stale.

A smoke test on 2026-08-08 showed TypeDoc now runs against `packages/core/src/index.ts` with
**0 errors** (120 cosmetic warnings). The original blocker is resolved.

## Decision

Re-enable `starlightTypedoc` in `apps/docs/astro.config.mjs`, entry point
`packages/core/src/index.ts`, tsconfig `packages/core/tsconfig.check.json`, and drive the API
Reference sidebar via the plugin's `typeDocSidebarGroup` (no hand-listed `api/*` slugs).

Adopt a **zero-warning contract** for the docs build: every `{@link}` must resolve and no
exported type may reference an undocumented type. The commit gate runs `pnpm --filter docs
build` and requires the TypeDoc step to emit 0 warnings. Once the existing 120 warnings are
burned down, set `typeDoc.treatWarningsAsErrors: true` so the docs build fails mechanically
on any regression.

## Consequences

- Docs site API Reference is live and regenerates from JSDoc; contributors get accurate docs
  for free by writing compliant JSDoc.
- New commit-gate step (docs build + 0 TypeDoc warnings) — see the commit checklist.
- **Burn-down complete (2026-08-08): 120 → 0 warnings**, and `treatWarningsAsErrors: true`
  is now set so the docs build fails on any regression. How each class was resolved:
  - 84 "multiple declarations" — root-cause type bug: `RelationshipFieldAdminConfig` extended
    `FieldAdminConfigInput` (input) instead of `FieldAdminConfig` (resolved), so the
    `AdminField` union mixed two comment-bearing bases. One-line fix; no docs removed.
  - Cross-package `{@link}`s — documented all implemented library packages as entry points
    (core, react, next, better-auth, file-storage-convex; richtext-plate excluded until it
    has exports) and rewrote cross-module links as `{@link <pkg>/src!Symbol}`.
  - Internal/unexported refs — exported real API (`StorageAdapterPresignedUrlInterface` +
    base, `usePaginatedQuery`), code-spanned genuine internals (`applyBaseInputSchemaMeta`,
    `NextAdminLayoutClient`, lucide `Icon`).
  - Tag/example/param fixes — `@todo`/`@description`/`@defaults` → prose, code captions off
    `@example` name lines, destructured-param `@param` cleanups, stale `CellComponentMap`/
    `usePaginatedCollection` links repointed.
- **Rejected: `entryPointStrategy:"packages"`.** Per-package compilation produced thousands
  of cross-program type-identity errors (generic-heavy source) regardless of source-vs-dist
  resolution, and the repo's `dts:false` leaves no `.d.ts` to resolve against. Kept the
  single-program resolve strategy via `apps/docs/tsconfig.typedoc.json`.
- Link-hygiene rules in `docs/standards/docs/jsdoc-conventions.md`; site/plugin conventions
  in `docs/standards/docs/docs-site-conventions.md`.
