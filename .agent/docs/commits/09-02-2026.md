feat(www): build the real marketing site, generate nested select unions

**The site.** `apps/www` is a new workspace member scaffolded from the published
marketing template, and it is the first thing in this repo built from a written
design rather than improvised: a sitemap and per-page content spec
(`2026-09-01-www-content-spec`) drove a design brief, and the returned design in
`.agent/docs/design/www/` is now normative for both the app and the template it
ships as. The IA narrows to three pages — `/`, `/features`, `/roadmap`. Three
blocks are new (`Stats`, `CodeShowcase`, `Split`), all eight existing renderers
were rebuilt against the design, and `Hero` grows a `variant` so the interior
pages reuse it compactly instead of forking a second hero. Seven shared
components carry the repeated shapes (`Container`, `SectionHeader`, `BrandMark`,
`CopyButton`, `InstallCommand`, `CodePane`, `MediaImage`). `CodeShowcase`
highlights with shiki in a server component, so no highlighter reaches the
client. Everything is field data on seedable blocks, never bespoke per-page JSX,
which is what lets one `pnpm seed` stand the whole site up.

**Nested `select` fields now generate literal unions.** `childInterfaceType()`
resolves the TypeScript type for a field nested inside another field, and the
three builders that needed it — blocks, groups, arrays — each duplicated the
logic and all three fell through to a generic `string[]`. Collections had been
emitting proper unions all along. A `select` inside a block now types as
`("full" | "compact")[]`, so renderers derive from generated types instead of
re-declaring hand-written unions beside them; `RoadmapItemStatus` was the last
such duplicate and is gone. `Roadmap.status` also gains a fifth value, `future`,
separating committed-but-unscheduled work from open research.

**`select` fields were unusable below the fold, and the cause was none of the
obvious candidates.** Opening one on a scrolled admin page threw the viewport
1341px and left the trigger off-screen. Scroll locks, Base UI's
`alignItemWithTrigger` page-scrolling, and a global `scroll-behavior: smooth`
were all real members of the defect family but none was the writer; that guess
cost three rounds and is now recorded as an anti-pattern. A floating popup is
positioned a frame or two *after* it mounts, and until then sits at the end of
`<body>`, thousands of pixels from its trigger. cmdk `scrollIntoView`s its
highlighted item in a mount-time layout effect inside that window, walking every
scrollable ancestor and dragging the page to the popup's pre-position location.
`scrollIntoView` takes no `preventScroll`, so it cannot be made safe — only a
no-op: `MultiSelectContent` holds content at `display: none` until positioned,
then reveals, focuses with `preventScroll`, and performs the item scroll itself.
Verified against the running admin edit form at three viewport positions through
full open/pick/close cycles: zero movement. Two regression tests pin the reveal
and focus behaviour.

**The admin gate no longer fails open.** `useCanAccessAdminPanel()` evaluates the
same `canAccessAdminPanel` predicate the server route uses, so the header stops
guessing at role names. It deliberately does *not* defer to `hasPermission`,
which returns `true` when handed no access config — correct for a server guard,
wrong on a public route where the absence only means no provider is mounted. The
hook fails closed on missing context or user.

**Admin readability.** Every collection and global declares an `admin.icon` and
every field an explicit `label`. The worst offender was repeatable rows:
`FormLabel` falls back to a field's path when it has no label, and `group()`
defaults `label` to `""` (only `defineCollection` infers one), so array items
rendered as `[10] - blocks[3].items[9]`. The `group()` passed as each array's
`items` is now labelled, and rows read `[10] - Roadmap Item`.

**Five template defects that only a real scaffold could surface.** Typecheck and
build passed throughout while a scaffolded project was broken: `turbopack.root`
pinned to the app directory broke every `--monorepo` build; base's
`(frontend)/page.tsx` collided with the marketing home on `/` and won; base's
fail-closed proxy matcher sent `/features` and `/roadmap` to sign-in; `anyApi`
in user-project code discarded the types the generated `api` already carries;
and `<img src={uploadField}>` set `src` to a Convex document id, so no uploaded
logo ever rendered. The overlay installer can only add and overwrite — never
delete, never edit `package.json` — so the route removal and the marketing-only
`shiki` dependency move into a new `finalizeMarketingOverlay()`.
`scripts/template-diff.mjs` now reports app↔template drift against the effective
template file, and the `template-sync` skill runs it instead of eyeballing.

**Verified** under forced, uncached runs: typecheck 15/15, tests 12/12, build
11/11, lint 0 errors, no naming violations, plus fresh scaffolds in both `--yes`
and `--bare` modes. The sticky `GlobalEditView` header rides along from an
earlier session, as this project commits the working tree in one commit per run.
