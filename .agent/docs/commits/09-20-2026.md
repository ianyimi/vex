feat(core,react,next): live preview — stream unsaved editor values into the real page

Ships launch-plan item E (ADR-012). `livePreview: { url }` was accepted on global admin
config and stored on the resolved config, but nothing read it — no listener, no panel, no
transport. A collection or global now declares `admin.livePreview.url`, a resolver from the
document to the public URL its preview renders, and the admin panel streams the form's
unsaved values into that page as the editor types. No drafts, no autosave, no preview
route: the target is the document's real public URL, and the overlay is applied on top of
whatever query the consumer already runs.

**Core.** New `livePreview` module: `LivePreviewUrlResolver`, `LivePreviewBreakpoint`, the
`admin.livePreview` input/resolved shapes, root `livePreview.{allowedOrigins,breakpoints}`,
the wire/gate constants, and pure helpers for the panel cookies and split-pane floors.
`AdminCollectionConfig`/`GlobalAdminConfig` gain a trailing `TCollectionSlug`/`TGlobalSlug`
generic — appended last, so no positional caller breaks — which types a resolver's `doc`
to that slug's exact generated document interface, inferred from the sibling `slug` with
no extra syntax. `DocumentByGlobalSlug` is new, mirroring `DocumentByCollectionSlug`.

`admin.livePreview.url` is declared with method syntax rather than as a property-position
function type: a property position makes `TDoc` strictly contravariant, which stopped a
`CollectionConfig` with a still-generic slug being assignable to the concrete union the
admin views hold, breaking `useCollectionForm`/`useGlobalForm`.

**React.** `<LivePreviewProvider>` keeps an `id → unsaved values` map fed by two transports
at once. `postMessage` is point-to-point but needs a window reference, which only exists
for the embedded iframe; a shared-name `BroadcastChannel` covers every surface that has no
reference — a duplicated tab, one opened from the panel's link — and a mount handshake
makes a newly-opened surface pull current state instead of waiting for the next keystroke.
Incoming payloads are validated against the target collection's Zod schema, and only the
keys the sender actually sent are overlaid: `.partial()` still applies field defaults, so
overlaying the parsed object blanked every field the editor had not touched.

Consumers read it through `useLivePreview(doc, slug)`, or `useLivePreviewQuery` — sugar for
the `getBySlug`-returns-an-array shape, narrowing to the single overlaid document. The
admin side adds `LivePreviewPanel` (resizable split pane, full-screen overlay on mobile,
breakpoint buttons that scale the frame rather than clipping or stretching it),
`useLivePreviewSync` (debounced full-snapshot posts; never a partial diff), a floating
`LivePreviewIndicator` for a page opened in its own tab, and a shadcn `ui/resizable`
primitive over the new `react-resizable-panels` dependency.

**Admin shell.** `main` is now the app's only scroll container — the wrapper was
`min-h-svh`, so the window scrolled and its scrollbar appeared and disappeared as views
changed height, shifting the layout on every preview toggle. Both edit views render a
`shrink-0` toolbar above a scrolling region in either mode, so the scrollbar never changes
owner; `usePreservedScrollTop` carries the offset across the container swap. Split-pane
geometry persists per collection/global in cookies read server-side by `NextAdminPage`
(open/closed and handle position), so a remembered layout paints correctly on the first
frame instead of snapping into place after hydration. Pane floors are pixel minimums
converted to shares of the measured split, capped so the two can never sum past 100.

**Next.** `NextAdminPage` reads both panel cookies via `next/headers` and threads them into
the edit views.

**apps/www + marketing-site template.** `pages` gets `admin.livePreview.url`, the root
config an origin allowlist, `PageContent` reads through `useLivePreviewQuery`, and
`proxy.ts` splits into a path dispatcher: the admin branch still fails closed, a new public
branch grants preview mode only after verifying an admin session. Preview mode is gated,
not ambient — the panel appends `?vexLivePreview=1` and the listener attaches only when a
session-verified `vex-live-preview` cookie is also present. The public route fails open: a
stale session renders the normal published page rather than redirecting.

The gate is a cookie, not the `x-vex-live-preview-enabled` request header the spec called
for. Reading a header in a layout opts the whole route out of static generation, which
would have undone the prerendering the SEO work delivered; `/` stays statically
prerendered. Recorded as an amendment on ADR-012, along with the second transport.

**Also fixes `<CodePane> is an async Client Component` on apps/www**, long-standing and
load-bearing here. `PageContent` is a client component, so every block below it is too,
and `CodePane` awaited shiki — it survived the server pass and threw on every client
re-render, which live preview causes constantly. `highlightPageBlocks` now pre-highlights
the fetched document's panes server-side into a `{ key → html }` map that crosses the
boundary as plain strings; `CodePane` is synchronous and reads it. Code that exists only in
the browser (what an editor is typing) misses the map and lazily imports a browser
highlighter, so ordinary visitors still ship none. Code panes move to the `tokyo-night`
theme over the unchanged Stark Ember surface.

**Template sync.** Every structural change above is mirrored onto
`templates/marketing-site`; `apps/www`'s marketing copy and seed content are deliberately
not. `scripts/template-diff.mjs` reports no live-preview file as app-only.

Known limits, both deliberate: neither transport reaches another browser or device (both
are same-machine constructs by web-platform design), and a cross-origin preview opened via
the header link gets no live updates — `BroadcastChannel` cannot cross origins and no
window reference exists for `postMessage`. The embedded iframe still works cross-origin.
Lifecycle hooks never run on preview data, so the preview renders what was typed,
pre-`beforeChange`.
