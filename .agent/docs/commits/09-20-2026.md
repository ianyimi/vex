## 01:45 — feat(core,react,next): live preview — stream unsaved editor values into the real page

Raw message: `.agent/docs/session-log/2026/09/2026-09-20.commit.md`

feat(core,react,next): live preview — stream unsaved editor values into the real page

Ships launch-plan item E (ADR-012). `livePreview: { url }` was accepted on global admin
config and stored on the resolved config, but nothing read it — no listener, no panel, no
transport. A collection or global now declares `admin.livePreview.url`, a resolver from the
document to the public URL its preview renders, and the admin panel streams the form's
unsaved values into that page as the editor types. No drafts, no autosave, no preview
route: the target is the document's real public URL, and the overlay is applied on top of
whatever query the consumer already runs.

**Core.** New `livePreview` module: `LivePreviewUrlResolver`, `LivePreviewBreakpoint`, the
`admin.livePreview` input/resolved shapes, root `livePreview.{allowedOrigins,breakpoints}`,
the wire/gate constants, and pure helpers for the panel cookies and split-pane floors.
`AdminCollectionConfig`/`GlobalAdminConfig` gain a trailing `TCollectionSlug`/`TGlobalSlug`
generic — appended last, so no positional caller breaks — which types a resolver's `doc`
to that slug's exact generated document interface, inferred from the sibling `slug` with
no extra syntax. `DocumentByGlobalSlug` is new, mirroring `DocumentByCollectionSlug`.

`admin.livePreview.url` is declared with method syntax rather than as a property-position
function type: a property position makes `TDoc` strictly contravariant, which stopped a
`CollectionConfig` with a still-generic slug being assignable to the concrete union the
admin views hold, breaking `useCollectionForm`/`useGlobalForm`.

**React.** `<LivePreviewProvider>` keeps an `id → unsaved values` map fed by two transports
at once. `postMessage` is point-to-point but needs a window reference, which only exists
for the embedded iframe; a shared-name `BroadcastChannel` covers every surface that has no
reference — a duplicated tab, one opened from the panel's link — and a mount handshake
makes a newly-opened surface pull current state instead of waiting for the next keystroke.
Incoming payloads are validated against the target collection's Zod schema, and only the
keys the sender actually sent are overlaid: `.partial()` still applies field defaults, so
overlaying the parsed object blanked every field the editor had not touched.

Consumers read it through `useLivePreview(doc, slug)`, or `useLivePreviewQuery` — sugar for
the `getBySlug`-returns-an-array shape, narrowing to the single overlaid document. The
admin side adds `LivePreviewPanel` (resizable split pane, full-screen overlay on mobile,
breakpoint buttons that scale the frame rather than clipping or stretching it),
`useLivePreviewSync` (debounced full-snapshot posts; never a partial diff), a floating
`LivePreviewIndicator` for a page opened in its own tab, and a shadcn `ui/resizable`
primitive over the new `react-resizable-panels` dependency.

**Admin shell.** `main` is now the app's only scroll container — the wrapper was
`min-h-svh`, so the window scrolled and its scrollbar appeared and disappeared as views
changed height, shifting the layout on every preview toggle. Both edit views render a
`shrink-0` toolbar above a scrolling region in either mode, so the scrollbar never changes
owner; `usePreservedScrollTop` carries the offset across the container swap. Split-pane
geometry persists per collection/global in cookies read server-side by `NextAdminPage`
(open/closed and handle position), so a remembered layout paints correctly on the first
frame instead of snapping into place after hydration. Pane floors are pixel minimums
converted to shares of the measured split, capped so the two can never sum past 100.

**Next.** `NextAdminPage` reads both panel cookies via `next/headers` and threads them into
the edit views.

**apps/www + marketing-site template.** `pages` gets `admin.livePreview.url`, the root
config an origin allowlist, `PageContent` reads through `useLivePreviewQuery`, and
`proxy.ts` splits into a path dispatcher: the admin branch still fails closed, a new public
branch grants preview mode only after verifying an admin session. Preview mode is gated,
not ambient — the panel appends `?vexLivePreview=1` and the listener attaches only when a
session-verified `vex-live-preview` cookie is also present. The public route fails open: a
stale session renders the normal published page rather than redirecting.

The gate is a cookie, not the `x-vex-live-preview-enabled` request header the spec called
for. Reading a header in a layout opts the whole route out of static generation, which
would have undone the prerendering the SEO work delivered; `/` stays statically
prerendered. Recorded as an amendment on ADR-012, along with the second transport.

**Also fixes `<CodePane> is an async Client Component` on apps/www**, long-standing and
load-bearing here. `PageContent` is a client component, so every block below it is too,
and `CodePane` awaited shiki — it survived the server pass and threw on every client
re-render, which live preview causes constantly. `highlightPageBlocks` now pre-highlights
the fetched document's panes server-side into a `{ key → html }` map that crosses the
boundary as plain strings; `CodePane` is synchronous and reads it. Code that exists only in
the browser (what an editor is typing) misses the map and lazily imports a browser
highlighter, so ordinary visitors still ship none. Code panes move to the `tokyo-night`
theme over the unchanged Stark Ember surface.

**Template sync.** Every structural change above is mirrored onto
`templates/marketing-site`; `apps/www`'s marketing copy and seed content are deliberately
not. `scripts/template-diff.mjs` reports no live-preview file as app-only.

Known limits, both deliberate: neither transport reaches another browser or device (both
are same-machine constructs by web-platform design), and a cross-origin preview opened via
the header link gets no live updates — `BroadcastChannel` cannot cross origins and no
window reference exists for `postMessage`. The embedded iframe still works cross-origin.
Lifecycle hooks never run on preview data, so the preview renders what was typed,
pre-`beforeChange`.

## 02:08 — build(dev): resolve workspace packages to source so package edits hot-reload

Raw message: `.agent/docs/session-log/2026/09/2026-09-20.commit.md`

build(dev): resolve workspace packages to source so package edits hot-reload

Editing a file under `packages/*/src` stopped reaching the browser: the apps resolved
`@vexcms/*` through the `import` condition to `dist`, so every change had to round-trip
through that package's `tsup --watch` first — and that watcher silently drops filesystem
events for some directories. `packages/react/src/components/livePreview/**` never fired
while `src/hooks/**` and `src/context/**` did, with the OS delivering events for all of
them (verified against raw `fs.watch` and a standalone chokidar process). tsup's ignore
predicate is `globSync(path, { ignore }).length === 0`, and tinyglobby defaults to
`onlyFiles: true`, so directory paths glob to nothing and read as ignorable. Scoping the
watchers with `tsup --watch src` helped but did not fix it.

**Dev resolves source.** `apps/www/next.config.ts` and `apps/test/next.config.ts` gain
`workspaceSourceAliases()`, feeding `turbopack.resolveAlias`. It derives the map from each
package's own `exports.*.source` condition rather than hardcoding paths, so adding a
subpath export needs no edit here, and it skips string exports carrying no `source`
(`@vexcms/react/styles` is a CSS file). 17 specifiers across `core`, `react`, `next`,
`better-auth`, and `file-storage-convex`. Next now watches the real `.tsx` files: real
Fast Refresh, and no bundler in the dev loop. `transpilePackages` is deliberately absent —
the alias bypasses `node_modules` entirely, so it would buy nothing.

**Production is unchanged.** The helper returns an empty map when
`NODE_ENV === "production"`, so builds keep resolving `dist` and what ships is exactly what
the published packages contain. Verified: after the change, `apps/www`'s production build
still lists `packages/react/dist/index.js` in its client-reference manifest, and `/` is
still statically prerendered.

**Alias values are relative to the app directory, not `turbopack.root`.** The comment on
`apps/test`'s pre-existing nuqs aliases claims the latter; following it produced an alias
that resolved to nothing and fell back to `dist` with no error, which is why the first
attempt appeared to do nothing at all. Absolute paths are rejected outright (Turbopack
prefixes `./` and reports "server relative imports are not implemented yet"). Paths are now
computed with `relative(appDir, absoluteSource)`, proven by the same manifest flipping from
`packages/react/dist/index.js` to `packages/react/src/index.ts`. By that evidence the nuqs
aliases are themselves inert; they are left alone here because correcting them changes
runtime behavior and wants its own verification.

**`@vexcms/react`'s client boundary moves into the source barrel.** `src/index.ts` and
`src/testing/index.ts` now open with `"use client"`, and `tsup.config.ts` drops the `banner`
that used to inject it. A banner only exists in the bundle, so an app importing
`src/index.ts` directly would fail its first RSC import with "You're importing a module that
depends on useState into a React Server Component module". Marking the barrel reproduces the
banner's semantics exactly — everything reachable from a client entry joins the client
graph — rather than auditing ~90 modules individually. esbuild preserves an entry's
directive prologue, so `dist/index.js` and `dist/testing/index.js` still open with exactly
one `"use client";`; keeping the banner too emitted it twice.

**Templates are deliberately not synced.** `scripts/template-diff.mjs` flags
`next.config.ts` as CHANGED and it stays that way: a scaffolded project has no `packages/`
directory, so these aliases are meaningless there. Everything else the diff reports is
pre-existing drift this commit does not touch.

Also folded in: two formatting-only edits made in the same working tree —
`LivePreviewPanel.tsx` unwraps a redundant flex `div` around the preview link, and
`CollectionEditView.tsx` re-indents the split-pane block under its wrapper element.

**Launch plan: E is done, C is next.** `v0.1.0-launch-plan.md`'s sequence table flips row

The E section itself is marked SHIPPED and kept as the record of _why_ the feature is
shaped the way it is, with the four places the build diverged from the written design
called out inline and the spec's own `## Design Decisions` named authoritative where they
disagree: the transport is dual `postMessage` + `BroadcastChannel` (`postMessage` alone
cannot reach a tab the admin never opened); the preview gate is a session-verified
`vex-live-preview` cookie rather than a request header, because a `next/headers` read in
the site layout opted every public route out of static prerendering; `@vexcms/next` ships
no `NextLivePreviewProvider`, since the config carries functions and cannot cross the RSC
boundary as a prop (ADR-013); and the split-pane width persists in a server-read cookie
rather than `autoSaveId`, so the pane paints at its remembered size instead of snapping.

**`2026-08-23-versioning-drafts` is superseded by `2026-09-20-versioning-drafts`.** The
old draft predates three things that invalidate it: F's write pipeline and lenient
validation mode, E's overlay (which removes the only reason drafts were needed for
preview, and needs no change itself — the overlay already applies to whatever document
the consumer's query returned), and the `access-constraint-builder` rework that deleted
the index API its Step 10 was written against. The replacement is a fresh 18-group spec;
the old `spec-tasks.md` gains a "Superseded" banner and is kept for its design history,
since `design-review.md`'s two-row model, RBAC shape, and read-path analysis carry
forward unchanged. A new spec id rather than an edit, so it is unambiguous which file is
implementable.

**Admin dashboard cards show collection icons.** `DashboardView` renders a collection's
or global's configured `admin.icon` beside its card title, matching how the sidebar
already presents them; entries without an icon are unchanged.

**`apps/www` tidy-ups.** `SessionButton` drops its raw `lucide-react` imports for the
package's own `Icon` component and shows a spinning `LoaderCircle` while a sign-out is in
flight. `auth/access.ts` factors the repeated `{ "*": false, read: true }` grant into a
`readOnly` const — behavior identical, though the refactor also removed the block comment
explaining why `images.read` is load-bearing for the public site (`MediaImage` and
`src/lib/metadata.ts` both resolve uploads through the RBAC-gated `vex/media:getUrl`).
