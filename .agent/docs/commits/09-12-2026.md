feat(core)!: replace group defaultOpen with admin.defaultCollapsed

**Group collapse config mirrors `blocks()` and Payload.** `group()`'s top-level `defaultOpen`
is replaced by `admin.defaultCollapsed`, so every collapsible field in a config reads the same
way. The polarity is the INVERSE of what it replaced and the default is `false`, matching
`blocks/config.ts` — a group is expanded on load, and `true` is the opt-in for secondary or
rarely-edited groups. Call sites migrated in `apps/test` and `apps/www`. The JSDoc for both
`GroupFieldAdminConfigInput` and `GroupFieldAdminConfig`, the defaults block, and the
`@example` had carried the old `defaultOpen` prose verbatim, which described the opposite
behaviour under the new name; all three are rewritten, along with `fields/group.mdx` and
`useAccordionDndState`'s usage example.

**Read access no longer disables form navigation.** `FormGroup` and `FormBlocks` passed
`readOnly` straight into `AccordionItem`'s own `disabled` prop, so a caller holding read but
not write access could not expand a `group`, `array` or `blocks` field to see values it was
allowed to read. Collapsing is navigation, not editing: the two `disabled={readOnly}` props are
gone, while add/remove buttons, drag handles, the `blockName` input and every sub-field stay
individually gated. Pre-existing since `10d3809` rather than a consequence of field-level
permissions, which only changed what `readOnly` evaluates to.

`runNestedFieldContainerSuite` pins the rule for all three containers across every child field
type: its "cascades readOnly" assertion previously required EVERY control to be inert,
trigger included, so it encoded the bug — it now skips disclosure triggers and a new case
asserts each one is operable and actually toggles. Triggers are matched on
`data-slot="accordion-trigger"`, which `FormBlocks`' `AccordionPrimitive.Trigger` now carries
for parity with the `ui/accordion` wrapper; matching `aria-expanded` instead wrongly caught a
nested `select`'s combobox, an editing control that must stay disabled.

**The accordion no longer flashes open on load.** `AccordionContent` animates with a CSS
transition on the inner wrapper's height, driven by Base UI's own
`data-starting-style`/`data-ending-style` and `--accordion-panel-height`, instead of the
`animate-accordion-*` keyframes. Those keyframes could not be salvaged: `tw-animate-css`
animates `height: 0` toward `--radix/bits/reka/kb-accordion-content-height`, none of which
Base UI sets, so on mount the animation ran from zero to a bogus end value — measured ~70ms at
`height: 0` while the content was already full height. Base UI does try to suppress this
(`useCollapsiblePanel` seeds `shouldCancelInitialOpenAnimationRef` from the initial `open` and
blanks `animation-name` while measuring), but the keyframes won. Withholding the class until
after mount does not help either, because applying an `animation-*` class to an element that
already matches `data-open` starts the animation at that point. A transition interpolates only
when the height actually changes, so a panel that mounts open is simply open and one that
mounts closed is simply closed.

The cost, accepted deliberately: the open/close toggle is now instant rather than animated.
Restoring the animation means defining the keyframes against `--accordion-panel-height`, which
requires shipping a stylesheet from `@vexcms/react` or documenting a `globals.css` addition.
Note `apps/www/src/components/ui/accordion.tsx` is a separate copy and still uses the old
keyframes.

**Field-permission documentation brought in line with what shipped.** The access-control guide
was written mid-implementation and had since gone wrong in two places: it claimed a field map
without `"*"` must name every field of the document (partial maps are valid, and an omitted key
is denied), and it used a worked example that no longer matched `apps/www`. It now also covers
the `throwOnDenied`-conditional developer error, create-versus-update diff semantics,
hidden-versus-read-only admin gating, disclosure staying operable, the diff submit, and the
public API surface. `guides/globals.mdx` gains an `## Access control` section documenting that
`upsertGlobal` authorizes `create`/`update` rather than `read` and merges partial payloads;
`guides/local-api.mdx` documents read-path stripping.

BREAKING CHANGE: `group()` no longer accepts a top-level `defaultOpen`. Use
`admin.defaultCollapsed`, whose meaning is inverted: `defaultOpen: false` becomes
`admin.defaultCollapsed: true`, and omitting it leaves the group expanded as before.
