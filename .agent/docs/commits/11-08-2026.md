feat: land launch infrastructure, a11y quality pass and public presence

**Roles hardening (core, better-auth, templates).** `roles` in every auth schema (www,
apps/test, base-nextjs template) now carries `input: false`, so a sign-up or update-user
call can no longer write `["admin"]` onto its own row. `defineServerConfig` backs this with
`assertRolesFieldNotClientWritable`: `VexAuthAdapter` gains optional
`clientWritableUserFields`, `betterAuthAdapter()` fills it from the merged user fields where
`input !== false`, and a client-writable `access.userRolesField` throws
`VexAuthConfigError` at config time. Changesets `roles-not-client-writable` and
`auth-roles-guard`.

**Drafts out of sitemaps (core).** `vexServerApi`'s bound `publishedSlugs` dropped the bound
config/auth, so draft-only rows in `versions.drafts` collections reached every
`sitemap.xml` and `generateStaticParams`. It now injects them like the other bound
operations; regression test in `publishedSlugs/server.test.ts`. Changeset
`published-slugs-skip-drafts`.

**Live-demo hardening (www).** convex-test harness split into `app`/`convex` vitest
projects; read-only access suite (14 mutations x 2 callers); hourly expired-anonymous-user
purge cron; proxy-attested auth rate limits via `@convex-dev/rate-limiter` 0.3.2 and
`AUTH_PROXY_SECRET`; `FirstAdminBootstrap` skips `isBootstrapped` when signed out; static
`/tour`, admin `error.tsx` with a `/tour` redirect on session-verification failure, Speed
Insights (sampled), `/privacy`. Ported verbatim to `apps/test`. `AUTH_PROXY_SECRET` is
declared in `turbo.json`'s build `env` (strict env mode would otherwise drop it on Vercel)
and placeholdered in `vercel-build-check.mjs`; `apps/www` takes `vite` as a direct dev
dependency so the `vite/client` reference in `createConvexTest.ts` resolves in a pristine
install.

**Accessibility and standards pass (react, richtext-plate, www, test).** jsx-a11y at
`error` through a shared `eslint.jsx-a11y.mjs` (root, both apps, base-nextjs template),
Playwright + axe, Lighthouse CI, Nu validator and a `quality.yml` workflow; findings ledger
F-001…F-142. Primitive fixes against APG (sidebar, multi-select chips, pagination,
date/time pickers, resizable, data-table labels and a keyboard-operable column resize capped
at 90% of the container), a `useAriaControlsCleanup` hook that strips dangling
`aria-controls` from accordion triggers, admin field fixes (array descriptions, timestamp
labels, media/relationship status regions, richtext toolbar label-in-name, dialog initial
focus), `ThemeProvider` applying the stored theme in `useLayoutEffect`, a darker
`--primary` for focus contrast, skip link/landmarks, `not-found` pages, production-only CSP
and security headers, and a pnpm patch for `@daveyplate/better-auth-ui`. Colocated tests
for each.

**Public presence.** Labels taxonomy + `scripts/sync-labels.mjs`, issue forms, PR template,
FUNDING, CONTRIBUTING, CODE_OF_CONDUCT, SECURITY, social preview; slim README; docs roadmap
rewrite, `compare` and `accessibility` pages, Sponsors/Release-emails header links, a
page-analytics section and `Head.astro` analytics; www `posts` collection with
`/posts/[slug]`, brand kit and `/brand`, roadmap/FAQ/footer seed copy in both apps.

**Templates (N).** `base-nextjs` and `marketing-site` synced from `apps/test` and
`apps/www` (CSP, drafts + live preview on `pages`, `SessionButton`, root `not-found`,
`useSitePreviewMode`); `n-sync.md` records the disposition of every template-diff row.
`getAuth` hoist and the `(site)/page.tsx` try/catch removal stay out — they break the
scaffold gates. `string-utils.ts` renamed to `stringUtils.ts`;
`regen-template-schema.mjs` passes `{ configPath, projectDir }` to `loadConfig`.

**Harness.** Specs, coordination board, launch plan, backlog and standards updates for the
launch-kit, launch-infrastructure, quality-pass and public-presence work; new draft spec
`2026-11-07-pre-launch-dependency-upgrades` with its research note.

feat(react,core,next,www,test,create-vexcms)!: tree-shakeable packages, /admin entry, lazy icons

Public pages loaded about 3.2 MB of JavaScript, most of it admin panel: TanStack
Table, dnd, every field component, all 1703 lucide icons and the auth UI. CI
Lighthouse TBT was 277–570 ms against a 200 ms budget. Any consumer importing one
hook from `@vexcms/react` paid for the whole package.

**Per-module dist (react, core).** `scripts/preserveModulesPlugin.mjs` makes tsup
emit one dist file per source module instead of a shared `chunk-*.js`, so bundlers
tree-shake per module. The react root barrel no longer carries `"use client"`. Each
client module declares its own, enforced by `src/clientDirective.test.ts`. `sideEffects`
is `["./src/adapter.ts", "./dist/adapter.js"]`. The `./form` export now points at
`dist/forms/*` (its types path never existed). ADR-017 supersedes ADR-009.

**Root vs `@vexcms/react/admin`.** A server component importing a barrel ships every
`"use client"` module the barrel reaches, so panel internals moved behind
`src/adminEntry.ts`:
- `reactAdapter` and the field `*Admin`/`*Cell` components
- slots and the document-edit runtime
- admin layout/views and collection/media/global views
- list-view context, `LivePreviewPanel`, the modal surface, `useVexForm`
- data-table, dnd, sidebar and resizable
- new exports: `VersionHistoryDropdown` and `AdminFieldBinding`

`useAppForm`/`AppForm` live at `@vexcms/react/form`. `ReactHKT`/`ReactAdapter` types
stay importable from the root. `@vexcms/next` imports the moved views from `/admin`.

**Icons.** `Icon` loads icons on demand through `lucide-react/dynamic.mjs` (lucide
0.577.0 has no exports map), with a same-size placeholder, everywhere including the
admin. `isIconName` guards untyped names. `resolveIconNodes` (`@vexcms/react/server`)
plus `IconNodeProvider` render CMS icons synchronously from the server HTML. Pages and
the site layout resolve their documents' icons, so first paint makes no icon requests.
The Features, HowItWorks, Footer and Split blocks use `Icon` instead of `icons[name]`.
`SessionButton` uses static icons.

**Auth UI.** `AuthUIProvider` mounts only in `src/auth/AuthViewProvider.tsx` around
`AuthView` (www, test, base-nextjs). The create-vexcms installer writes the OAuth and
credentials options there.

**Hero.** Only the heading animates. The badge, subheading, CTAs and install command
render at first paint; the CTA's delayed reveal was the LCP element.

**Gates.**
- `scripts/check-import-cost.mjs` (CI): esbuild consumer fixtures against `dist`.
  `cn` costs 26.5 KB (was 2.3 MB), `useLivePreviewQuery` 14.5 KB, and the root's full
  reach has no admin module.
- `scripts/check-site-bundle.mjs` (CI, apps/test): Next's analyzer, per-route budgets
  and a deny list. `/` is about 1.78 MB (was 3.35 MB). It fails when a route is absent
  from the analysis.
- `scripts/export-names.mjs` reads exports statically and tracks every react entry.
- Local Lighthouse: performance 1.0 on `/`, `/features` and `/auth/sign-in`
  (TBT 8–77 ms, CLS 0).

**Fixes.** `dropdown-menu.test.tsx` waits for Base UI's rAF focus before typing;
`verify-scaffold.mjs --negative` awaits `runTemplate`. Templates mirror every app
change. Docs gain a "What ships to your pages" section and corrected `/admin` imports.

BREAKING CHANGE: panel internals moved from `@vexcms/react` to `@vexcms/react/admin`,
and `useAppForm`/`AppForm` to `@vexcms/react/form`. The migration table is in
`.changeset/react-admin-entry.md`. `AdminIcon` never shipped; use `Icon`.
