# Commits — 2026-08-12

## 00:13

feat(core): add globals system with flat typed api and admin ui

**Globals core (spec 35).** Add `defineGlobal` with the five
CollectionConfig-parallel generics and compile-time reserved-key enforcement
(`_id`, `_creationTime`, `_slug`). All globals share a single `vex_globals`
Convex table (`slug` + `data: v.any()`), emitted by `generateVexSchema` only
when globals are registered. The API layer flattens each global on read and
re-nests on write: `globalsApi(config, query, mutation)` registers
`globals.get`, `globals.find`, and `globals.update` (find-by-slug upsert),
with populate/depth reusing the collection populate machinery directly on
flat documents — relationship IDs sit at root level, so `populateDocs` reads
them identically to collection documents (D17).

**Type generation.** `vex generate` emits flat per-global interfaces
(`NavGlobal extends VexDocumentGlobal<"nav">`) plus `GlobalSlug`,
`GlobalDocumentBySlug`, and `GlobalsFieldTypeMap` inside the
`GeneratedVexTypes` augmentation, giving `globals.get({ slug })` compile-time
slug validation and populate narrowing identical to collections. The
`defineGlobal` slug generic is constrained by `GlobalSlug`, mirroring
`defineCollection`'s `CollectionSlug` constraint.

**Admin UI.** New `GlobalsListView` (config-driven index; DB queried only for
timestamps) and `GlobalEditView` (singleton edit form reusing the existing
field renderers). New `useGlobalForm` hook mirrors `useCollectionForm` per
D21, driven by `getGlobalDefaultValues`/`getGlobalInputSchema`;
`useCollectionForm` and the collection form utils stay collections-only —
the interim `CollectionConfig | GlobalConfig` widening is reverted. Previously
passing a `GlobalConfig` into `useCollectionForm` failed workspace typecheck
once `CollectionSlug` narrowed (a global slug is never a collection slug).
`AdminTopNav` is rebuilt around a crumbs array (replacing triplicated
divider JSX) and renders config-driven `Home › Globals › <label>` breadcrumbs;
on globals routes the document subscription is skipped because the third path
segment is a global slug, not a Convex document ID. The sidebar gains a
globals section.

**Next adapter + www.** `NextAdminPage` routes `/admin/globals[/slug]`,
validating the slug against `config.globals` before fetching so the narrowed
`globalConfig.slug` flows through without casting the raw URL segment, and
rendering a not-found state for unregistered slugs. `GlobalEditViewProps`
drops the redundant `slug` prop — the slug derives from `global.slug`, and
the page title uses `global.label` (D16). apps/www registers the `nav`
global, wires `globalsApi` in `convex/vex/globals.ts`, replaces the legacy
`convex/vex/collections.ts` wiring, and regenerates schema and types.
