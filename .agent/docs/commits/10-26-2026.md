feat(core,react)!: reorganize packages into domain folders and app form

**Core domain folders.** `src/api/` is dissolved: collection, global and version server operations now live beside their domain as `collections/api/`, `globals/api/` and `versions/api/` `<op>/server.ts` modules, `media/api/` follows the same scheme, and the shared read/write pipeline moves to `src/db/` with the access dispatchers (`resolveAccessCall`, `resolveReadCall`) in `access/`. All four document shapes (`VexDocument`, `TDocument`, `VexVersionDocument`, `VexMediaDocument`) live together in `src/documents/types.ts`; `vexConvexApi` gets its own file and `src/server.ts` is the single server entry. `ComponentHKT`/`ApplyComponent` move to `components/types.ts`, `validateFields` to `fields/validate.ts`, the live-preview resolver to `livePreview/api/resolve/server.ts`, and the missing `*FieldType` constants join `fields/constants.ts` (`UIFieldType` is deliberately absent — it collides with the existing union type). No shims: every importer was migrated.

**App form and field override contracts.** The old `createFieldInput` factory and the whole `components/form/` layer are replaced by the TanStack-based app form exposed as `@vexcms/react/form` (`useAppForm`, `AppForm`, one `forms/*Field.tsx` per type), with `useAppForm`/`AppForm` also re-exported from the package root. Admin field components are renamed `<Type>FieldAdmin` to pair with the existing `<Type>FieldCell`. Core drops `InputComponentProps`: `FieldComponentProps` carries the edit-form shape directly, `FieldControlProps` is the narrower shape an `admin.components.Input` override receives, and `admin.components.Field` is a new whole-field override slot.

**React feature folders.** `scripts/move-modules.mjs` (with tests) `git mv`ed the React package into top-level feature folders mirroring core — `ui/`, `utils/`, `config/`, `auth/`, `access/`, `slots/`, `modals/`, `livePreview/`, `revalidate/`, `fields/`, `forms/`, `collections/`, `globals/`, `versions/`, `media/`, `admin/` — rewriting every importer and `vi.mock` path. `usePaginatedQuery`/`usePaginatedSearch`/`useTableSelection` land in `hooks/`; the dead `usePaginatedQuery2` and narrating comments are gone. `scripts/export-names.mjs` snapshots the public export names so `--check` proves no unintended export changed across the moves.

**Regression restoration.** A 20-finding audit against the pre-refactor tree (4d504e7) is fixed, each with a regression test: array primitive labels hidden `sr-only`, compact menu order, the `MenuRootContext` error at narrow widths, stable stored-id keying for array/blocks items, inline vs menu item actions, paste above/below, clipboard `max` enforcement, the blocks permission check, group auto-open on a failed submit plus the field-count badge, the json placeholder, `RenderFields` defaulting its region to `'all'`, Label/Description slot overrides, checkbox `py-2`, the `DateField` invalid flag and a doubled `role=group`. Block item markup (borders, header band, accordion header/chevron, content padding, multi-open, picker search/footer/copy, empty-block message) is restored verbatim.

**Blocks header and button rows.** At the request of the developer, Collapse/Expand all stay inline while Copy all/Paste/Replace all always live in the ⋯ menu, and the compact switch uses the generic 512px form threshold instead of the removed `BLOCKS_HEADER_INLINE_MIN_PX`. Relationship and upload button rows now `flex-wrap` on narrow widths.

**Apps, templates, satellites.** `apps/www`, `apps/test` and the `marketing-site`/`base-nextjs` templates rename their components to PascalCase (`motion-primitives/AnimatedGroup`, `TextEffect`, `context/CodeHighlightContext`) and drop unused examples; `apps/test` gains a `FieldsTitleInput` `admin.components.Input` override that the Step 21 smoke exercised. `richtext-plate` comes under the `react-components-pascal` rule; dead `better-auth/src/utils.ts` and `file-storage-convex` `adapter/types.ts` are removed. `eslint.config.mjs`'s shadcn override follows `components/ui` → `ui`.

**Docs and harness.** New `apps/docs` Development section (`dev/*.mdx`) records the package layout and conventions, plus `fields/richtext.mdx`; `admin-customization.mdx` and `framework-adapters.md` lose stale paths, and the `@vexcms/react` README lists the full `<Type>FieldAdmin`/`<Type>FieldCell` set. Standards, `directory-structure.md`, `context-rules.yaml`, state and the session log are updated; the spec with its four review rounds lands under `.agent/docs/specs/2026-10-25-codebase-conventions-refactor/`.

BREAKING CHANGE: `@vexcms/core/convex` is removed — import the same names from `@vexcms/core/server`. `@vexcms/react`'s `<Type>FieldInput` components are renamed `<Type>FieldAdmin`, and `createFieldInput` plus the `components/form/` exports (`AppForm`, `AppFormContext`, `FormArray`, `FormBlocks`, `FormGroup`, `FormTabs`, `FormCollapsible`, `FormRow`, `FormUI`, `FormLabel`, `FormError`, `FormDescription`, `RenderFields`, `FieldConditionGate`) are removed in favor of `@vexcms/react/form`. `@vexcms/core`'s `InputComponentProps` is removed — use `FieldComponentProps`, or `FieldControlProps` for `admin.components.Input` overrides.
