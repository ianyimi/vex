fix(create): repair alpha.2 scaffold stand-up, prep alpha.3

Post-release fixes for the three failures a real alpha.2 scaffold hit on
first stand-up — a build break on the default (`--orgs` declined) path, a
403 on first sign-in, and a deprecated-`baseUrl` tsconfig error — each
root-caused live in the developer's `tmp/my-site` scaffold before being
ported back, plus the developer's alpha.3 version pass, committed as one
unit per P-016.

**Org-declined scaffolds actually build.** The installer stripped the
organization plugin but ten checked-in template files still referenced
`organization` unconditionally, so the first `vex dev` regen — which drops
org tables from the generated registry — broke `pnpm build`.
`configureOrganizations(false)` now also strips org wiring down to the
org-free shape across nine scaffolded files (`convex/vex.ts`,
`convex/vex/{globals,media}.ts`, `convex/auth/api.ts`,
`src/auth/{access,hasPermission}.ts`, `src/context/AuthContext.tsx`,
`src/db/constants/index.ts`, and full-scaffold `src/vexcms/api.ts`) via
six new `stripOrgFrom*` transforms in `installers/string-utils.ts`. Every
transform throws loudly when its expected pattern is missing instead of
silently no-opping on template drift. Four new integration tests pin the
declined-vs-accepted shapes; `--orgs` accepted scaffolds are untouched.

**`orgCollectionSlug` is optional.** `@vexcms/better-auth`'s
`createGetAuth` required it even when `resolveOrgs` was `false` — the
only case that ever read it — forcing org-declined scaffolds to pass a
throwaway placeholder slug. `resolveOrgs: true` without a slug now skips
org resolution instead of type-erroring.

**The convex tsconfig heals itself.** `@vexcms/cli`'s `patchConvexTsconfig`
no longer injects `baseUrl` (deprecated in TS 6/7, errors under
`moduleResolution: "Bundler"`) and actively deletes a leftover
`baseUrl: "."` it used to write, so already-scaffolded alpha.2 projects
self-heal on the next `vex dev`. It also ensures `../src/vex.types.ts`
stays in `include` — Convex rewrites the file on every provisioning pass
and would otherwise hide the `GeneratedVexTypes` augmentation from the
convex program. The template's `convex/tsconfig.json` matches: no
`baseUrl`/`ignoreDeprecations`, `types: ["node"]` (the relocated
`convex/auth/options.ts` reads `process.env`), `vex.types.ts` included.

**`motion` is gone from scaffolds.** The marketing overlay's
`AnimatedGroup`/`TextEffect` are rewritten as pure-CSS reveal/blur-in
(new `reveal.module.css`, new `AnimatedItem` export), the Hero block drops
its spring `transitionVariants`, and base-nextjs's `package.json` sheds
the `motion` dependency entirely.

**The 403 was documentation.** Better Auth runs inside the Convex
deployment and never reads `.env.local`; missing deployment-side env vars
are the most common first-sign-in failure. The base-nextjs README, the
create-vexcms README, and the docs quickstart now document
`npx convex env set SITE_URL …` / `npx convex env set BETTER_AUTH_SECRET …`
as a stand-up step.

**alpha.3 version pass.** Three patch changesets (cli, better-auth,
create-vexcms) folded by the developer's `pnpm version:packages` into
`pre.json`; the fixed group moves `0.1.0-alpha.2` → `0.1.0-alpha.3`
across the eight publishable manifests and CHANGELOGs, and the template's
`@vexcms/*` dependency ranges re-sync to `~0.1.0-alpha.3`.
`.gitignore` gains `/tmp/*` so live test scaffolds stay untracked.

fix(create): theme wiring, upload collection scoping, nested-build fixes

Post-alpha.3 test-iteration round, proven in the developer's live tmp/test
scaffold and ported back into the templates and packages, committed as one
unit per P-016.

**The marketing overlay finally themes.** base-nextjs ships no theme, so the
overlay now carries the full wiring: a new root `src/app/layout.tsx`
(apps/test pattern) mounts `ThemeScript` plus site-scope
`ThemeStyle`/`ThemeLive` once for the whole app, and a new
`(vexcms)/admin/layout.tsx` re-emits `ThemeStyle`/`ThemeLive` with
`scope="admin"` at `:root:root` specificity so `siteSettings.adminTheme`
overrides the site theme on admin routes only. `(frontend)/layout.tsx` drops
its now-duplicate `ThemeStyle` and instead mounts the new headless
`FirstAdminBootstrap`, which promotes the first signed-in user to admin —
previously a fresh marketing scaffold had no way to mint an admin without
visiting `/admin` cold. In base, `ThemeScript` lands in `<head>` so the
persisted light/dark class applies before first paint instead of flashing
light.

**Nested scaffolds build.** A scaffold living inside an outer monorepo made
Next walk up and adopt the outer lockfile, shifting Turbopack's file-tracing
root and Tailwind's source-scan root; `next.config.ts` pins
`turbopack.root: import.meta.dirname`. Tailwind's `@source` lines narrow to
each `@vexcms` package's `dist/**/*.js` and add `@source not "../../public"`
— the old workspace-relative raw-`src` globs only resolved inside this
monorepo and let the scanner chew binary/public assets into garbage
classes.

**Uploads are collection-scoped.** `VexMediaGenerateUploadUrlArgs` in
`@vexcms/core` gains a required `collection`, and `@vexcms/react`'s
`MediaUploadForm`/`MediaUploadDropzone` pass the target collection slug to
`generateUploadUrl`, so storage adapters can scope upload URLs per
collection. `FormBlocks` fixes the inverted drag-handle guard
(`disabled={!readOnly}` → `disabled={readOnly}`), which disabled block
reordering exactly when the form was editable, plus Tailwind class-order
normalization.

**Auth routes shed the site chrome.** `/auth/sign-in` (and every auth route)
rendered inside the marketing header/footer because `(frontend)/layout.tsx`
wrapped all of its children in `SiteHeader`/`SiteFooter`. The overlay now
splits a `(frontend)/(site)/` route group that owns the chrome plus the
header/footer fetches — `page.tsx`, `[slug]/`, and `PageContent.tsx` move in,
URLs unchanged — while `(frontend)/layout.tsx` shrinks to
`FirstAdminBootstrap` + `{children}` + the `@auth` slot, so auth pages render
as a standalone themed card and the sign-in modal interception keeps working.

**Template content.** The marketing seed grows features and roadmap pages
(+253 lines in `convex/seed.ts`); five block configs correct their defaults
(GitHub links `vexcms/vex` → `ianyimi/vex`, Hero badge "public beta" →
"public alpha"); `pages.ts` collapses the blocks array by default
(`admin.defaultCollapsed`); base's users collection gains
`name: text({ required: true })` with `admin.useAsTitle: "name"` — required
on purpose: an optional field regenerates as `name?: string` and collides
with better-auth's `name: string` user contract on the first `vex dev` run.

**getUserOrg stays session-first — the earlier verdict was a false
positive.** An intermittent `unauthorized` had been blamed on session
rotation and patched away from session-first lookup in the template's
`convex/auth/api.ts`; re-investigation traced the failures to Tailscale
IPv6 connection timeouts misread as auth rejections. The session row is the
revocation record, so session-first is correct: the patch was reverted to
HEAD and those files intentionally show no diff here.

Two changesets ride along (core + react minor for the upload API, a
create-vexcms patch for the template round), plus session log, ledger, and
regenerated state/struct.
