feat(core,react,next)!: versions and drafts part 4 (history, unpublish, draft reads)

**Version history.** New `listVersions`, `getVersionSnapshot`, `deleteVersion`, and
`unpublish` endpoints on `versionsApi`. History is view-only in the admin:
`VersionHistoryDropdown` shows a snapshot in the form via `viewingVersion`/`onViewVersion`
without saving, confirms before discarding unsaved edits, tags the published version and
live draft **Active**, hides delete on the live/shown/published row, and scrolls to the
shown version once Base UI finishes opening. Saving from an older version sends only the
edits plus `restoredFrom`; `saveDraft` rewrites the draft from that snapshot
(`buildDraftReplace`) and records it as the parent. `publish({ version })` publishes a
historical snapshot and marks that row published (`markVersionPublished`) instead of adding
rows; normal publish no longer archives the superseded state. Publish is disabled when the
form already matches the published document.

**Draft reads and constraints.** `get`/`find`/`search` (server + client) take
`drafts: true` to return the draft overlay for callers with `readDrafts`.
`statusConstraint` composes `vex_status` into index selection with new `draftStatus` /
`indexDraftStatus` options and re-applies a dropped range as a filter.
`assertUniqueAmongPublished` scopes unique fields to published rows; deleting a draft
cascades to its published parent; `backfillStatus` stamps legacy rows. Mutation hooks gain
the `"unpublish"` operation. `useAutosave` saves only real changes and resets the form after.

**Next / CLI.** `NextAdminPage` preloads with the same `drafts` args as the client queries;
the revalidate route treats `unpublish` as an update. `vex dev` no longer runs the automatic
version-status backfill.

**Bundle size.** All `fields/*/inputSchema.ts` and `fields/utils.ts` import Zod as
`import * as z from "zod"`, which tree-shakes: `@vexcms/core` 90 KB → 46 KB gzipped (P-027).

**Self-hosted Geist (www).** `apps/www` loads Geist / Geist Mono from the `geist` package's
variable woff2 files via `next/font/local` instead of `next/font/google`. Google Fonts
intermittently returns extensionless `/l/font?kit=…&skey=…` URLs that fail Turbopack builds
(vercel/next.js#99114), which broke the www Vercel deploy. Same CSS variables; weights 100–900.
`apps/test` and the create-vexcms templates still use `next/font/google`.

**Apps and docs.** `apps/test` now mirrors the www site with draft preview
(`getBySlugPreview`); www gains the same preview path. New "Versioning & Drafts" guide;
`core` README updated. Changesets added for versioning and the Zod import; pending
`unified-versions-api` / `use-fields-form` bumps corrected to `patch` for the alpha track.
Template sync for `apps/test` → `base-nextjs` not performed.

BREAKING CHANGE: `vex dev` no longer backfills `vex_status`; call `backfillStatus` from an
internal mutation. Versioned collection reads are published-only unless `drafts: true` is
passed by a caller with `readDrafts`.
