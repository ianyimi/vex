fix(next): commit the lockfile entry for the new vitest devDependencies

`packages/next/package.json` gained `vitest` and `@vitest/coverage-v8` when the
package got its first test suite, but no install followed, so `pnpm-lock.yaml`
never recorded them. Vercel installs with `--frozen-lockfile` and refused the
tree: `ERR_PNPM_OUTDATED_LOCKFILE`, `2 dependencies were added: vitest@catalog:,
@vitest/coverage-v8@catalog:`.

The drift was invisible locally because `.npmrc` sets `shamefully-hoist=true`.
`vitest` resolved from the hoisted root, so `@vexcms/next`'s tests ran and
typecheck, test, build, and lint all passed against a lockfile that could not
install from scratch. Regenerated with `pnpm install --lockfile-only` — six
added lines, confined to `packages/next` — and verified by installing a pristine
copy of tracked plus untracked-but-not-ignored files, with no `node_modules`,
under `--frozen-lockfile`. Also sorts that file's `devDependencies`
alphabetically, matching every sibling package.

**Close the gap that let it through.** Nothing in the commit checklist ran a
frozen-lockfile install, and `scripts/vercel-build-check.mjs` — written for
exactly this class of fault, after two deploys failed on faults invisible in a
working copy — was never a checklist item despite its own docstring saying to
run it before committing. Both are now "Must pass" entries, the first scoped to
"whenever any `package.json` changed", the second to "when `apps/www` or any
package it imports changed", with a note that a pristine tree has no
`.next/cache` so `next/font` needs network to fetch Geist and an offline failure
there is environmental rather than a code fault.
