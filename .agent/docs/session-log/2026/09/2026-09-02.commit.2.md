ci: give apps/test build the env it needs so the gate actually runs

WP-5 added `apps/test` to the build step so app-level breakage would be caught
before a publish. It never caught anything: `next build` loads `next.config.ts`,
which parses runtime env through `@t3-oss/env-nextjs`, and a CI runner has no
Convex deployment or auth secret. The step died at config load, before compiling
a single line — the exact failure now visible on PR #22.

`SKIP_ENV_VALIDATION=1` looks like the fix and is not sufficient. Measured: it
clears the config-load parse, then the build still fails at "Failed to collect
page data", because the Convex client needs a parseable URL during prerender.

Four placeholder values clear both phases and leave validation **enabled**, so a
newly added required env var that nobody wired up still fails the build — the
signal `SKIP_ENV_VALIDATION` would have masked. `apps/test` is the sandbox app
and is never published or deployed (it is in the `.changeset` ignore list), so
the inlined `NEXT_PUBLIC_*` placeholders reach no real artifact.

Applied identically to `release.yml` and `ci.yml`, scoped to the build step
rather than the job so nothing else inherits them.
