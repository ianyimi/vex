test(react): add exported component test kit and per-field contract suites

Builds `@vexcms/react`'s test suite as a reusable, exported kit rather than a set of
internal test files, and wires two apps up as its first consumers. All 16 task groups of
`2026-09-04-react-test-suite` (49/49 steps). Deliberately does NOT fix any product defect
it uncovered — that is the follow-up, and it is why the suite is red.

**Exported test kit (`@vexcms/react/testing`).** New subpath shipping plain functions whose
bodies call `describe`/`it` themselves, so a consumer imports and invokes them from their
own test file instead of the package shipping `.test.*` source. `runVexReactSuite` is the
one-call entry point; `runFieldInputContractSuite` asserts the 10-point behavioral contract
every field input owes (label association and name fallback, `admin.description`,
`admin.placeholder`, both independent readOnly sources, required reflection, empty/valid/
invalid value states, the full error-timing lifecycle, typed change/blur wiring,
`ADMIN_FIELDS` defaultValue seeding, and axe checks in three states);
`runNestedFieldContainerSuite` recurses that contract through `array`/`group`/`blocks` over
arbitrary child types; `runRbacStateSuite` renders any permission-gated component across
five access scenarios against the real `defineAccess`/`usePermission` resolution. Test
runtime deps (`vitest`, `@testing-library/*`, `vitest-axe`, `convex-test`) are peer-only and
optional, so no consumer of the `"."` entry is forced to install them.

**Per-field fixtures live with their field.** Each type owns
`components/fields/<type>/testFixture.ts` beside its own `Input.tsx`, and
`testing/fixtures/index.ts` is a pure aggregator — one import plus one registry entry per
type, no data of its own. `testing/fixtures/index.test.tsx` asserts the registry's keys
match `ADMIN_FIELDS`, so a forgotten entry fails loudly instead of silently skipping
coverage. All 12 types are registered and the suite runs 819 tests, up from 88.

**Convex-backed fields test against real query execution.** `testing/convex/bridge.ts`
adapts a `convex-test` instance to the `{ query(funcName, args) }` shape
`@convex-dev/react-query`'s `ConvexQueryClient` calls, so `relationship` resolves seeded
documents through a real `useQuery(convexQuery(...))` render in jsdom rather than a
hand-typed mock. `convexTest` is always called with an explicit `testModules` map —
`import.meta.glob` is a Vite build-time macro that stays literal inside convex-test's
prebuilt `dist`, matching the workaround `@vexcms/core`'s own suite already uses.

**One bundle graph for both entries (ADR-009).** `packages/react/tsup.config.ts` folds back
to a single config with `splitting: true`. Two tsup invocations cannot share a chunk, so
`.` and `./testing` each bundled their own `AppFormContext` `createContext` call and every
component a consumer mounted threw "must be rendered inside `<AppForm>`" — 26 of 27 tests
in `apps/www`. `"use client"` now stamps the test bundle too, which is inert in a vitest
process and strictly cheaper than two React contexts.

**Broke a real circular import between `fields` and `form`.** `FormArray`/`FormGroup`/
`FormBlocks` import `fieldToInputComponent` from `../fields` while every `fields/*/Input.tsx`
imported `createFieldInput` from the `../../form` barrel. Latent under separate bundles;
under shared chunks esbuild ordered it the other way, `fieldToInputComponent("text")`
returned `undefined`, and consumer suites collected zero tests. All 14 field files now
import leaf modules directly. Import paths only, no behavior change.

**`@vexcms/next/testing` re-exports the kit** so Next consumers import from one package
instead of mixing `@vexcms/next` and `@vexcms/react`. `apps/test` runs the full suite (711
tests) and `apps/www` a focused `includeCore: false` smoke (27), both through the published
subpath — which is the only place the dual-context class of defect above is observable.

**`scripts/record-test-findings.mjs` separates a discovered defect from a broken test.** It
exits 0 when tests ran, appending every failed assertion to the spec's `findings.md`, and
non-zero only when a file cannot collect or yields zero tests. Without it the `/implement`
verify gate halts on the first real bug found, twelve times over.

**Findings.** 353 failing assertions, root-caused in
`.agent/docs/specs/2026-09-04-react-test-suite/BUGS-REPORT.md`. Two causes dominate: six
field types render a `<label for>` bound to no control at all (193), and `required: true` is
unenforceable on seven of twelve types because their input schemas end in an unconditional
`.default(defaultValue)` never gated behind `!field.required` (40). `packages/core`'s 924
tests are unaffected.
