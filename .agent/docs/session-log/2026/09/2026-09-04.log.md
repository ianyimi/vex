## 2026-09-04 — 12:18 — fix(www): call convex deploy directly so the vercel build resolves a binary

**Spec:** .agent/docs/specs/2026-08-30-launch-readiness/spec.md (WP-6 prod deploy)

### What was built

Follow-up to `7200c67`, which shipped a Vercel `buildCommand` of
`pnpm vex:deploy && pnpm build`. That build failed on its first run, before reaching
Next.js:

```
> www@0.1.1-alpha.4 vex:deploy /vercel/path0/apps/www
> vex deploy
sh: line 1: vex: command not found
Error: Command "pnpm vex:deploy && pnpm build" exited with 1
```

- `apps/www/package.json` — `vex:deploy` (`vex deploy`) replaced with
  `deploy:convex` (`convex deploy`).
- `apps/www/vercel.json` — `buildCommand` now `pnpm deploy:convex && pnpm build`.
- `apps/www/README.md` — Deployment section and the script table updated, with a
  paragraph explaining why the richer command cannot be used in CI.
- `.agent/docs/decisions/ADR-008.md` — Decision and Consequences rewritten around
  `convex deploy`; the ADR shipped in `7200c67` documented the command that does not run.

### Decisions made

**`convex deploy` instead of making `vex deploy` work.** The developer's first read was
that `vex deploy` did not exist and needed writing, plus a changeset and a re-version of
`@vexcms/cli`. It does exist — `packages/cli/src/commands/deploy.ts`, wired at
`src/index.ts`'s `case "deploy"` — so none of that was needed. The failure is binary
resolution, not a missing command: `@vexcms/cli`'s `bin` is
`{ "vex": "./dist/index.js" }`, and `dist` is gitignored (`.gitignore:24` — `/**/dist`,
`git ls-files packages/cli/dist` returns 0). On a fresh CI clone the shim target does not
exist until the CLI is built, so pnpm links nothing usable. It works locally only because
the CLI has been built here.

Two fixes were available: build the CLI ahead of the app in CI, or call `convex deploy`.
The second was chosen, and it is what the developer asked for once the command was
confirmed to exist. `convex` is a *published* dependency of the app
(`convex@1.44.0`, `bin: { "convex": "bin/main.js" }`), so its binary exists the moment
`pnpm install` finishes — no build ordering to get wrong.

**Nothing is lost by dropping the codegen step**, which was the thing worth checking
before agreeing. `vex deploy` adds schema generation and auto-migration on top of
`convex deploy`, but all three generated artifacts are tracked
(`convex/vex.schema.ts`, `convex/schema.ts`, `src/vex.types.ts` — confirmed with
`git ls-files --error-unmatch`), so `convex deploy` ships exactly the schema `vex deploy`
would have produced. Schema freshness is already enforced at the commit by
`turbo typecheck`, which is a better place for it than the deploy.

**No changeset, and no re-version.** The fix touches only `apps/www` and one ADR;
`@vexcms/cli` and every other published package are untouched. The developer had
expected to version packages again for this — they do not need to.
