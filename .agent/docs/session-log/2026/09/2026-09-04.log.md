### Decisions made

**The prod RBAC "bug" was not an access-control bug.** `usable-bee-730` was running stale
function code, so `seed:init` executed a superseded `seed.ts` (hence "old text after
reseeding") and access control enforced a superseded `access.ts` — the pre-`9051c15` matrix
had `adminPanel: { access: false }` and no `pages` read grant, which is why the fresh Vercel
route admitted a caller the Convex queries then denied. Confirmed from
`git show 9e3622e:apps/www/src/auth/access.ts`, not from prod: the local Convex CLI is not
authorised for that project (`npx convex data --prod` resolves to `insightful-whale-68`, a
different and empty deployment) and `.env.prod` carries no deploy key. Diagnosis is therefore
code- and history-based, and is stated as such.

**A failing build is the correct behaviour when `CONVEX_DEPLOY_KEY` is absent.** The build
command was briefly reverted when the developer said they would handle the deploy manually,
then restored on their go-ahead. A committed `buildCommand` also overrides Vercel dashboard
config, so it is documented rather than silent.

**`reinit` reconciles; it does not merge.** Overwriting admin-panel edits to seeded fields is
the point. The one exception is `siteSettings`: `upsertGlobal` replaces the whole `data` blob
rather than merging field by field, so a bare patch would have dropped `adminTheme` and every
SEO field an editor had set. Existing values are carried forward under the seeded ones, with
`_`-prefixed keys and `slug` filtered out.

**The demo collections stay out of the project.** The developer's instruction ("put the
collection in the www project and give it to the vex.config, then review the vex.schema.ts
file") was read as the harvesting method, not as a request to keep them. Both `posts` and
`testimonials` were created, registered, harvested verbatim — including the `by_author` /
`by_company` indexes vex infers — and then reverted, so no unused table reaches prod. The
marketing claim stays literally true because the output came from a real generator run.

**"Signed in" excludes an anonymous demo session.** The logout button was already hidden with
no session; what was visible belonged to the anonymous session `AdminDemoButton` mints.
`session.user.isAnonymous` is the discriminator, and `anonymousClient()` already types it, so
the initial cast was removed once `tsc` proved it unnecessary.

**www's `future` bucket was preserved rather than flattened to match the docs.** It exists by
an earlier explicit developer request. The docs file gained a matching `## Future` section
instead; only the two genuine open-research items were reclassified to `exploring`.

### Problems hit

**Hoisting the seed payloads silently lost contextual typing.** As inline arguments to
`ctx.db.insert` the literals were checked against the generated table type; as standalone
consts, `variant: ["full"]` widened to `string[]` and stopped satisfying
`("full" | "compact")[]`. Annotating each with
`WithoutSystemFields<Doc<typeof TABLE_SLUG_*>>` restored it — caught by `tsc`, not by review.

**The `vex dev` watcher again rewrote generated files mid-session.** Registering the throwaway
`testimonials` collection regenerated `vex.schema.ts`, `vex.types.ts` and `convex/schema.ts`
and pushed the table to dev. Deleting the file does not self-heal them, so all three were
reverted explicitly and re-checked for residue. A convex file that is *not* a collection
config (the two throwaway cleanup mutations) does not trigger this.

**Verifying the third session state required creating a real account.** Signed-out and
anonymous states were observable, but "real account shows the button" was not. A throwaway
account was registered through `/api/auth/sign-up/email`, observed (`isAnonymous: false` →
button visible), then deleted along with its `session` and `account` rows via a temporary
mutation that was removed afterwards.

**Three anonymous demo user rows have accumulated in the dev deployment** from repeated
verification runs. Harmless, and they are what a public demo produces by design, but prod will
grow the same way.
