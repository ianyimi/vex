fix(react)!: make bulk selection reachable and the admin usable on phones

**Bulk selection is reachable, and gated on delete permission.** `DataTable`
mounted `BulkDeleteModal` but never rendered `DataTableBulkActions` — the only
call to `setDeleteModalOpen(true)` lived in a commented-out block — so ticking
rows did nothing, and `enableRowSelection` was hardcoded `true`, so a role that
cannot delete saw dead checkboxes. The bar is now rendered whenever an
`onBulkDelete` handler is supplied, and `CollectionListView` /
`MediaCollectionListView` drive `enableRowSelection` and `enableBulkActions`
from `canDelete`, so a read-only visitor sees no checkbox column at all. The
commented block had been written against an older prop shape; the component had
since been rewritten to consume a `useTableSelection` object that `DataTable`
never holds. Rather than adopt that hook (replacing the checkbox column, row-id
derivation, and every selection assertion in two suites), `DataTableBulkActions`
takes what `DataTable` already has — `selectedCount`, `onDelete`, `onClear`,
`isDeleting` — and the `all` / `inverse` badges, unreachable without a
select-all-across-pages control, are gone. `useTableSelection` is now
production-dead; spec I reintroduces it with that control. `dataTableSuite` and
`viewSuite` lose their absence-assertions and gain real ones: the bar renders,
deletes exactly the selected ids, clears, and never appears without a handler;
a role without `delete` gets no checkboxes and a role with it does. Two viewer
fixtures that asserted "the select column stays" — true only because selection
was unconditional — now hold `delete: true`, keeping the assertion's real intent
that read-field filtering leaves non-field columns alone.

**The admin no longer overflows at phone widths.** Audited every admin view at
375 / 390 / 768 / 1024. Three genuine overflows shared one cause: the header
action groups (`Revalidate · Save · Cancel` at 270px, `Revalidate all · + New
Theme` at 275px) are `shrink-0 whitespace-nowrap` and never wrapped, pushing the
layout viewport to 394px on a 375px screen. All five view headers gain
`flex-wrap gap-y-2`, and the edit headers' fixed `h-16` becomes `min-h-16` so a
wrapped second line is not clipped. `CreateDocumentModal` and `CreateMediaModal`
hardcoded `w-[50svw]` at every breakpoint — a 187px dialog with 115px inputs on a
phone — and are `w-full` below `sm`, the create form also `h-[80svh]` there since
its field region scrolls. The new bulk bar is `max-w-[calc(100vw-2rem)]` with
`flex-wrap` so it cannot overflow either. The 768 sidebar flip, the mobile
Sheet, the media picker, and both `www` routes were clean; the roadmap tab
strip scrolled correctly but showed no scrollbar, so `Roadmap/index.tsx` adds
`<ScrollBar orientation="horizontal" />`. Audit matrices live under the spec's
`audit/`; a 16px-tall title-link touch target is filed to the backlog for spec G.

**The auto-migration stubs leave the public API.** `diffSchema`,
`planMigration`, `makeFieldsOptional` and `addRemovedFieldsAsOptional` were
exported from `@vexcms/core` and stubbed: `diffSchema` returned an empty diff for
every input, so any caller silently migrated nothing. They move to a new
`@vexcms/core/internal` subpath — sibling packages only, no stability guarantee
— because `cli/src/lib/generateSchema.ts` carries a complete orchestration built
on them that would be wrong to delete. `schema.autoMigrate: true` now throws at
`defineConfig` instead of no-opping; `autoMigrate` was never declared on
`SchemaConfigInput`, only claimed by its JSDoc, and the CLI reads it under
`@ts-nocheck`. That JSDoc and `TypesConfigInput`'s (which stated the wrong
default path) are corrected, and `core/README.md` drops its Auto-Migration
section.

**Root README shows the product and the step that was missing.** The admin
panel preview (`.github/assets/preview.png`) replaces the WP-6 TODO directly
under the alpha warning. Quick Start gains the `npx convex env set SITE_URL` /
`BETTER_AUTH_SECRET` step between `convex dev` and `pnpm dev` — Better Auth runs
inside Convex and never reads `.env.local`, and skipping it is the documented
cause of a 403 on first sign-in. It was in the scaffold README and the docs
quickstart, but not where a new user starts. The false "sortable" / "searchable"
data-table claims and the CLI "migrations" claim are gone, and
`@vexcms/richtext-plate` is described as built-but-unwired rather than shipped.
