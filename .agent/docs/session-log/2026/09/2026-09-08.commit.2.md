feat(react)!: ship the exported test kit and fix every defect it found

Two specs land together: `2026-09-08-react-coverage-expansion` built the suite and recorded
what it found without fixing anything, then `2026-09-08-react-bug-fixes` cleared all 18
recorded defects. Splitting them would leave a commit whose own tests are red on purpose.

**Exported test kit.** `@vexcms/react/testing` — re-exported wholesale as the new
`@vexcms/next/testing` subpath — now ships `runVexReactSuite`, one call that runs the entire
admin contract against a consumer's own build, plus the factories behind it:
`runFieldCellContractSuite`, `runColumnDefSuite`, `runShellSuite`, `runViewSuite`,
`runDataTableSuite`, `runModalSuite`, `runMediaSuite` and `runHooksSuite`. A `sections` option
selects categories, `custom` drives project-authored field fixtures through the same contract,
and `access` threads a real `VexAccessConfig` so RBAC-gated paths render under the consumer's
own matrix. `apps/test` deliberately omits `sections` so it runs everything and picks up future
sections automatically; `apps/www` keeps a fast `["shell"]` subset. Statement coverage on
first-party `packages/react` code went from 58.2% to 91.62%, gated in `vitest.config.ts` at a
fixed 80% for statements plus measured floors for the rest.

**List-view cells.** Every type renders the em-dash placeholder for a `null`/`undefined` value
instead of crashing — `text` and `array` threw a `TypeError` on `.length`, and a throw in a cell
renderer takes down the whole table render. A `date` cell holding epoch `0` now renders
1970-01-01 rather than treating a real timestamp as an absent value. All 12 types honor
`isTitleField` by wrapping their content in an edit link, so a `date` or `select` title column is
finally clickable; `relationship` and `upload` wrap every return path, loading states included.
Values longer than 77 characters truncate with the full text on `title`, which `relationship`,
`select`, `array`, `blocks`, `upload` and `group` previously left unreachable by tooltip.

**Selection and pagination hooks.** `useTableSelection`'s `"all"` mode reads `selectedIds` as an
exclusion set, so "select all, then untick one" genuinely deselects that row instead of
reporting it as selected — which would have deleted an excluded row once bulk-delete returns.
`toggleRow`'s `onSelectionChange` reports the post-change `mode` rather than a stale closure
value. `usePaginatedQuery.loadMore()` reveals one page per call instead of fetching page N and
exposing it only on the next call, and `isDone` derives from the query's own
`isLoading`/`isError`, so a pending or rejected first page is no longer indistinguishable from a
complete empty collection.

**Modals.** `Modal` gains a `dismissible` prop that cancels Base UI's own close handling, gating
Escape, backdrop clicks and every `DialogClose` centrally instead of per trigger.
`CreateDocumentModal` pairs it with a synchronous in-flight flag set before TanStack Form's async
validation resolves: a rapid double-click creates one document instead of two, and Escape
mid-submit no longer closes the dialog while the write still lands.

**Views and media.** `MediaCollectionEditView`'s Save/Cancel now read `!canEdit ||
isDefaultValue`, and `MediaCollectionListView` resolves a create-action permission for its Upload
button — both matching their non-media counterparts. `MediaUploadDropzone` filters dropped files
against a safe-media MIME allowlist (it previously accepted executables) and keeps the first file
of a multi-file drop instead of rejecting the batch. `FilePreview` falls back to the filename
when `alt` is empty; the old `??` never fired, since `alt` is a required `string` that is `""`
when unset, so every image without alt text rendered `alt=""`.

**Rules of Hooks and storage robustness**, found while hardening the suite rather than by a
finding. `ThemeProvider` reads and writes `localStorage` through guarded helpers — the unguarded
access threw inside the mount effect and unmounted the whole admin shell wherever Web Storage is
unavailable, including Safari private mode and "block all cookies". `upload`'s cell calls
`useQuery` unconditionally with `get`'s own `skip` sentinel instead of after an early return, and
`MediaUploadForm` owns its accordion state in a real `StagedFilesEditor` component instead of
inside a render prop; both made React log "Rendered fewer hooks than expected" and abandon
concurrent rendering. `FormArray`/`FormBlocks` pass `isDragDisabled` when read-only, so a
read-only list stops registering drag handles it never renders.

**Dead code removed.** `usePagination` and `DataTablePagination` had zero production consumers —
both list views paginate with `usePaginatedQuery` + `onLoadMore`, and no view ever rendered
page-number pagination. Deleted with their tests rather than fixing defects in unreachable code.

**Test output is silent again.** `apps/test` and `apps/www` could not run at all: their
`coverage.reporter` listed `"default"`, a *test* reporter, so istanbul threw
`Cannot find module 'default'` before a single test executed. Beyond that, `expectNoA11yViolations`
runs axe inside `act`, the dropzone's negative paths wrap their settle window, and the
double-submit test awaits the dialog's close — a real assertion, since closing is the last thing
the create's success path does. 13 stale `// FAILS:` comments became regression-guard notes now
that those assertions pass. `scripts/vercel-build-check.mjs` skips tracked files deleted in the
working tree instead of crashing on them, so the pristine-clone check runs on a tree with
deletions.

**`@vexcms/core`'s own diagnostics no longer leak to stderr.** Its suite printed eight
`[vexcms]` dev warnings per run. Two of the three causes were tests that deliberately trigger
a diagnostic — the access-index collision in `find/server.test.ts` and the two "dev warning
only" degenerate configs in `access/config.test.ts` — but let it print instead of following
the `vi.spyOn(console, "warn")` convention the same file's own "dev-mode warnings" block
already uses; they now spy and assert the message, so the diagnostic is a tested contract
rather than output. The third was a real test smell: `publishedSlugs/server.test.ts` passed
`access: { bypass: true }` on four calls that thread no config, and `resolveAccessCall` was
correctly reporting that the flag changed nothing. Dropped, with a note on why the sitemap
JSDoc's advice does not apply to a config-less call. Every other package — better-auth,
file-storage-convex, cli, create-vexcms, next, and both apps — was already silent.

**Released as `0.1.0-alpha.14`.** One consolidated changeset covered this landing plus the two
commits that shipped without one — `fix(fields)` (10d3809) and `test(react)` (60646d3) — and
`pnpm version:packages` has consumed it: `@vexcms/core`, `@vexcms/react` and `@vexcms/next`
carry the minor bump, every package's CHANGELOG gained the entry, and `create-vexcms`'s
template pins were synced to the new range.

BREAKING CHANGE: `defineCollection` now singularizes a collection's `slug` before title-casing
it for the default `labels.singular`, and derives `labels.plural` as the title-cased slug
itself instead of running it through `plural()` again. For slug `posts`, `singular` was `Posts`
and is now `Post`; `plural` was `Postses` and is now `Posts`. Irregular-suffix slugs were hit
the same way — `categories` was `Categorieses`, `media` was `Medias`. Set `labels` explicitly to
pin the old values. Separately, `usePagination`, `UsePaginationProps`, `UsePaginationReturn`,
`DataTablePagination` and `DataTablePaginationProps` are no longer exported from
`@vexcms/react`; use `usePaginatedQuery` for cursor pagination.
