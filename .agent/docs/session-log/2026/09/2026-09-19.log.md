### Decisions made
- Collection hook properties (`beforeChange` etc.) are declared **generic-per-call over
  `TDataModel`**, not fixed to the interface's own type params — this is what lets a
  dispatch call site (`collection.hooks.beforeChange({ ctx: realCtx, ... })`) infer
  `TDataModel` fresh and avoid a cast on `ctx`, mirroring why `validateFields` is generic.
  A hand-typed hook with an *explicit* `BeforeChangeProps<"posts">` annotation (not
  contextual inference) is the one authoring style this breaks — verified with a scratch
  compile against real Convex types, not guessed.
- `min`/`max` on `array`/`blocks`/`upload`/`relationship` skip validation ONLY when the
  value is an empty array AND the field is not required. Required fields' `min`/`max` still
  run on `[]` too, so a required field's custom message stays reachable (otherwise an empty
  array — the only way to violate `min` — would always report the generic "This field is
  required." instead).
- `relationship`'s pre-existing `required` semantics are unusual by design (CORE-1: a
  required relationship can still be an empty array — a document may legitimately have zero
  relations) — a `min`/`max` config was NOT literally forwarded to `arrayFieldToInputSchema`
  (would have imported array's stricter required-implies-non-empty behavior); the pattern
  was reused, adapted to relationship's own semantics, and the resulting edge case (min
  still bypasses on `[]` unless a `min` is explicitly configured) is documented and tested.
- Sonner replaces the initial Base UI `Toast` implementation entirely (user's call after
  reviewing the built UI) — `vexToastManager`/Base UI's `toast.tsx` deleted outright rather
  than left as a second path.

### Decisions made
- **`react-resizable-panels` 3.0.6, not the spec's `^2.1.0` or npm-latest 4.12.4.** v4 is an
  API rewrite (`Group`/`Separator`, no `autoSaveId`) that the shadcn Resizable the spec
  specifies does not target; 3.0.6 keeps `PanelGroup`/`Panel`/`PanelResizeHandle` and
  supports React 19. Catalog pins exact per repo convention.
- **`admin.livePreview.url` uses method syntax, not a property-position function type.**
  A property-position `LivePreviewUrlResolver<TDoc>` makes `TDoc` strictly contravariant, so
  a `CollectionConfig<…, TSlug>` with a still-generic slug stopped being assignable to the
  concrete union the admin views hold (`useCollectionForm`/`useGlobalForm` broke). Method
  syntax restores bivariance. Two matching boundary casts in `collections/config.ts` and
  `globals/config.ts` bridge the Input side's conditional slug to the resolved side's.
- **The preview gate moved from a request header to a session-verified marker cookie, read
  client-side — developer-approved deviation from Design Decisions 14/15.** `headers()` in
  the site layout opted every public route out of static generation, breaking
  `verify-scaffold`'s `/ is prerendered` assertion and undoing the SEO spec's prerendering.
  `proxy.ts` still verifies the session on `?vexLivePreview=1`, but now sets
  `vex-live-preview=1` (`LIVE_PREVIEW_COOKIE`, 1h, non-HttpOnly, carries no secret);
  `LivePreviewProvider` enables only when both the param and that cookie are present, read
  in an effect. `LIVE_PREVIEW_HEADER` deleted.
- **`NextLivePreviewProvider` deleted with it.** With no header read it had no job, and the
  config cannot cross the RSC boundary as a prop (ADR-013 — `livePreview.url` and field
  validators are functions; React refused to serialize them, failing the `/features`
  prerender). Both the app and the template now mount a local `"use client"`
  `SiteLivePreviewProvider` that imports `~/vex.config` directly, mirroring the admin's
  existing `clientProviders.tsx`.
- Spec-tasks.md was regenerated from spec.md before starting: its step titles named symbols
  a later spec revision renamed (`VexLivePreviewContext`, `useVexPreview`), and its

  shell-clean command).
