### Decisions made
- Collection hook properties (`beforeChange` etc.) are declared **generic-per-call over
  `TDataModel`**, not fixed to the interface's own type params — this is what lets a
  dispatch call site (`collection.hooks.beforeChange({ ctx: realCtx, ... })`) infer
  `TDataModel` fresh and avoid a cast on `ctx`, mirroring why `validateFields` is generic.
  A hand-typed hook with an *explicit* `BeforeChangeProps<"posts">` annotation (not
  contextual inference) is the one authoring style this breaks — verified with a scratch
  compile against real Convex types, not guessed.
- `min`/`max` on `array`/`blocks`/`upload`/`relationship` skip validation ONLY when the
  value is an empty array AND the field is not required. Required fields' `min`/`max` still
  run on `[]` too, so a required field's custom message stays reachable (otherwise an empty
  array — the only way to violate `min` — would always report the generic "This field is
  required." instead).
- `relationship`'s pre-existing `required` semantics are unusual by design (CORE-1: a
  required relationship can still be an empty array — a document may legitimately have zero
  relations) — a `min`/`max` config was NOT literally forwarded to `arrayFieldToInputSchema`
  (would have imported array's stricter required-implies-non-empty behavior); the pattern
  was reused, adapted to relationship's own semantics, and the resulting edge case (min
  still bypasses on `[]` unless a `min` is explicitly configured) is documented and tested.
- Sonner replaces the initial Base UI `Toast` implementation entirely (user's call after
  reviewing the built UI) — `vexToastManager`/Base UI's `toast.tsx` deleted outright rather
  than left as a second path.
