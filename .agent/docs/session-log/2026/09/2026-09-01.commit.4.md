fix(react): controlled upload accordion, DragHandle without Draggable

Completes the admin-UI bug round begun in b8dbb1a ("fix(create): theme
wiring, upload collection scoping, nested-build fixes") — the sibling
fixes from the same round (`AccordionTrigger`'s postIconChildren
restructure for the nested-`<button>` hydration error, `FormBlocks`'
controlled accordion, the template's env-derived `images.remotePatterns`,
docs) were swept into that commit mid-flight; this remainder ships as one
unit per P-016.

**MediaUploadForm's staged-files accordion is controlled.** It recomputed
an uncontrolled `defaultValue` from live file state on every render, so
Base UI's Accordion warned "changing the default value state of an
uncontrolled Accordion after being initialized" whenever files were
appended after mount (multi-select "Add more", a second drag-drop). The
open-state now lives in `useState` inside the TanStack `form.Field`
render-prop callback — called unconditionally before the empty-state early
return so hook order stays stable with zero staged files — and a
tracked-ids comparison during render auto-opens newly staged file ids
while the user's manual toggles persist.

**DragHandle no longer requires a Draggable ancestor.** It called the
throwing `useDraggableInstanceContext` hook, so rows rendered outside a
`Draggable` wrapper — `FilledInput`'s single-value (non-`hasMany`) upload
rows, which mount a `DragHandle` purely for layout alignment — crashed
globals pages with "useDraggableInstanceContext must be called from within
a Draggable component". It now reads `DraggableInstanceContext` nullably
via `useContext` and degrades to the same static/inert render already used
when DnD isn't mounted or the handle is disabled; this also removes the
conditional hook call the old early return hid.

**Tests pin all three contracts.** `accordion.test.tsx` asserts
postIconChildren never nest a `<button>` inside the trigger button;
`MediaUploadForm.test.tsx` covers the staged-files accordion mounting and
the append-after-mount path; `DragHandle.test.tsx` covers the
no-`Draggable` inert render (single row and a whole mapped list) plus the
positive path resolving real drag-handle props through
`Droppable`/`Draggable`.

A new `admin-accordion-draghandle-fixes` changeset (react patch) documents
both fixes for the next version pass. The sibling session had extended
`media-and-scaffold-fixes` instead, but that changeset was already
consumed into alpha.5 (recorded in `.changeset/pre.json`), so notes added
there would never reach a CHANGELOG — the extension moved into the new
file and the consumed changeset is restored to HEAD. `MediaUploadForm`'s
JSDoc also gains the `@returns` line `jsdoc/require-returns` demands (a
lint error that pre-existed at HEAD, surfaced by this run's commit gate).
Session log and ledger ride along.
