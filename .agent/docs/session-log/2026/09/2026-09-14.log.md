### Decisions made
- **Access validation moved from `defineConfig` to `defineServerConfig`** (spec put it in `defineConfig`). Reason: bootstrap deadlock — on a clean checkout `vex.auth.ts` is an empty placeholder, so the client config has no auth collections and `access` rules naming `user.by_email` throw before the CLI can ever evaluate the adapter that produces them. Server-side validation also turns a bad matrix into a `vex dev`/`next build` error instead of a browser white screen. Purity of `defineConfig` unaffected.
- **`VEX_CLI_BOOTSTRAP=1`** (read by `defineServerConfig` via a `typeof process` guard) skips the drift check + access validation for the CLI's first import only, so `vex generate` can repair a drifted artifact instead of deadlocking on it. Outside the CLI the drift check is strict: an empty or stale artifact throws `VexAuthConfigError` ("Run `vex generate`").
- **Hash is pure JS, not `node:crypto`.** `defineServerConfig` runs inside the Convex runtime (`convex/vex.ts` imports `~/vex.config.server`) and core is ESM-only (`require` unavailable) — the spec's `require("node:crypto")` would fail in both. Functions/`undefined` are skipped like `JSON.stringify` so the live adapter hashes equal to its data-only emission.
- Generated artifact uses `as unknown as AuthCollectionConfig[]`: `defineCollection` stamps `meta.collectionSlug` on every field, which `AuthFieldMeta` does not declare, so a direct annotation fails typecheck.
- Testing kit keeps `access` as sugar on `renderWithVexProviders` (spec said replace with `config`) — identical single-provider behaviour, ~25 call sites untouched.
- Non-null `collection!.slug` from the subagent replaced with arrow functions that keep the guard's narrowing.
