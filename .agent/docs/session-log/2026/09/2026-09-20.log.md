### What was built

- **Split-pane floors, final shape.** Per-column pixel minimums converted to a share of
  the measured split: 560px form / 720px preview, capped at 35% / 50%. Caps exist because
  the floor applies to BOTH columns — two floors summing past 100 leave no travel, which
  is literally the "handle is stuck" bug from earlier in the session. Below ~1440px the
  caps govern (35/50, fifteen points of travel); a 2560px split derives 22/28.
- **Floors measure the split, not the viewport.** `useLivePreviewPanelMinSize` observes a
  wrapper around the panel group with a `ResizeObserver`. The sidebar is ~256px of the
  window but none of the split, so a viewport-derived floor was wrong whenever it was
  open, and toggling it changed the geometry without firing a window event.
- **Scroll position survives the preview toggle** (`usePreservedScrollTop`). The two modes
  scroll different elements, so opening the preview mounted a fresh scroller at 0 and the
  form jumped to the top. One shared ref restores the offset on attach, with a single
  `requestAnimationFrame` retry for the case where the new column's layout has not settled
  and the assignment gets clamped.
- **Admin shell owns its scrollbar.** `SidebarProvider`'s wrapper went `min-h-svh` →
  `h-svh overflow-hidden`, `SidebarInset` gained `min-h-0 overflow-hidden`, and `main`
  became the single `overflow-y-auto` scroller. Consequences handled: the three
  `sticky top-12` view headers became `sticky top-0`, and the edit views always render a
  `shrink-0` toolbar above a scrolling region, so the scrollbar never changes owner and
  the toolbar buttons stop shifting when the preview opens.
- **Edge treatment.** Toolbars bleed `-mx-6 px-6` so their border spans the pane; the
  split bleeds `-mr-6` (on the measuring wrapper) so the preview reaches the shell edge;
  the non-split form scroller bleeds and re-pads so its scrollbar rides the outer edge
  instead of pressing against the inputs; the resize handle is a 1px rule with the grab
  zone supplied by `hitAreaMargins`, not CSS.
- **`.vex-scroll-area`** in `@vexcms/react`'s stylesheet — transparent track, permanently
  visible semi-transparent thumb — applied to the admin scrollers and mirrored onto
  `apps/www` + the marketing template's document scroller.
- **Tokyo Night** token colours for code panes over the unchanged Stark Ember surface,
  and `highlightPageBlocks` / `CodeHighlightContext` / `highlightClient` moving shiki out
  of the client tree (see the 09-19 entry for why that was load-bearing).
- **Pop-out removed** along with its downstream dead code, after the developer deleted the
  button as redundant next to the header's preview link.

### Decisions made

- **`LivePreviewBreakpoint.icon` stays.** The earlier plan was to delete it with the
  DevTools-style ruler; the developer's panel edit passes it to the breakpoint `Button`,
  so it has a live consumer again and the follow-up is void.
- **The DevTools breakpoint ruler is not being ported.** `MediaQueryInspector.ts` is a
  `UI.Widget` bound to `SDK.CSSModel`, `Bindings.CSSWorkspaceBinding`, `i18n` and Lit, and
  it renders one row per media query discovered in the page's stylesheets, positioned in
  page pixels scaled by the emulation scale. Neither liftable nor a fit for a fixed list
  of presets. Reverted to the simple button row; recreating it is a design exercise, and
  the honest prerequisite is a surface an agent can drive headlessly (the admin is
  session-gated), not another blind iteration.
- **Pop-out removal is safe because the link never used `postMessage` anyway.** A
  `target="_blank" rel="noreferrer"` tab has no `window.opener`; it is served by
  `BroadcastChannel` plus the mount handshake — exactly the gap Design Decision 4 added
  the second transport for. Verified headlessly earlier: a plain tab with no opener
  received a broadcast and applied it.

### Problems hit

- **`react-resizable-panels`' inline styles defeated two Tailwind fixes.** `PanelGroup`
  pins `width: 100%` inline, so `-mr-6` shrank its margin box without widening it (the
  preview never reached the edge); `Panel` sets `overflow: hidden`, so a `-ml-2` meant to
  bridge the handle was clipped (pane borders never met the divider). Both are now solved
  structurally — the bleed lives on a plain wrapper div, and the handle is 1px so the rule
  IS the boundary.
- **The handle's grab area was cosmetic.** The library hit-tests `getBoundingClientRect()`
  plus `hitAreaMargins`, so the `before:` pseudo-element added for grabbing widened
  nothing it could see.
- **Two more eval-shell file-edit incidents**, both self-inflicted: a Python rewrite
  re-introduced IPython `!`-mangling (`__omp_shell(...)`) into `LivePreviewPanel`, after an
  earlier `open(path,"w")` truncated both edit views to zero bytes. Reconstructed from
  `git show HEAD` plus a prior read; the developer called it out and file edits now go
  through the Write/Edit tools only.
- **`pnpm typecheck` was not in my verification loop.** The package's build tsconfig
  excludes tests while `tsconfig.check.json` includes them, so two stale
  `breakpoints={[]}` props in `LivePreviewContext.test.tsx` survived green `build`, `test`
  and `lint` runs. Fixed; `pnpm -r typecheck` is now part of the loop.

### Where I left off

Live preview is feature-complete and verified end to end. Spec `2026-09-18-live-preview`
has Steps 1–5, 7, 8 marked done; **Step 6 is `Verify: manual`** and remains the only open
