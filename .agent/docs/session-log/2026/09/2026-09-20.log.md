### What was built

- **Split-pane floors, final shape.** Per-column pixel minimums converted to a share of
  the measured split: 560px form / 720px preview, capped at 35% / 50%. Caps exist because
  the floor applies to BOTH columns — two floors summing past 100 leave no travel, which
  is literally the "handle is stuck" bug from earlier in the session. Below ~1440px the
  caps govern (35/50, fifteen points of travel); a 2560px split derives 22/28.
- **Floors measure the split, not the viewport.** `useLivePreviewPanelMinSize` observes a
  wrapper around the panel group with a `ResizeObserver`. The sidebar is ~256px of the
  window but none of the split, so a viewport-derived floor was wrong whenever it was
  open, and toggling it changed the geometry without firing a window event.
- **Scroll position survives the preview toggle** (`usePreservedScrollTop`). The two modes
  scroll different elements, so opening the preview mounted a fresh scroller at 0 and the
  form jumped to the top. One shared ref restores the offset on attach, with a single
  `requestAnimationFrame` retry for the case where the new column's layout has not settled
  and the assignment gets clamped.
- **Admin shell owns its scrollbar.** `SidebarProvider`'s wrapper went `min-h-svh` →
  `h-svh overflow-hidden`, `SidebarInset` gained `min-h-0 overflow-hidden`, and `main`
  became the single `overflow-y-auto` scroller. Consequences handled: the three
  `sticky top-12` view headers became `sticky top-0`, and the edit views always render a
  `shrink-0` toolbar above a scrolling region, so the scrollbar never changes owner and
  the toolbar buttons stop shifting when the preview opens.
- **Edge treatment.** Toolbars bleed `-mx-6 px-6` so their border spans the pane; the
  split bleeds `-mr-6` (on the measuring wrapper) so the preview reaches the shell edge;
  the non-split form scroller bleeds and re-pads so its scrollbar rides the outer edge
  instead of pressing against the inputs; the resize handle is a 1px rule with the grab
  zone supplied by `hitAreaMargins`, not CSS.
- **`.vex-scroll-area`** in `@vexcms/react`'s stylesheet — transparent track, permanently
  visible semi-transparent thumb — applied to the admin scrollers and mirrored onto
  `apps/www` + the marketing template's document scroller.
- **Tokyo Night** token colours for code panes over the unchanged Stark Ember surface,
  and `highlightPageBlocks` / `CodeHighlightContext` / `highlightClient` moving shiki out
  of the client tree (see the 09-19 entry for why that was load-bearing).
- **Pop-out removed** along with its downstream dead code, after the developer deleted the
  button as redundant next to the header's preview link.

### Decisions made

- **`LivePreviewBreakpoint.icon` stays.** The earlier plan was to delete it with the
  DevTools-style ruler; the developer's panel edit passes it to the breakpoint `Button`,
  so it has a live consumer again and the follow-up is void.
- **The DevTools breakpoint ruler is not being ported.** `MediaQueryInspector.ts` is a
  `UI.Widget` bound to `SDK.CSSModel`, `Bindings.CSSWorkspaceBinding`, `i18n` and Lit, and
  it renders one row per media query discovered in the page's stylesheets, positioned in
  page pixels scaled by the emulation scale. Neither liftable nor a fit for a fixed list
  of presets. Reverted to the simple button row; recreating it is a design exercise, and
  the honest prerequisite is a surface an agent can drive headlessly (the admin is
  session-gated), not another blind iteration.
- **Pop-out removal is safe because the link never used `postMessage` anyway.** A
  `target="_blank" rel="noreferrer"` tab has no `window.opener`; it is served by
  `BroadcastChannel` plus the mount handshake — exactly the gap Design Decision 4 added
  the second transport for. Verified headlessly earlier: a plain tab with no opener
  received a broadcast and applied it.

### Problems hit

- **`react-resizable-panels`' inline styles defeated two Tailwind fixes.** `PanelGroup`
  pins `width: 100%` inline, so `-mr-6` shrank its margin box without widening it (the
  preview never reached the edge); `Panel` sets `overflow: hidden`, so a `-ml-2` meant to
  bridge the handle was clipped (pane borders never met the divider). Both are now solved
  structurally — the bleed lives on a plain wrapper div, and the handle is 1px so the rule
  IS the boundary.
- **The handle's grab area was cosmetic.** The library hit-tests `getBoundingClientRect()`
  plus `hitAreaMargins`, so the `before:` pseudo-element added for grabbing widened
  nothing it could see.
- **Two more eval-shell file-edit incidents**, both self-inflicted: a Python rewrite
  re-introduced IPython `!`-mangling (`__omp_shell(...)`) into `LivePreviewPanel`, after an
  earlier `open(path,"w")` truncated both edit views to zero bytes. Reconstructed from
  `git show HEAD` plus a prior read; the developer called it out and file edits now go
  through the Write/Edit tools only.
- **`pnpm typecheck` was not in my verification loop.** The package's build tsconfig
  excludes tests while `tsconfig.check.json` includes them, so two stale
  `breakpoints={[]}` props in `LivePreviewContext.test.tsx` survived green `build`, `test`
  and `lint` runs. Fixed; `pnpm -r typecheck` is now part of the loop.

### What was built
- `apps/www/next.config.ts` and `apps/test/next.config.ts` gained `workspaceSourceAliases()`,
  feeding `turbopack.resolveAlias`. It derives the map from each package's own
  `exports.*.source` condition instead of hardcoding paths, so a new subpath export needs no
  edit here, and it skips string exports with no `source` (`@vexcms/react/styles` is a CSS
  file). 17 specifiers across `core`, `react`, `next`, `better-auth`, and
  `file-storage-convex`; every target verified to exist.
- Gated on `NODE_ENV !== "production"`, so production builds keep resolving `dist` and what
  ships is exactly what the published packages contain.
- `packages/react/src/index.ts` and `src/testing/index.ts` now open with `"use client"`, and
  `packages/react/tsup.config.ts` drops the `banner` that used to inject it. Changeset:
  `.changeset/react-source-use-client-directive.md`.
- Two formatting-only edits the developer made in the same tree rode along:
  `LivePreviewPanel.tsx` (unwrapped a redundant flex `div` around the preview link) and
  `CollectionEditView.tsx` (re-indented the split-pane block under the wrapper added with
  `useLivePreviewPanelMinSize`).

### Decisions made
- **The `"use client"` boundary belongs in the source barrel, not only in the bundle.** The
  worry going in was a per-module directive audit across ~90 files; marking the barrel
  reproduces the banner's semantics exactly, because everything reachable from a client
  entry joins the client graph. Verified with an isolated build: without the tsup banner,
  `dist/index.js` and `dist/testing/index.js` each still start with exactly one
  `"use client";` — esbuild preserves an entry's directive prologue — and keeping both
  emitted it twice.
- **Dev-only, via `resolveAlias` rather than `transpilePackages`.** The alias bypasses
  `node_modules` outright, so `transpilePackages` buys nothing; adding it would be cargo
  cult. Gating on `NODE_ENV` keeps the published-bundle path under test in CI and on Vercel.
- **Templates deliberately NOT synced.** `templates/*/next.config.ts` is flagged CHANGED by
  `scripts/template-diff.mjs`, and stays that way: a scaffolded project has no `packages/`
  directory, so these aliases are meaningless there and would break resolution. Everything
  else `template-diff` reports is pre-existing drift untouched by this commit.

### Problems hit
- **`turbopack.resolveAlias` values are relative to the APP directory, not `turbopack.root`.**
  The comment on `apps/test`'s existing nuqs aliases claims the latter, and following it
  produced an alias that silently resolved to nothing: the first restart changed nothing
  because the package quietly fell back to `node_modules` → `dist`. Absolute paths are
  rejected outright ("server relative imports are not implemented yet" — Turbopack prefixes
  `./`). Diagnosed from `page_client-reference-manifest.js`, which listed
  `packages/react/dist/index.js` before the fix and `packages/react/src/index.ts` after,
  using a build with the production gate temporarily lifted as the test harness. Paths are
  now computed with `relative(appDir, absoluteSource)`.
- **Latent bug left in place:** by the same evidence, `apps/test`'s nuqs dedupe aliases
  (`apps/test/node_modules/nuqs/dist/index.js`, workspace-relative) are inert. Their comment
  says they exist to stop `useQueryState` losing `NuqsAdapter`'s context. Either the problem
  is gone or it is still there unnoticed; correcting them changes runtime behavior, so it
  wants its own verification rather than a drive-by fix.
- The original symptom — `tsup --watch` silently dropping filesystem events for
  `packages/react/src/components/livePreview/**` while sibling directories fired — is
  sidestepped rather than fixed. tsup still builds `dist` for consumers outside Next (the
  Convex bundler, published packages); it is simply no longer in the dev feedback loop.

### What was built

- **`useLivePreviewDocumentQuery`** (`packages/react/src/context/LivePreviewContext.tsx`,
  exported with `LivePreviewDocumentQueryResult`). Editing `headers` while previewing `/`
  changed nothing: `SiteHeader` read its document through a bare `useQuery`, and the
  overlay only reaches documents a consumer hands it. The existing `useLivePreviewQuery`
  sugar assumes a `getBySlug`-style array, so a singleton read had no wrapper at all. The
  new hook takes a query that already resolves to ONE document and collapses `null` into
  `undefined` so consumers have a single "nothing to render" case. `TData` is inferred
  rather than pinned — a `getFirst` read is typed `Doc | null` and a lookup by id often
  just `Doc`, and fixing the parameter to either makes the other unassignable.
- **`admin.livePreview.url` accepts a literal path.** `apps/www`'s `headers` collection is
  `url: "/"` rather than `url: () => "/"`. `LivePreviewUrlResolver` is now declared as a
  method-syntax member read back through an index access, which is what keeps `TDoc`
  bivariant.
- **The selected breakpoint survives the panel closing** — persisted per slug under
  `vex-live-preview-breakpoint:<slug>`, with `resolveStoredLivePreviewBreakpoint` exported
  for its three unit tests. The panel unmounts every time the editor hides the preview, so
  the selection previously reset to full width on every toggle.
- **The split re-measures when the preview is opened.** `useLivePreviewPanelMinSize`
  returned a `RefObject` and measured in a mount-only effect, so a split that mounts later
  — which is every open of the preview — kept the default floors. It returns a callback
  ref now and keys the `ResizeObserver` effect on the measured element; new
  `useLivePreviewPanelMinSize.test.tsx` covers open-after-mount and close-then-reopen.
- **Admin chrome.** `AdminTopNav` breadcrumbs render the collection's `admin.icon` beside
  the label; `AdminLayout` moves `ViewSiteButton` next to the breadcrumbs (`mr-2`/`ml-2`)
  instead of pushing it to the opposite edge with `ml-auto`.
- **Mirrored into `templates/marketing-site`:** `SiteHeader`, `SiteFooter` (by that
  session) and `collections/headers.ts`'s `livePreview` block (by this `/commit` run — the
  template had the hook wiring without the config that gives the header a preview panel).
- **Docs:** `packages/core/README.md` and `guides/live-preview.mdx` now describe the
  string form of `url` and the single-document hook; the guide's old advice to "compose
  the primitives" for a singleton query is replaced.

### Decisions made

- **The resolver type goes back to the bivariance hack.** Widening `url` to
  `string | LivePreviewUrlResolver` reintroduced the Step 1 variance failure: a function
  type in property position is strictly contravariant, so a `CollectionConfig` whose slug
  is still generic stops being assignable to the concrete union the admin views hold, and
  method shorthand — the previous fix — is not available to a member of a union. Without
  the indirection `useCollectionForm`, `defineConfig` and every `access` resource fail to
  type-check.
- **The stored breakpoint is restored after mount, not in a `useState` initializer.** The
  admin page is server-rendered; reading `localStorage` during render produces markup the
  server never emitted, and React keeps the server's attributes through a hydration
  mismatch — the selection was restored but its button rendered inactive.
- **Spec `2026-09-18-live-preview` is complete.** Step 6's four files had already landed
  in `b5263dc`; its `Verify: manual` is satisfied by this session's live check
