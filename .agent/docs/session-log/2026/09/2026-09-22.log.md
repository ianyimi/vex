### What was built

  `admin.livePreview.collections`/`.globals` maps with a single `resolveLivePreviewSettings`
  precedence function; `{ server }` URL resolvers resolved through a `livePreviewUrl` Convex
  query and `useLivePreviewServerUrl`; the generated `DataModel` emitted into the
  `GeneratedVexTypes` augmentation as `VexDataModel`, which gives every config callback a
  typed `ctx` without a type parameter; slug-first field generics
  (`VexResourceSlug`/`DocumentByResourceSlug`) and a `validate()` that throws instead of

  handed to config callbacks.
- **Globals now actually preview.** `LivePreviewProvider` resolved an incoming
  `collectionSlug` against `collections` only and returned early on a miss, so every global
  update died before validation. It now falls through to `globals` and validates with
  `getGlobalInputSchema(...).partial()`. The overlay map is keyed by PREVIEW KEY — `_id` for a
  collection document, slug for a global, matching what `GlobalEditView` sends — and
  `useLivePreview`/`useLivePreviewDocumentQuery` widened from `CollectionSlug` to
  `VexResourceSlug`.
- **`VexConfigProvider` moved to the app root** (`components/providers/client.tsx`), one mount
  for the admin panel and the public site. `LivePreviewProvider` now takes NO props, reading

  and both templates.
- **`<ThemeLive />` resolves `siteSettings -> theme` on the client** via a new
  `api.theme.byId`, instead of subscribing to `api.theme.getActive`. The server query does the
  join server-side and is structurally blind to an unsaved `activeTheme`.
- **The floating `LivePreviewIndicator` is gone** (developer call: it could not be expanded in
  the full-page preview route). Reverses spec Design Decision 10.
- **`toVexQueryCtx`/`toVexMutationCtx`** in `api/utils.ts` — the single place the

- Docs updated to match: the live-preview guide's "Wire the public site",

### Decisions made

- **The overlay's identity for a global is its slug, not its document id.** One document per
  global; its `_id` is an implementation detail neither side should have to agree on.
- **`LivePreviewProvider` reads config from context rather than props.** Props were a second
  provenance for the same config, free to disagree with the first.
- **Config context at the app ROOT, not per-subtree.** `ThemeLive` is root-level and needed
  the overlay, so the root is the honest home. Cost recorded: `base-nextjs` now ships
  `vex.config` in the public bundle for the first time; `apps/www` and `marketing-site`
  already paid it.
- **The ctx cast is kept and centralized, not removed.** Measured, not assumed: typing the
  param bases `ctx: VexQueryCtx` while the `DataModel` generic is still threaded gives 12
  errors (including `find`/`search`'s `withIndex` machinery), and constraining
  `DataModel extends VexDataModel` does NOT make `GenericQueryCtx<DataModel>` assignable —
  `GenericQueryCtx` is invariant in its model (`db.get` produces model-typed documents,
  `db.insert`/`patch` consume them), so the bound is irrelevant and a `= VexDataModel` default
  never fires because `ctx` always infers the parameter.
- **`access` stays on the server API functions.** It is `AccessCallOptions`
  (`{ action?, bypass? }`) — per-call overrides, already optional, and `bypass: true` is load
  bearing at 9 call sites in `apps/www/convex`. `hasPermission`'s `access` is the
  `VexAccessConfig` and is also already optional; it cannot default from config because core
  holds no ambient config and its biggest consumer is the browser, where `usePermission`
  already fills it from context.

### Problems hit

- **Preview URLs resolved on the server never got `?vexLivePreview=1`.** `NextAdminPage`
  passed `fetchQuery(livePreviewUrl, …)`'s result straight to `initialPreviewUrl`, so the
  iframe loaded an ordinary page that listens to nothing — a silent failure that made every
  other fix look ineffective. `appendLivePreviewParams` moved from `LivePreviewPanel.tsx` into
  `@vexcms/core` and both branches now route through one `resolveInitialPreviewUrl`.
- **The preview flashed the saved state between edits.** Two independent causes:
  `useLivePreviewServerUrl` embeds form values in the query key, so each edit started a new
  query whose `data` was briefly `undefined` and the hook fell back to `initialUrl`, changing
  the iframe `src` — fixed with `placeholderData: keepPreviousData`, with a regression test
  verified to fail without it. And `ThemeLive` created its `<style>` inside the effect that
  writes the CSS, so every dependency change ran that effect's cleanup and REMOVED the
  element; element ownership moved to its own mount-scoped effect. Verified by sampling
  `--background` every 25ms across a switch on a cold load: one transition, no removed frame.
- **`pnpm build`/`pnpm test`/`pnpm lint` do not typecheck test files.** A `defineGlobal`
  fixture missing its required `label` passed all four and only `pnpm typecheck`
  (`tsconfig.check.json`) caught it. Typecheck now runs for any change touching tests.

- **The commit skill now runs a docs sweep every run.** Docs had fallen behind: the
  live-preview guide still showed root `livePreview` (moved under `admin` two amendments
  ago), the theming guide still taught the `getActive` subscription that cannot see an
  unsaved `activeTheme` and the `<style>`-in-the-writing-effect pattern that flashes, and
  live preview was still advertised as "coming-soon"/"planned" in all three roadmap
  surfaces. The cause was procedural: the checklist's docs item existed but the skill's
  gate step never forced a positive, diff-driven sweep, so it was reported as done from
  memory. `.agent/skills/commit/SKILL.md` gains step 8 — build the surface list from
  `git diff` on `packages/*/src/**`, grep both the old and new spelling across
  `apps/docs`, every README, and `apps/www`'s blocks + `convex/seed.ts`, move shipped
  features in all three roadmap surfaces, verify the regenerated `llms-full.txt` with
  `grep -F` for one added and one removed string, and report every file touched. The
  checklist gains the matching gate line.

- **Swept every commit back to `0.1.0-alpha.18` for the same rot**, four parallel
  read-only audits (config split, hooks/validation, live preview/theming, cross-cutting
  roadmap+READMEs). What they found, all fixed: `@vexcms/next` and `@vexcms/react`
  READMEs still said live preview "is not implemented yet" and mounted
  `VexConfigProvider` around the admin route only; `@vexcms/core`'s README and
  `fieldValidator`'s TSDoc `@example` still taught `validate` returning a string with an
  explicit `DataModel` type argument, so the GENERATED api reference shipped a snippet
  that no longer type-checks; the core README linked a lifecycle-hooks guide that does not
  exist; `livePreviewUrl`/`globalLivePreviewUrl` still took a dead `TDataModel` parameter
  and cited `defineConfig<DataModel>()`, which no longer exists. The most interesting one

  rendered NOWHERE on the live site — four of them in the marketing template. Lifecycle
