feat(core)!: add field-level permissions to the RBAC matrix

A permission check's filter callback may now return a field map instead of a boolean —
`update: () => ({ "*": false, adminTheme: true })` — whether written bare on the action or as
the `filter` beside a `constraints` descriptor. Nothing new may be written directly ON an
action, which is what keeps a document free to own fields named `constraints` or `filter`: a
returned object is always a map, so there is nothing to disambiguate. A map is either
wildcard-bearing or partial, and an omitted key resolves to denied.

`hasPermission` remains the single gate and still returns `boolean`. It folds a resolved map
by what the caller says about the operation: with `changes` every CHANGED key must be
permitted (a field resent unchanged is not a write to it, which is what lets a full-form
submit succeed); with only `data` the map projects rather than denies, so a read is shaped
instead of refused; with neither, the existing `scope` decides. One exported resolver,
`resolveFieldPermissions`, answers the separate read-only question "which fields may this
caller touch?" and shares `hasPermission`'s role walk via `resolveRoleResults`, so the two
cannot drift.

**Type-checked with no call-site ceremony.** `ValidateFieldMaps` walks the inferred
`permissions` literal and replaces any entry whose returned map names an unknown field with a
template-literal error type, because excess-property checking does not reach an object literal
returned from a contextually typed arrow. A misspelling now reports
`✖ field map returns a field not on this resource: "admnTheme"` at the exact property — no
`satisfies`, no return annotation, no wrapper. `FieldPermissionKey` degrades to `string` when a
document enumerates no keys, so the check is inert until `vex generate` has run rather than
rejecting every map.

**Enforcement is server-side at every write site.** `create`, `update`, `upsertGlobal` and
`createMediaDocument` pass `changes`; a denied field throws `VexAccessError` carrying the field
name and no partial write lands. Read paths (`find`, `get`, `search`, `globals/get`,
`globals/find`) strip denied keys from each returned document after the existing per-document
check, never mutating what Convex returned and never stripping `_id`/`_creationTime`/`_slug`.
Call sites that asked a quantified question while spelling it as "to everything"
(`generateUploadUrl`, the revalidate route, the New/Revalidate buttons) now pass
`scope: "any"`, which they always meant; a field map would otherwise have denied them.

**Globals authorize the verb they actually perform.** `upsertGlobal` defaulted to `read`, so a
role holding only `siteSettings.read: true` could overwrite the entire global. It now
authorizes the first save as `create` and every later one as `update`, checks before Zod
validation so a denied caller cannot probe the schema through validation errors, and receives
the flattened stored document so a rule reading `data.name` sees `data.name`. Its patch now
MERGES into the stored `data` blob instead of replacing it, with validation run on the merged
result — replacing meant an omitted field was a deleted field.

**Admin panel gating, advisory only.** Read-denied fields are HIDDEN rather than disabled
across `CollectionEditView`, `GlobalEditView` and `MediaCollectionEditView`: the views derive
inputs from the CONFIG, so server-side stripping removes a value but cannot remove its input,
and a disabled input would still carry the value in its `value` attribute. Such a field is
also kept out of `defaultValues` and out of the Zod schema, so it cannot be submitted and a
required one cannot silently block Save. Update-denied fields stay visible and read-only. List
views filter their column defs with `scope: "any"`, since a column cannot answer a per-row
question.

**Edit forms submit only what changed.** All three views now send a diff built from TanStack's
sticky `isDirty` — never the derived `isDefaultValue`, which tracks the live document and
would resend a stale value for a field the SERVER changed. Paired with the globals merge this
fixes real clobbering: two editors on one document no longer revert each other's untouched
fields. `useLiveFieldMerge` completes the pair by adopting server changes into untouched
fields while leaving unsaved edits alone, which TanStack declines to do form-wide once any
field is touched.

In `apps/www` the public demo role may now change `siteSettings.adminTheme` and nothing else,
which is the acceptance scenario this feature exists for. Coverage no longer gates `pnpm test`
in any package: thresholds are gone and coverage belongs to `pnpm coverage`, because declaring
a permission callback a test never invokes is not a defect, and enabling coverage on the test
path let two concurrent runs delete each other's `coverage/.tmp` files.

BREAKING CHANGE: upsertGlobal now authorizes `create`/`update` instead of `read`. A role that
relied on a global's `read` grant to write it must be given `create` and/or `update`
explicitly. `upsertGlobal` also merges its payload into the stored `data` blob rather than
replacing it, so a caller that depended on replacement to CLEAR omitted fields must now send
those fields explicitly.
