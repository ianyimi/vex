  changeset land with the FIX commit, not before.

  fix it in the suite, never record it as a product defect. `BUGS-REPORT.md`'s

## Do not

- **Do not weaken, skip, or delete a test to make it pass.** Every red assertion encodes
  intended behavior taken from the component's own JSDoc. If a test is genuinely wrong, fix
  the test *and* say so explicitly — it is a finding either way.
- **Do not re-split `packages/react/tsup.config.ts` into two configs.** ADR-009: two tsup
  invocations cannot share a chunk, so `.` and `./testing` each bundle their own
  `AppFormContext` and every component a consumer mounts throws. Keep `splitting: true` and
  the object-form `entry`.
- **Do not reintroduce `../../form` barrel imports inside `components/fields/`.** The
  `fields` ⇄ `form` cycle is still in the module graph, only unexercised; barrel imports
  make it fatal under shared chunks (`fieldToInputComponent` returns `undefined`, suites
  collect zero tests).
- **Do not remove the `AppFormBoundary` casts** in `testing/fieldInputContract.ts`,
  `testing/nestedFieldContainer.ts`, `testing/rbacState.test.ts` until `PKG-1` is fixed —
  they are what make the kit compile. Delete them *as part of* that fix.
- **Do not unwire `apps/test` / `apps/www` from `@vexcms/next/testing`.** Consuming the
  published subpath is the only place the dual-context defect class is observable.
- Do not add a changeset or bump versions until the suite is green.
- Do not start writing task groups before the developer has confirmed that defect's fix
  approach via `AskUserQuestion`.
