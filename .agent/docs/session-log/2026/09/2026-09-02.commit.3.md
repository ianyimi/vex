fix(ci): quote the lint glob so CI and local check the same files

`pnpm lint` reported 0 errors on macOS and 115 in GitHub Actions. Not flake —
the two were linting different file sets, and had been for as long as the script
existed.

`eslint packages/*/src/**/*.{ts,tsx}` was unquoted, so the shell expanded it
before eslint ever saw it. macOS runs the script under bash: brace expansion
works, and `**` without `globstar` collapses to a single `*`, so the pattern
resolved to 163 files and matched only paths exactly one directory below `src/`.
Linux CI runs dash, which has no brace expansion at all; the glob matched
nothing, passed through literally, and eslint's own minimatch expanded `**`
recursively over every file.

Everything the developer's machine never linted lived in the gap: files sitting
directly in `src/` (`packages/next/src/NextAdminLayout.tsx`,
`packages/better-auth/src/index.ts`) and anything two or more levels deep
(`packages/react/src/components/fields/blocks/Cell.tsx`). Quoting the pattern in
`lint` and `lint:fix` hands expansion to eslint on every platform; `pnpm lint`
now reproduces CI exactly.

That surfaced 115 real errors, all fixed. Three were not documentation:

`DateTimePicker` accepted a documented `modal` prop, destructured it, and never
passed it to its `Popover` — the prop that is supposed to control popover
modality was silently dropped, leaving the date field on Base UI's scroll-locking
default. It is now forwarded, matching the opt-in pattern `MultiSelect` uses.

`Toolbar` tracked separator placement by assigning to a `needsSep` variable from
inside JSX (`{(needsSep = true) && null}`), a render-time mutation that happened
to work only because children evaluate in order. Enabled groups are now collected
into an array and joined, so separators derive from position.

`DataTable` imported `DataTableBulkActions` for a bulk-action bar that is still
commented out. The import is gone; the component stays, since it is part of the
package's public export surface.

The rest is JSDoc on previously unlinted exports across `richtext-plate` (64),
`react` (35), `next`, `core`, and `better-auth`, plus four dead imports in
`create-vexcms`. Written from reading each implementation, not generated with
`--fix`, which would have inserted empty tags that satisfy the rule and document
nothing.

Verified by running the release workflow's six steps in order: install
`--frozen-lockfile`, lint, build, typecheck, test, `check-packed-manifests` —
all exit 0, plus a publish dry-run showing all 8 packages at 0.1.0-alpha.7 with
no `catalog:`/`workspace:` leaks.
