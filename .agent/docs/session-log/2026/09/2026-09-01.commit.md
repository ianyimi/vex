feat(create)!: ship templates, cut collection codegen, prep alpha.2

WP-2 (CLI + templates, all 9 groups) plus WP-5 steps 1–3 (CI for the alpha)
and the developer's alpha.2 version pass, committed as one unit per P-016.

**apps/www → apps/test.** The demo app renames with a full cascade — root
scripts, `vex-dev`, changeset `fixed`/`linked` config, `pre.json`, standards
globs, product docs, six non-done specs' `touches:` — plus a surgical
lockfile importer-key rename instead of a full re-resolve. Live references
the old name would have broken (turbopack nuqs aliases in `next.config.ts`,
JSDoc examples in core/file-storage, the critique skill, the docs guide) are
repointed. This frees the `www` name for WP-3's marketing site.

**Per-collection generation is gone.** `@vexcms/core` removes the dead
`generateCollectionQueries` stub and its `GENERATED_HEADER`/
`CollectionQueryImports` exports; `@vexcms/cli` drops
`generateCollectionFiles` and its tests. The emitted `convex/vex/api/*`
files had no consumers — the runtime API is factory-registered
(`collectionsApi`, globals/media factories) — so `vex generate`/`vex dev`
now write only `vex.schema.ts` and `vex.types.ts`, and `vex generate` gains
`--cwd`. Two new CLI unit-test files (9 tests) cover config-path and
Convex-URL resolution.

**`RenderBlocks` in `@vexcms/react`.** A generic, typed dispatcher for
`blocks()` content: a `components` map keyed by `blockType` with each entry
narrowed via `Extract<TBlock, { blockType: K }>`, an optional `fallback`,
and `block.id` as the React key. Replaces the hand-rolled switch every
consumer wrote — apps/test's `PageContent` migrated as proof, and both
templates render page/header/footer content through it. The ui barrel now
also exports `accordion` (existed, was un-exported; the FAQ block needs it).

**Real templates, not README stubs.** `templates/base-nextjs` (93 files:
auth, admin panel, media, users, first-admin bootstrap) and the
`templates/marketing-site` overlay (44 files: pages, headers, footers,
themes, siteSettings, 8 marketing blocks, theme wiring, seed data), authored
from apps/test per the spec's translation tables. Convex artifacts are
procedure-generated against an anonymous local deployment — never
hand-written — and the overlay ships its own artifact set so Contract 6
(deployment-less typecheck/build) holds for full scaffolds. Overlay-only
files (collections barrel, `api.ts`, `src/vex.config.ts`) stay out of base
so `--bare` keeps compiling; template code is aligned to the current core
API (canonical lucide names, `description` out of `admin`, array-wrapped
select seeds, `.filter()` in access predicates).

**create-vexcms grows `--monorepo` and `--yes`.** `helpers/monorepo.ts`
walks to the nearest `pnpm-workspace.yaml`, targets `apps/<name>`, and
rewrites deps catalog-aware (new `yaml` catalog entry); `--yes` accepts
every prompt default. `updatePackageName` now also substitutes
`{{PROJECT_NAME}}` in the scaffolded README.

**Honest gates.** The create-vexcms integration suite loses its 17
silent-return guards — template absence is now a hard `beforeAll` failure —
and scaffold-smoke graduates to a shared assertion module (31 tests).
`scripts/verify-scaffold.mjs` (root `verify:scaffold`) proves both templates
from packed tarballs outside the repo (create → install → typecheck →
build), with a `--negative` AP-013 self-test.

**CI for the alpha (WP-5 1–3).** `pnpm lint` is green (JSDoc on the flagged
exports, stale text-field `min`/`max` examples swept, unused eslint-disables
removed), so it can gate. `release.yml` pins all actions to full commit SHAs,
moves to Node 22, adds `id-token: write` + `NPM_CONFIG_PROVENANCE` on the
publish step only, runs lint, and builds/typechecks apps/test so app-level
breakage cannot ship silently. New `ci.yml` runs the same checks minus
publish on PRs to master, concurrency-cancelled per ref, with both
`check-packed-manifests` legs and no token or publish surface.

**alpha.2 version pass.** `pnpm version:packages` in pre mode consumed the
16 pending changesets into `pre.json`, moved the fixed group to
`0.1.0-alpha.2`, wrote each package's CHANGELOG, and synced template dep
ranges to `~0.1.0-alpha.2`. Four new changesets cover this commit's package
changes (create-vexcms + react + cli minor, core patch).

**Docs + harness.** Root README and the docs quickstart are restored to
`pnpm create vexcms@latest`; the create-vexcms README is rewritten for the
real templates; the `template-sync` skill keeps templates tracking apps/test.
WP-2 spec lands complete (9 groups, 50/50) alongside the WP-5 spec (steps
1–3 verified); session log, ledger, state/tasks/struct ride along.

BREAKING CHANGE: `vex generate`/`vex dev` no longer emit per-collection
`convex/vex/api/*` and `convex/vex/model/api/*` files; projects relying on
them must migrate to the factory-registered API exposed by `@vexcms/core`
(`collectionsApi` et al.). `@vexcms/core` no longer exports
`generateCollectionQueries`, `GENERATED_HEADER`, or `CollectionQueryImports`.
