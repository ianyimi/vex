fix(core): deny caller-scoped rules in query-shaping with no user

**`resolveAccessRule`'s query-shaping pass now shares `hasPermission`'s sentinel
guard.** The earlier `anon-constraint-fail-closed` fix made `hasPermission`'s
per-document pass deny a caller-scoped rule reached through `anonRole` when
there is no user, instead of crashing or silently widening.
`resolveAccessIndex`/`resolveAccessConstraint` — the sibling pass deciding
which `withIndex`/`.filter()` a query gets — still defaulted the caller to a
plain `{}`, so a rule like `base-nextjs`'s own `fq.eq("email", user.email)`
compiled `eq("email", undefined)` for a sessionless caller: Convex reads
`undefined` as "field is absent," so `find` read a widened range before the
per-document check (correctly) discarded the rows. The sentinel-`Proxy`
technique is extracted into a shared `createUserReadSentinel`
(`packages/core/src/access/userReadSentinel.ts`), used by both
`hasPermission.ts`'s `resolveConstrainedCheck` and `resolveAccessRule.ts`'s
`classifyRole`, so the two passes can no longer disagree about which rows a
rule describes. Two new tests in `resolveAccessRule.test.ts` pin it.

**That guard was unreachable from every real server call.** `create`, `get`,
`update`, `remove`, both `globals` write paths, both `media` API files, and
`find`/`search`'s own per-document filters all normalized
`user: args.auth?.user ?? {}` before calling `hasPermission` — collapsing a
sessionless caller's `null` to `{}` upstream defeats a `null`-keyed sentinel
before it runs. All 19 call sites across `packages/core/src/api/**` and
`packages/core/src/media/api/**` now pass `?? null` through, matching what
`find`/`search` already did for their index-resolution calls.

**`@vexcms/better-auth` gains `anonRoleDatabaseHook(role)`.** Better Auth's
`additionalFields` default-fills `roles` on every new user regardless of
`isAnonymous`, so an anonymous-plugin visitor silently lands in whatever role
every other signup gets and `anonRole` never actually applies to it. The new
`databaseHooks.user.create.before` hook stamps the same role string passed to
`defineAccess({ anonRole })` onto anonymous-plugin users specifically, keeping
the two in lockstep by construction. Wired into `apps/www` and the
`base-nextjs` template's `auth/options.ts`, both still assigning anonymous
visitors the existing `"user"` role — no permission-matrix change.

**Docs cleanup.** Example collections no longer hand-roll a
`status`/`publishedAt` lifecycle pair (`apps/www/convex/seed.ts`, the
`marketing-site` template's `seed.ts`, the root and `@vexcms/core` READMEs,
the `select`/`date` field doc pages), and the access-control guide's
constraint examples narrow on a `visibility` field instead.
`@vexcms/core`'s `select` field JSDoc example moved off the same
`status: draft/published` shape to `tier: free/pro`. `@vexcms/next`,
`@vexcms/react`, and `@vexcms/richtext-plate` READMEs now name the real
package instead of a pre-rename one; unshipped feature sections (versioning &
drafts, live preview, impersonation) are now roadmap notes; documented
exports that were never exported are removed from every table and example;
`apps/www`'s FAQ block copy dropped its "draft/publish workflows, live
preview" claim. `GlobalEditView`'s heading now wraps the global's label in
`text-primary`, matching how the rest of the admin panel distinguishes a
document's identity from its chrome.

**`providers/server.tsx`'s double `ConvexClientProvider` mount removed**
across `apps/www`, `apps/test`, and the `base-nextjs` template.
`ClientProviders` already renders `ConvexClientProvider` and is nested inside
`ServerProviders`, so the outer copy built a second
`ConvexReactClient`/`QueryClient` pair on every server render with no
consumer. `marketing-site` has no own copy of this file, so nothing there
needed the fix.

**Release tooling: `apps/www` now rides the release train.**
`scripts/sync-template-versions.mjs` sets `apps/www/package.json#version` to
the core package version after `changeset version`, since `www` is
changesets-ignored and consumes the packages via `workspace:*` — its manifest
had drifted to `0.1.1-alpha.4` against a `0.1.0-alpha.11` release line. The
guard on the `www` path is warn-and-skip, not fatal like the templates guard,
since `www` is private and its version is cosmetic.
