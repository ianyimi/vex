fix(www): let anonymous visitors read media so og:image and site images render

**Public-site media was denied to every anonymous request.** `vex/media:getUrl`
is the RBAC-gated media query: `hasPermission(read, images)` with
`throwOnDenied`. `anonRole: user` applies that role to every unauthenticated
public-site request — including the build-time metadata fetch — and the `user`
role in `apps/www/src/auth/access.ts` had no `images` entry, so `"*": false`
denied it. `resolveMediaUrl` in `lib/metadata.ts` swallowed the throw and
emitted no `og:image` on any build; `MediaImage` (Header, Footer, Split)
rendered `null`, so anonymous visitors saw no logo or split images at all. The
`user` role now carries `images: { "*": false, read: true }` with a docblock
explaining why it is load-bearing. `templates/base-nextjs/src/auth/access.ts`
had the same hole, and the marketing overlay ships no `access.ts` of its own,
so every scaffold inherited it — fixed there too, with a note to narrow via a
`constraints` rule rather than remove. Proven against the real matrix: anon
read allowed, update still denied.

**The large-image card is emitted whenever an image resolves.** Discord, Slack
and X choose the large layout from `twitter:card`, not `og:image`, and Next
auto-fills `card: "summary"` (a small thumbnail) when `twitter` is omitted.
`metadata.ts` only set it when a handle existed; now `summary_large_image`
whenever `ogImageUrl` resolved, `site` only with a handle. Mirrored into
`templates/marketing-site/src/lib/metadata.ts`. Takes effect on the next
deploy, since the page is a static prerender; Discord has cached the imageless
embed for the bare URL, so the first share should carry a query string.

**Two production symptoms diagnosed, neither changed.** Stale content after
`seed:reinit` from the Convex dashboard is the documented limitation — seed and
dashboard writes bypass the admin panel's purge route, the ISR backstop is
3600s, and the admin Revalidate button is the remedy. The React #482 crash
("An unknown Component is an async Client Component") ~2s after hydration is
the backlog's `CodePane` entry: a live `useQuery` update that introduces or
changes a `split` / `code_showcase` block re-renders the async `CodePane`
inside `PageContent`'s client tree. It was recorded as "confirmed non-fatal";
it is fatal, and the live-reactivity that motivated deferring the fix never
worked for code panes. Entirely an `apps/www` defect — `RenderBlocks` and
`packages/*` are uninvolved — so the fix stays deferred; the backlog entry now
states the real failure mode and the workaround.
