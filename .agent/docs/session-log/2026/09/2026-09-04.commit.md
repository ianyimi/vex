fix(www): deploy convex on build, add seed reinit and logout control

**No Vercel build had ever deployed the Convex functions.** `apps/www` carried no
`vercel.json`, no deploy script, and `build = next build`, so `usable-bee-730` kept
running whatever function code was last pushed by hand. That one gap produced both
of the failures reported from production, each disguised as something else. Running
`seed:init` executed a superseded `seed.ts`, so reseeding looked like it did nothing
and the site kept rendering old copy. Access control enforced a superseded
`access.ts` — the matrix before `9051c15` had `adminPanel: { access: false }` and no
`pages` read grant — so the freshly deployed Next.js route admitted a caller whom the
Convex queries then denied, and the panel rendered with access-denied errors in every
collection. Neither was an RBAC bug. `vercel.json` now sets
`buildCommand: "pnpm vex:deploy && pnpm build"`, with a matching `vex:deploy` script.
The build fails when `CONVEX_DEPLOY_KEY` is absent, which is deliberate: a deploy that
silently skips the backend is what caused this. `apps/www/README.md` documents the key,
the Convex-side `SITE_URL`, and both disguises.

**`seed:init` cannot update a seeded deployment, so `seed:reinit` now does.** `seed.ts`
is restructured into a single `runSeed(ctx, mode)` behind two `internalMutation` entry
points. `init` keeps its insert-only-if-absent behaviour verbatim — a fresh scaffold is
unaffected — while `reinit` patches every document it finds. Both locate documents by
natural identifier (theme or header/footer name, page slug, the `siteSettings`
singleton), never by id, so neither can duplicate a row and ids, inbound relationships,
and unseeded fields all survive. `siteSettings` needs care that the tables do not:
`upsertGlobal` replaces the whole `data` blob instead of merging field by field, so a
bare patch would have dropped `adminTheme` and every SEO field an editor had set;
existing values are carried forward beneath the seeded ones. Proven against dev — ten
documents patched, then three pages, one header, one footer and four themes, with
`adminTheme`, `metaTitle` and `twitterHandle` intact.

**The header offers no way to leave a session.** A new `LogoutButton` renders for a
real signed-in account in both the desktop bar and the mobile Sheet, with no sign-in
counterpart: the site has no public registration flow, and `AdminDemoButton` is already
the way in. An anonymous demo session deliberately does not count as signed in.
Better Auth's `anonymous()` plugin issues a genuine session for any visitor who opens
the read-only panel, so `session.user` is truthy for someone who never signed in to
anything, and offering them "Sign out" asks them to leave an account they do not have.
`session.user.isAnonymous` is the discriminator; `anonymousClient()` already types it.

**"View site" disappeared with the sidebar it lived in.** `AppSidebar`'s header is
inside a collapsible region, so the button vanished exactly when an admin wanted more
room. It moves to `AdminLayout`'s topbar, to the right of `AdminTopNav` and before
`SidebarTrigger`, and stays visible regardless of sidebar state. `ThemeToggle` stays
where it was. The topbar's existing "Home" is a breadcrumb to `basePath`, not a way out
to the site, which is why this is still needed.

**The `/features` code showcase demonstrates a collection becoming a database.** A
`testimonials` collection — the shape any marketing site has — sits beside the Convex
table `vex dev` emits from it. The collection is invented, but the output is not: it was
written into `apps/www`, registered in `vex.config.ts`, harvested verbatim from the
generator down to the `by_company` index vex infers, then reverted so no unused table
reaches production. This closes part of the `/features` gap the content spec describes.

**Both roadmaps now agree.** `apps/docs/.../roadmap.md` is authoritative and gains a
`## Future` section so it carries the same five statuses as the site's roadmap block;
www's `Analytics Adapter` and `Multi-Component Workspaces` move from `future` to
`exploring`, the bucket that already existed for open research. The React testing suite
is marked as required before the v0.1.0 launch in both. Nothing was removed from either.

**The `@latest` trap survived in six more places.** npm's `latest` tag still points at
the unrelated `0.0.20` line, so every install string must name `@alpha`. The previous
pass missed the root and `@vexcms/core` READMEs, `create-vexcms`'s README and CLI banner,
`apps/test`, and `apps/docs/.../guides/quickstart.mdx` — the page behind every call to
action on the site. Pre-release warnings were added atop the root and `create-vexcms`
READMEs, both of which npm publishes.

Also included, from the developer rather than this session: `themes` added to
`access.ts`'s `resources` with `read: true` for the `user` role, and a
`pnpm version:packages` run taking all eight packages to `0.1.0-alpha.11`.
