fix(react,core): overlay singleton documents in live preview

Follow-ups from the manual pass that closed spec `2026-09-18-live-preview`'s last step
(Step 6, `Verify: manual`). The spec is now complete; nothing here changes the transport
or the gate.

**Singleton documents were invisible to the overlay.** Editing a `headers` document while
previewing `/` changed nothing: `SiteHeader` read its document through a bare `useQuery`,
and the overlay only reaches documents a consumer hands it. The one piece of sugar that
existed, `useLivePreviewQuery`, assumes the `getBySlug`-returns-an-array shape, so a
`getFirst`-style singleton read had no wrapper at all and the guide's advice was to
compose the primitives by hand. `useLivePreviewDocumentQuery` is its sibling for a query
that already resolves to ONE document — a singleton read or a lookup by id — collapsing
`null` into `undefined` so consumers have a single "nothing to render" case. Its `TData`
is inferred rather than pinned, because a `getFirst` read is typed `Doc | null` while a
lookup by id is often just `Doc`, and fixing the parameter to either makes the other
unassignable. `SiteHeader` and `SiteFooter` use it in `apps/www` and in the
`marketing-site` template; the footer had the same latent bug.

**`admin.livePreview.url` accepts a literal path.** A collection or global that always
previews in one place declares `url: "/"` instead of `url: () => "/"`; `apps/www`'s
`headers` collection is the first. The union reintroduced the variance failure Step 1
originally fixed — a function type in property position is strictly contravariant, so a
`CollectionConfig` whose slug is still generic stops being assignable to the concrete
union the admin views hold, and the method-shorthand fix is not available to a member of
a union. `LivePreviewUrlResolver` is therefore declared as a method-syntax member read
back through an index access, which is what keeps `TDoc` bivariant; without it
`useCollectionForm`, `defineConfig` and every `access` resource stop type-checking.

**The selected breakpoint survives the panel closing.** The panel unmounts every time the
editor hides the preview, so the simulated width reset to full on every toggle. It now
persists per collection or global under `vex-live-preview-breakpoint:<slug>`, restored in
an effect rather than a `useState` initializer: the admin page is server-rendered, and
reading `localStorage` during render produces markup the server never emitted — React
keeps the server's attributes through the mismatch, which left the restored button
rendered inactive. `resolveStoredLivePreviewBreakpoint` is exported for its unit tests and
drops a stored width that is no longer configured.

**The split re-measures when the preview is opened.** `useLivePreviewPanelMinSize`
returned a `RefObject` and measured in a mount-only effect, so a split mounting later —
which is every open of the preview — kept the default floors and the handle's travel was
wrong until something else forced a resize. It returns a callback ref now and keys the
`ResizeObserver` effect on the measured element.

**Admin chrome.** `AdminTopNav` breadcrumbs render the collection's `admin.icon` beside
its label, matching the sidebar and the dashboard cards. `AdminLayout` places
`ViewSiteButton` next to the breadcrumbs rather than pushing it to the opposite edge with
`ml-auto`.

**Template sync.** `SiteHeader`, `SiteFooter` and `collections/headers.ts` are mirrored
onto `templates/marketing-site` — the template had the hook wiring without the
`livePreview` config that gives its header a preview panel to be driven from. Everything
else `scripts/template-diff.mjs` reports is pre-existing drift this commit does not touch.

**Docs.** `packages/core/README.md` and `guides/live-preview.mdx` describe the string form
of `url` and the new hook; the guide's "compose the primitives" paragraph is replaced with
the reason every editable document on a page needs a wrapper, not just the page's own.

`footers` still has no `admin.livePreview.url`, so its wiring has no editor surface yet —
deliberate, it gains one when the footer needs a preview panel.
