docs(plan): close out live preview, re-spec versioning & drafts

**Launch plan: E is done, C is next.** `v0.1.0-launch-plan.md`'s sequence table flips row
4 (E — live preview) to ☑ done against `b5263dc` and row 5 (C — versioning & drafts) to
◑ next up; `roadmap.md` and `docs/tasks.md` follow, with E moved to Recently Done and C
promoted into In Progress carrying its re-scope conditions.

The E section itself is marked SHIPPED and kept as the record of *why* the feature is
shaped the way it is, with the four places the build diverged from the written design
called out inline and the spec's own `## Design Decisions` named authoritative where they
disagree: the transport is dual `postMessage` + `BroadcastChannel` (`postMessage` alone
cannot reach a tab the admin never opened); the preview gate is a session-verified
`vex-live-preview` cookie rather than a request header, because a `next/headers` read in
the site layout opted every public route out of static prerendering; `@vexcms/next` ships
no `NextLivePreviewProvider`, since the config carries functions and cannot cross the RSC
boundary as a prop (ADR-013); and the split-pane width persists in a server-read cookie
rather than `autoSaveId`, so the pane paints at its remembered size instead of snapping.

**`2026-08-23-versioning-drafts` is superseded by `2026-09-20-versioning-drafts`.** The
old draft predates three things that invalidate it: F's write pipeline and lenient
validation mode, E's overlay (which removes the only reason drafts were needed for
preview, and needs no change itself — the overlay already applies to whatever document
the consumer's query returned), and the `access-constraint-builder` rework that deleted
the index API its Step 10 was written against. The replacement is a fresh 18-group spec;
the old `spec-tasks.md` gains a "Superseded" banner and is kept for its design history,
since `design-review.md`'s two-row model, RBAC shape, and read-path analysis carry
forward unchanged. A new spec id rather than an edit, so it is unambiguous which file is
implementable.

**Admin dashboard cards show collection icons.** `DashboardView` renders a collection's
or global's configured `admin.icon` beside its card title, matching how the sidebar
already presents them; entries without an icon are unchanged.

**`apps/www` tidy-ups.** `SessionButton` drops its raw `lucide-react` imports for the
package's own `Icon` component and shows a spinning `LoaderCircle` while a sign-out is in
flight. `auth/access.ts` factors the repeated `{ "*": false, read: true }` grant into a
`readOnly` const — behavior identical, though the refactor also removed the block comment
explaining why `images.read` is load-bearing for the public site (`MediaImage` and
`src/lib/metadata.ts` both resolve uploads through the RBAC-gated `vex/media:getUrl`).
