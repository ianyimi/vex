### Decisions made

- **`revalidateSeconds` deleted from the config entirely.** Next reads
  `export const revalidate` by static analysis before any module executes, so it
  accepts only an inline literal — measured: both a `vexConfig` member
  expression and a plain imported `const` fail the build with "Invalid segment
  configuration export detected". A config key no adapter could ever honor is
  worse than no key, so the ISR window lives as a literal in each route.
- **`revalidate: { mapper }` → `routes: { map }`,** and the route-mapping
  vocabulary moved to its own `core/src/routes/` module. The function answers
  "where does this document render?", which is not a cache concern — admin "View
  page" links, sitemaps, and preview links all want the same answer. Naming it
  after one consumer would have forced the second to either import from a
  cache-named config or duplicate the map. Developer chose `map` over `mapper`.
- **`VexRevalidateSnapshot` deleted** — proven structurally identical to
  `Partial<VexDocument>` (`Exact<>` bidirectional-extends check compiles as
  `true`). Four more names corrected for describing something other than their
  contents: `VexRevalidateTarget` → `ResolveTargetsResult`, `VexCacheOptions` →
  `VexServerClientOptions`, `RevalidateOperation` → `CrudWriteAction` (moved
  beside `CrudAction`, since it is plain CRUD-minus-read), and
  `ResolveRevalidateTargetsProps` → `ResolveTargetsProps`.
- **Wire types live in `@vexcms/core`, not `@vexcms/next`** (P-010).
  `@vexcms/react` builds the request and `@vexcms/next` parses it; neither
  depends on the other, so the contract belongs in the package below both. Also
  caught and collapsed a duplicate `VexMutationOperation` declaration.
- **`meta.protected` gates `updatedAt` injection,** not just the per-field
  `"updatedAt" in fields` check. `jwks` declares no `updatedAt` of its own, so
  the field check alone added a column to an auth-owned table that nothing would
  ever populate.
- **`meta.locked` is the runtime reserved-key discriminator.** A bare

  field and breaks the auth adapter outright.
- **Step 6's and the scaffold gate's assertions were corrected, not weakened**

### Decisions made

- **Folded `packages/react/tsup.config.ts` back to ONE config with `splitting: true`.**
  Two separate tsup invocations cannot share a chunk, so `.` and `./testing` each inlined
  their own `createContext` call — a consumer importing `TextFieldInput` from `.` and
  `AppForm` from `./testing` got two distinct `AppFormContext` instances and every mounted
  component threw. Measured: 26/27 failures in `apps/www`, fixed to 21/27 passing. The
  `"use client"` banner now stamps the testing bundle too; inert in a vitest process.
  Runtime correctness beat the cosmetically clean banner. **Do not re-split.**
- **Broke the `fields` ⇄ `form` circular import** (import paths only, 14 files). Field
  `Input.tsx` files now import leaf modules (`../../form/createFieldInput`,
  `../../form/FormLabel`) instead of the `../../form` barrel, which pulled in
  `FormArray`/`FormBlocks`/`FormGroup` → back into `../fields`.
- **The shared `renderField` now provides every context a field may read** — nuqs adapter,
  `VexConfigContext`, `QueryClientProvider`, `ConvexProvider`. This removed 338 rows of
  harness noise (208 nuqs + 78 media-collection + 52 QueryClient) that read like product
  defects but were missing test scaffolding.

### Problems hit

- **`splitting: true` exposed the circular import as a hard failure.** Latent under separate
  bundles; with shared chunks esbuild resolved it in the wrong order,
  `fieldToInputComponent("text")` returned `undefined`, and `apps/test` collected **zero
  tests**. Diagnosed by a sibling agent, fixed at the source rather than reverting — the
  cycle is a real defect and reverting would only re-hide it.
- **I dropped the `"use client"` banner** when folding the tsup configs, hard-failing
  `apps/www`'s RSC build. Caught by a sibling agent mid-flight and restored.
- **`pnpm --filter <pkg> test -- <pattern>` does not forward the pattern to vitest.** Steps
  2, 3 and 10's Verify commands were silently full-suite runs that only passed while
  everything was green. Rewritten to `exec vitest run <file>`.
- **`convexTest(schema)` throws without an explicit modules map** (`import.meta.glob` is a
  Vite macro that stays literal in convex-test's prebuilt dist). Added `testModules`;
  core's own suite has the same workaround.
- **Both apps needed `src/**/*.test.ts(x)` excluded from their tsconfig.** With
  `customConditions: ["source"]`, importing the kit pulls the harness's *source* into the
  app's tsc program, where `accessFixtures`' hardcoded `slug: "posts"` isn't in the app's
  generated slug union. `next build` failed until excluded; vitest is unaffected.
