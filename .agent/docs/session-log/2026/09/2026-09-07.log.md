### Decisions made

- **`revalidateSeconds` deleted from the config entirely.** Next reads
  `export const revalidate` by static analysis before any module executes, so it
  accepts only an inline literal — measured: both a `vexConfig` member
  expression and a plain imported `const` fail the build with "Invalid segment
  configuration export detected". A config key no adapter could ever honor is
  worse than no key, so the ISR window lives as a literal in each route.
- **`revalidate: { mapper }` → `routes: { map }`,** and the route-mapping
  vocabulary moved to its own `core/src/routes/` module. The function answers
  "where does this document render?", which is not a cache concern — admin "View
  page" links, sitemaps, and preview links all want the same answer. Naming it
  after one consumer would have forced the second to either import from a
  cache-named config or duplicate the map. Developer chose `map` over `mapper`.
- **`VexRevalidateSnapshot` deleted** — proven structurally identical to
  `Partial<VexDocument>` (`Exact<>` bidirectional-extends check compiles as
  `true`). Four more names corrected for describing something other than their
  contents: `VexRevalidateTarget` → `ResolveTargetsResult`, `VexCacheOptions` →
  `VexServerClientOptions`, `RevalidateOperation` → `CrudWriteAction` (moved
  beside `CrudAction`, since it is plain CRUD-minus-read), and
  `ResolveRevalidateTargetsProps` → `ResolveTargetsProps`.
- **Wire types live in `@vexcms/core`, not `@vexcms/next`** (P-010).
  `@vexcms/react` builds the request and `@vexcms/next` parses it; neither
  depends on the other, so the contract belongs in the package below both. Also
  caught and collapsed a duplicate `VexMutationOperation` declaration.
- **`meta.protected` gates `updatedAt` injection,** not just the per-field
  `"updatedAt" in fields` check. `jwks` declares no `updatedAt` of its own, so
  the field check alone added a column to an auth-owned table that nothing would
  ever populate.
- **`meta.locked` is the runtime reserved-key discriminator.** A bare
  `"updatedAt" in fields` throw rejects better-auth's own legitimately-declared
  field and breaks the auth adapter outright.
- **Step 6's and the scaffold gate's assertions were corrected, not weakened**
  (AP-012). Step 6 asserted `/` prerenders before Step 7 migrated its reads —
  impossible at that step; it now asserts `/_not-found` and `/unauthorized`,
  which only the cookie read was keeping dynamic. The scaffold gate demanded a
  sitemap `<loc>` with no Convex deployment, where degrading to `[]` is the
  designed behavior; it now asserts well-formedness.
- **Template `/[slug]` splits its two failure modes,** deviating from the spec
  draft: a throw means unreachable deployment (must still build under
  placeholder env), a successful empty result means 404. The draft's
  swallow-to-`undefined` served a full `WelcomePage` at 200 for every bogus URL —
  a soft 404 worse than the empty-200 Step 1 fixed. `/` keeps the old shape
  deliberately, since `WelcomePage` there is real pre-seed onboarding.
- **`cacheComponents` deferred, not attempted.** Assessed by enabling it on
  `apps/www` and building until every error class was enumerated: 4 blockers,
  ~2–3 days. Deferred because it is an app-wide switch that also enables Partial
  Prerendering, so it changes how the cookie-driven admin panel renders and
  cannot be adopted per route. Tags are additive, so waiting costs nothing.

### Problems hit

- **`pnpm install` was already broken for fresh scaffolds.** Transitive
  `@better-auth/passkey` resolved to 1.7.2, whose peer range excludes the pinned
  `better-auth@1.6.23`; `ERR_PNPM_PEER_DEP_ISSUES` killed the install before
  anything built. Pre-existing and invisible until upstream published a newer
  minor. Fixed by mirroring the monorepo's own `pnpm.overrides` +
  `peerDependencyRules` into `base-nextjs/package.json` (marketing-site has no
  `package.json`, so base covers both).
- **The AP-013 negative self-test could never fail.** It returned `1` on both
  branches, and the Verify line wraps it in `!`, so a broken route assertion
  would have inverted to a pass forever. The exit code now discriminates: `1`
  when detection worked, `0` when it did not.
- **Template generated artifacts were stale and regeneration is not uniform.**
  Missing `updatedAt` is not cosmetic — the write path stamps that column, so a
  scaffolded project failed Convex schema validation on its first save.
  Standalone regeneration is wrong twice: prettier misses the underscore-renamed
  `_prettierrc`, and `marketing-site` cannot resolve its own config because
  `convex/auth/options.ts` comes from base. Regenerating inside the gate's own
  `--keep` scaffolds gave a clean 5-line diff for marketing-site; base is still
  lossy (org tables sit behind the conditional `{{ORGANIZATIONS_PLUGIN}}` marker)
  so it took only its one real delta.
- **`number()`'s `0` default leaked into create forms** as `updatedAt: 0` — a
  document claiming it was last updated at the epoch. The injected field
  overrides `defaultValue: undefined`. Skipping `readOnly` fields wholesale was
  the wrong fix: they render from form state, so edit mode would have stopped
  displaying them.
- **`defineCollection`'s conditional parameter broke two wrappers.**
  `defineMediaCollection` forwarded its own unresolved `TFieldSlug`, which TS
  cannot check against a conditional type; it now passes `string` (truthful — its
  `fields` is a widened Record) and casts at the boundary. `@vexcms/react`'s
  `defineCollection` wrapper now derives its parameter from core's signature via
  `Parameters<typeof coreDefineCollection<…>>[0]`, so the reserved-key guard
  reaches its callers instead of being silently dropped.
- **`createVexSitemap` could emit `Invalid Date`.** It omitted `lastModified`
  only when `getUpdatedAt` was absent entirely, so a per-entry `undefined` became
  `new Date(undefined)`. Reachable precisely because Step 9 made `updatedAt`
  exist-but-empty for seeded/imported rows. Now resolved per item.
- **Self-inflicted: `git checkout apps/www/src/app` while reverting the
  `cacheComponents` experiment clipped six of this session's own files.** Caught
  immediately, all six restored by hand and re-proven against the Step 6 and
  Step 7 gates including the cache assertions before continuing.
- **`Math.random()` in `SidebarMenuSkeleton`** blocked prerendering under
  `cacheComponents` and was a live hydration-mismatch hazard regardless — a
  `useState` initializer runs during render on both server and client. Replaced
  with a hash of `React.useId()`, which is stable across both and keeps the
  intended per-row width variety (measured: 50–90%, 10 distinct of 12).
