### What was built

- **`ThemeStyle` no longer hoists the admin block.** `scope === "admin"` returns a plain
  `<style data-vex-theme="admin">` rendered in place inside the admin layout; only the
  site block keeps `href` + `precedence`. Applied to `apps/www`, `apps/test` and
  `packages/create-vexcms/templates/marketing-site`.
- **`ThemeLive` appends to `<body>`, not `<head>`.** With the admin server block now
  in-tree, the end of `<body>` is the only insertion point that follows *both* server
  blocks (hoisted site block in `<head>`, admin block inside the admin subtree), so the
  live override still wins at equal specificity.
- **`apps/docs/.../guides/theming.mdx`** rewritten to teach the corrected pattern: the
  snippet branches on scope, "Site vs admin scope" gains a "never hoist the admin block"
  paragraph, and "Live updates" states the body-end insertion rule.
- Changeset `admin-theme-scope-leak.md` (`create-vexcms` patch).

### Decisions made

- **`precedence` means "document-scoped", and that is now the rule.** A hoisted `<style>`
  is a React *resource* with document lifetime; only the site theme has document lifetime.
  Route-scoped CSS must render in-tree so React's deletion path removes it.
- **Rejected: having `ThemeLive` remove the leftover hoisted node on unmount.** React
  retains `resource.instance` after the node is detached, so `acquireResource` would never
  re-insert it — a second visit to `/admin` would paint in the site palette until the
  Convex query resolved.
- **Rejected: scoping the admin CSS to a container selector** (`[data-vex-admin]`, or
  `:root:has([data-vex-admin])`). Correct in principle, but it moves the selector contract
  into `@vexcms/core`'s `buildThemeCss` — published API, docs, templates — and the
  descendant variant breaks every Radix portal that renders outside the admin subtree.

### Problems hit

- **The bug: the admin theme followed the visitor back to the public site.** Open the
  demo admin (anonymous session via `AdminDemoButton`), set `siteSettings.adminTheme` to a
  palette different from the active theme, then use the panel's "View site" link — the
  marketing site rendered in the admin palette until a hard reload.
  **Root cause:** `<ThemeStyle scope="admin" />` rendered `<style href precedence>`, which
  React 19 treats as a stylesheet *resource*. react-dom's `commitDeletionEffectsOnFiber`
  (fiber tag 26) only decrements `resource.count` for resources — it removes the DOM node
  only for non-resource hoistables — so the `:root:root` block stayed in `<head>` after
  the admin layout unmounted and outranked the site's `:root` block. `ThemeLive`'s own
  block was never the culprit: its effect cleanup removes it correctly.
  **Repro (headless, `localhost:3020`):** load `/admin`, click "View site", read
  `getComputedStyle(document.documentElement)['--primary']` — pre-fix
  `oklch(62.31% 0.18801 259.81)` (admin blue) on `/`, post-fix the site's ember. Verified
  again on `apps/www` (`localhost:3030`) through the anonymous demo flow, and that a
  mutated `#vex-theme-live-admin` block still overrides the server block inside `/admin`.
- **Noticed, not fixed:** `/auth/*` renders with no server theme block at all. Those routes
  sit outside `(frontend)/(site)`, and `ThemeStyle` moved out of the root layout when it
  was made Convex-free, so a hard load of `/auth/sign-in` paints from `globals.css` until
  `ThemeLive` resolves. Pre-existing and separate from this fix.
