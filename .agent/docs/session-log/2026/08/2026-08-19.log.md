### Decisions made

- **`scope` replaced `mode`, with three values and an `all` default.** `PERMISSION_EVAL_MODES`
  → `PERMISSION_SCOPES` (`doc` / `any` / `all`). Omitting `data` is a *quantified* question, so
  the answer depends on which one you're asking: `any` → `true` (nav/sidebar gating), `all` →
  `false` (bulk actions), `doc` → throws (edit views must supply the document). Default is
  `all`, i.e. fail-closed and never throwing. Deviates from the spec, which had a two-value
  `mode` with a throwing default.
- **`vexServerApi` takes a callback, and `DataModel` is a required type argument.** `config` is
  static but `auth` is per-request, so it must resolve from `ctx` on every call — hence the
  callback rather than an auth value. Core cannot discover `config` implicitly (it lives in the
  consumer project; a module-level singleton would be import-order dependent and untestable).
  `DataModel` has no default because falling back to `GenericDataModel` produces an unreadable
  `ctx` mismatch at every call site instead of an error at the factory.
- **Client wrapper return types are inlined in signatures, not named.** TypeScript prints a
  referenced non-conditional alias by name, so returning `FindReturn<…>` hovered as
  `FindReturn<"session", Record<string, never>, 0>`. Signatures inline `DocReturnItem<…>[]`
  instead, which hovers as `SessionDocument[]`. The no-op-conditional alternative forces clean
  display but is not assignable while generic, and would have required `as` casts at 8
  implementation sites.
- **Client args interfaces default `D = number`; the functions default `D = 0`.** The interfaces
  are used as standalone prop types (`usePaginatedQuery`), where `0` would reject `depth: 1`.
- **Relationship/upload `interfaceType` now emits the literal target slug.** Was a static
  `Id<CollectionSlug>[]`, which made `RelationshipTargetOf` infer the whole slug union.
- **`access: undefined` intentionally fails open** — that is the "no RBAC configured" escape
  hatch, not a bug.

### Problems hit

- **Public site 500 after migrating `convex/pages.ts` to the bound API.** RBAC then applied to
  reads made by anonymous visitors; `hasPermission` denies when `knownRoles.length === 0` and
  `get` throws on denial. Fixed by marking the two proven-public queries (`getIndex`,
  `getBySlug`, both rendered by `src/app/page.tsx` and `src/app/[slug]/page.tsx`) with
  `skipAccess: true`. Verified `/` back to 200.
- **`convex` resolved to two versions (1.42.1 + 1.44.0)**, producing `QueryBuilder` shape
  mismatches across `apps/www/convex/*`. Root cause: a `pnpm.overrides.convex: ^1.39.1` in the
  root `package.json` outranked the workspace catalog, so bumping the catalog had no effect
  (compounded by `CI=1` in the shell, which makes pnpm default to `--frozen-lockfile`).
  Resolved by removing the override.
- **`useAuth` appearing to return `null` when signed in** was the `useSession()` pending window,
  not a bug — resolved structurally by moving to a server-resolved auth context.
- **Two access tests broke** when the `scope` default changed to `all`; both asserted the
  throwing default. Realigned: they now pass `scope: "doc"` explicitly, and a new test guards
  the `all` default (resolves `false`, never throws).
- `find.queryKey` could not stay an expando property once `find` became overloaded — exported
  as `findQueryKey` with `find.queryKey` kept as an alias.
- `usePaginatedQuery`'s `continueCursor: null` sentinel violated Convex's `string` type once
  `data` stopped being `any`; settled on `""` (falsy, never reaches `paginationOpts.cursor`).
