### Decisions made

- **`no data` + a document-reading callback answers a *quantified* question.** Kept the
  three-way `scope` (`doc`/`any`/`all`) rather than collapsing `hasPermission` to a bare
  boolean: `any` for nav/list gating, `all` for bulk affordances, `doc` to demand the document.
  A boolean cannot distinguish "denied" from "you asked the wrong question".
- **The RBAC switch lives on the access config, not in `vex.config.ts`.** An earlier attempt put
  a `RBAC_ENABLED` const in `auth/access.ts` exporting `access | undefined`; it was reverted in
  favour of the developer's `enabled` field, which is strictly better — it travels *inside* the
  object both halves already receive, so there is no second wiring to forget. Reverting also
  restored `auth/hasPermission.ts` byte-for-byte.
- **`update` authorizes on the stored row, not the merged result.** Matches `get`/`find`/`remove`;
  a merged-result check (blocking a doc being moved into a state you could not create) is a
  separate, more advanced policy and was left out.
- **`no-empty` allows empty `catch`** via config rather than editing the two deliberate
  best-effort formatter fallbacks in the CLI.
- **`react-hooks` plugin NOT added.** It is neither installed nor registered, so the stale
  `eslint-disable react-hooks/exhaustive-deps` in `PlateEditorField.tsx` was converted to a
  plain comment. Installing it would add a dependency and surface new errors in a package
  slated for rewrite. Note `tech-stack.md` claims `react-hooks` is configured; it is not.
- **`auth-file-roles` widened** to allow `access`/`hasPermission`/`plugins` rather than renaming
  the three files the RBAC spec introduced.

### Problems hit

- **`adminPanel.access: false` had no effect.** The admin route checked `getToken()` only —
  authentication, never authorization — and `adminPanel` appeared nowhere in any enforcement
  path. Fixed with the gate above.
- **Privilege escalation in `update`.** It passed `data: args.data` (the caller's patch) to
  `hasPermission`, so a per-document rule could be satisfied by the payload rather than by the
  row being protected. Its siblings all pass the fetched document. Verified the new regression
  test fails against the old code before restoring the fix.
- **`canCreate` false but the button still live — two causes.** The `disabled` prop was
  inverted, *and* the base class only had `disabled:*` variants, which never match the `<a>`
  that Base UI renders for `nativeButton={false}`; so fixing the inversion alone would still
  have shown nothing.
- **The client and server read the access matrix from different places.** `vex.config.ts` feeds
  the server; `admin/clientProviders.tsx` feeds the UI from a direct `~/auth/access` import,
  because the sanitized client config strips `access` (callbacks are not serializable across the
  RSC boundary). Commenting `access` out of the config therefore disabled only the server half.
  The `enabled` flag closes this because it lives inside the shared object.
- **Failing the proxy closed nearly created an outage loop.** `/unauthorized` was itself matched
  by the proxy, so redirecting there on a verification error would have looped during exactly
  the outage it handles. Exempted `/` and `/unauthorized`; `/unauthorized` now returns 200.
- **Five core tests broke when `enabled` landed** — hand-built fixtures predated it and were
  read as "RBAC off". Added `enabled: true` with a comment noting only `defineAccess()` defaults it.
- **`FormBlocks.tsx` had an unfinished hook hoist** (component-scope `canEdit` shadowed by an
  inner one). Removed the *unused outer* call, not the inner one: they are not equivalent — the
  inner omits `scope` (defaults to `all`, disabling controls) where the outer passed `any`.
- **Two subagents self-reported destructive edits** while fixing JSDoc (one wiped and restored
  `AdminTopNav.tsx`'s function bodies). Verified mechanically that **zero non-comment lines**
  changed across all 38 JSDoc files.
