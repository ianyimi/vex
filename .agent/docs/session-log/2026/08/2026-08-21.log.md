- **`update` authorizes on the stored row, not the merged result.** Matches `get`/`find`/`remove`;

## 2026-08-21 — 21:40 — feat(access): add anonRole fallback for unauthenticated callers, fix(core): deny caller-scoped rules in query-shaping with no user

### What was built

- **`anonRole` public-access fallback in RBAC** (`packages/core/src/access/`): optional
  `anonRole?: TRoles[number]` on the `defineAccess()` input (typed against the roles tuple, so
  a typo is a compile error) and `anonRole?: string` on `VexAccessConfig`; `defineAccess`
  validates non-empty and passes it through to the frozen config; `hasPermission` falls back to
  `[access.anonRole]` when a caller's normalized roles resolve empty (no session, `user: {}`,
  or a Better Auth anonymous-plugin user whose roles field is unset/garbage). Explicit roles
  always win over the fallback. Developer implemented the feature; agent verified all four
  files and wrote the tests.
- **Tests:** `hasPermission.test.ts` gains a 9-case `anonRole fallback` describe (boolean
  grants for `user: {}`, callback checks against document data, explicit-false still denies,
  role-less user doc falls back, empty roles array falls back, explicit roles win, unknown
  role gains nothing, non-string garbage falls back, no-`anonRole` contrast case still
  denies); `config.test.ts` gains a `defineAccess — anonRole` describe (stored, undefined when
  omitted, empty string throws `VexAccessConfigError`). Access suite 3 files / 102 tests green;
  `tsc --noEmit` clean.
- Fixed error-message typo in `config.ts` (`anonRoles` → `anonRole`).
- **Migration planning:** `.pi/agent-docs/product/maprios-roadmap-gaps.md` gains an

  (json, PDF block, block grouping) → React UI testing framework → npm publish + rebuild→master
  + www migration → multi-component last.

### Decisions made

- **`anonRole` config field over a reserved `$public` matrix row.** The `$public` design broke
  on Better Auth anonymous-plugin users (real sessions, real user docs, no roles — the public
  row would never apply). `anonRole` is a pure role-derivation fallback: no matrix-type
  changes, no wildcard-resolver changes, adapter-agnostic, and anons can share an existing
  role (`"user"`) or get a dedicated one later without migration.
- **Fallback lives inside `hasPermission`, not the API layer.** No per-function "public
  visibility" detection — all 10+ server callsites get it for free; `resolveGetAuth` already
  tolerates unauthenticated (`getAuth` → `undefined`), so zero API-layer code changes.
- **Fallback, not floor:** a caller with any non-empty roles (even unknown ones) never gains
  anon grants.
- **Garbage roles values (e.g. `42`) fall back to anon** rather than hard-deny — unreadable
  roles are treated as unauthenticated. Deliberate; noted as the one semantics choice.
- **www migration does NOT require multi-component** (Spec 43a/43b is Tier 2, main-app only);
  it moves to last. Email/textarea field types pulled out of "quick wins" into form builder
  scope since the contact form needs them.
- Hooks system stays deferred; revisit only if the form builder wants `afterCreate`
  submission notifications.
