feat(docs): generate multi-package TypeDoc API reference

**Generated API reference.** starlight-typedoc was re-enabled (it had been disabled since
2026-04-07) and expanded into a multi-package API reference. TypeDoc now reads the JSDoc on
every exported symbol across `@vexcms/core`, `@vexcms/react`, `@vexcms/next`,
`@vexcms/better-auth`, and `@vexcms/file-storage-convex` and generates a browsable page per
symbol — types, functions, interfaces — under the docs site's API Reference, injected via
`typeDocSidebarGroup`. The docs now document the actual code straight from source comments,
and `{@link}` references between symbols render as clickable cross-links, so a reader can jump
from a guide to the exact type or function it mentions. All entry points compile as one
program via `apps/docs/tsconfig.typedoc.json` (resolve strategy). Warnings were driven 120 → 0
and `treatWarningsAsErrors` is on, so a broken `{@link}`, an undocumented referenced type, or a
bad tag fails the docs build — and therefore `pnpm build`, which builds `apps/docs`. A root
`pnpm typedoc` script runs that build.

**Supporting API and a real type fix.** So the reference is complete and its links resolve,
`usePaginatedQuery` and `StorageAdapterPresignedUrlInterface` (plus its base interface) are now
exported from their package barrels, and cross-package doc links use the module-qualified
`{@link <pkg>/src!Symbol}` form. The 84 "multiple declarations" warnings were a genuine type
bug: `RelationshipFieldAdminConfig` extended the input admin base (`FieldAdminConfigInput`)
instead of the resolved base (`FieldAdminConfig`), so the `AdminField` union mixed two
comment-bearing declarations of each admin prop. Fixing the `extends` clears the warnings and
corrects resolved relationship admin props that were wrongly optional.
`entryPointStrategy: "packages"` was evaluated and rejected — per-package compilation of this
generic-heavy source throws thousands of cross-program type-identity errors, and `dts: false`
leaves no `.d.ts` to resolve against.

**Agent harness.** Initialized the harness under `.agent/`: manifest, product docs (mission,
tech-stack, dev-processes, roadmap), standards across six domains (frontend, backend, core,
testing, tooling, docs), machine-checkable naming rules, env manifest, the commit gate, and
OMP + Claude bridges. Verified content was migrated from the old `.pi/` harness and the
superseded agent files (old `.pi/` standards/prompts/skills, `.claude/commands/*`, root
`memory/`) were removed. ADR-001 records the TypeDoc decisions above.
