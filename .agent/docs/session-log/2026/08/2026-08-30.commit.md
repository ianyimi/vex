fix(packages): ship type declarations for all published packages

**Declarations.** Every one of the seven published packages advertised
`types: "./dist/index.d.ts"` and emitted no `.d.ts` whatsoever: all seven
`tsup.config.ts` files carried `dts: false`, annotated "Temporarily disable DTS
to fix CPU issue". Installing any `@vexcms/*` package therefore gave consumers
`any`. Each `build` script now runs
`tsup && tsc -p tsconfig.build.json --emitDeclarationOnly`. `dts: false` stays
on purpose and its comment now says why — tsup's rollup-dts pegs the CPU on this
dependency graph, so tsup builds JS and tsc builds types.

**Why it was disabled.** The real blocker was TS6059, `File is not under
rootDir`. Workspace dependencies resolved through the `source` export condition,
which pulls sibling `src/` trees into each package's program. The build configs
now set `"customConditions": []`, so dependencies resolve through their
published `types` entry instead; Turbo's `dependsOn: ["^build"]` already
guarantees upstream `dist/` exists first. `react` and `richtext-plate` gained a
`tsconfig.build.json`; the other five had one and gained the condition. Dev
configs are untouched and still resolve siblings through `source`, keeping
go-to-definition and single-pass typecheck.

`@vexcms/better-auth` needed more than a resolution flag: `adapter.ts` imported
`AuthFieldMeta` through `../../core/src/auth/types`, reaching into another
package's source. A package that does that cannot emit a correct declaration, so
`AuthFieldMeta` is now part of `@vexcms/core`'s public surface and the adapter
imports it from the barrel.

**Release script.** `scripts/sync-template-versions.mjs` crashed
`pnpm version:packages` outright — it read a `packages/create-cli/templates`
directory that no longer exists, and its hardcoded package list still named
`@vexcms/admin-next`, `@vexcms/ui`, and `@vexcms/richtext` from before the
renames. It now derives the package set from the workspace and warns about
template directories without a `package.json` rather than throwing.

Verified by packing `@vexcms/core`: the tarball contains `dist/index.d.ts` and
its `catalog:` specifiers are resolved to real ranges. Publishing must go through
`pnpm` — `npm pack` leaves `catalog:` literals in `dependencies`.
