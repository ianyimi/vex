feat(core)!: per-call access.action/bypass seam across the server api

Server functions hardcoded which permission verb they checked (read for the
queries, create/update/delete for the mutations) at 22 sites, so declared
customActions had zero runtime consumers and versioning had no way to ask for
readDrafts. Every raw server function, the globals/media functions, and the
vexServerApi wrappers now take one grouped access: { action?, bypass? } option,
resolved once per call by resolveAccessCall — the single enforcement seam.
bypass returns access: undefined, reusing the documented RBAC-off path (and
skipping getAuth), so no second enforcement branch exists to drift. skipAccess
is renamed away; it had no call sites.

The options are deliberately server-side only — never in a client-callable
Convex args validator. An action nothing declares used to resolve through
defaultPermissionMode, which defaulted to allow (measured: undeclared actions
and subjects returned true), making a client-chosen action a read-anything
hole. That knob is now gone entirely: the posture is pinned to deny and an
allow posture is written as a role-level "*": true — per-role and greppable.
Undeclared actions now deny, so the seam's dev guards (bypass-while-RBAC-off,
action-not-declared) are diagnostics, not security controls.

vex generate emits CustomActionsBySlug beside IndexFieldsBySlug, and
QueryCallActionFor/MutationCallActionFor type access.action per collection
slug: custom verbs autocomplete exactly where declared and are compile errors
elsewhere, with a permissive pre-generation fallback so core's unaugmented
suite still compiles. apps/www/src/auth/access.typecheck.ts pins the strict
unions with tsc-enforced @ts-expect-error assertions — no test runner.

customActions authoring hardened along the way: the RolePermissions gate is
reordered so built-in verbs resolve before any inference-dependent branch
(deferred conditionals were silently turning callback params into any), the
extractor matches query/mutation lists independently (a single-list
declaration no longer widens the action union to string), auth subjects
honour their declared custom actions, and the input field carries an
exact-keys never-intersection plus a concrete completion constituent — the
Partial<Record> bound alone is a weak type that accepts garbage keys beside
one valid entry. Registry emission fixes: index-less collections emit {}
(keyof never poisoned every SubjectMap consumer) and the augmentation key is
asserted verbatim in tests (a one-character drift fails silently to the
fallback).

Specs synced across the arc: server-api-access-options done (25/25);
constraint-builder and index-resolution ticked against code with remaining
work enumerated; versioning-drafts inherits the binding decisions and its
draft-query blocks now route through the seam. Standards harvested:
P-006..P-008, AP-004..AP-009.

BREAKING CHANGE: defaultPermissionMode is removed from VexAccessConfigInput —
the undeclared-permission posture is always deny; declare a role-level
"*": true for allow-style roles. skipAccess is replaced by
access: { bypass: true } on vexServerApi calls.
