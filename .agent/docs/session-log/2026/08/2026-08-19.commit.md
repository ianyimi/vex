feat(core)!: add rbac access control and typed api return narrowing

**RBAC.** New `packages/core/src/access/` module: `defineAccess()` builds a role → subject →
action matrix whose types are inferred from the registered collections and globals, and
`hasPermission()` resolves it at runtime, merging every role the caller holds. Every server API
guard now enforces it through `resolveGetAuth`, with `createGetAuth()` in `@vexcms/better-auth`
resolving the caller (user + active organization) from `ctx`. Leaving `access` undefined
deliberately disables enforcement, so projects that do not want RBAC pay nothing for it.

A check that inspects the document is answered by `scope` rather than by guessing what "no data"
means: `"any"` resolves such a check to `true` for nav and list gating, `"all"` resolves it to
`false` for bulk affordances, and `"doc"` demands the document and throws when it is missing.
The default is `"all"` — fail-closed, and it never throws.

**Bound server API.** `vexServerApi()` binds `config` once and resolves `auth` per call,
returning the whole server surface with both already injected. Previously every call site passed
both by hand, where omitting `config` silently disabled RBAC for that call and passing `config`
without `auth` denied every check; both failure modes are now unreachable. `skipAccess: true` is
the explicit per-call opt-out for genuinely public reads. `DataModel` is a required type
argument because `getAuth` is optional and therefore not a reliable inference site — letting it
fall back to `GenericDataModel` produced an unreadable `ctx` mismatch at every call site instead
of an error at the factory.

**Typed API returns.** The client wrappers `get`, `find`, `search`, and `globals.get` now narrow
to the document of the `collection` slug passed in, honouring `populate` and a literal `depth`.
They previously returned `ReturnType<typeof convexQuery>`, which instantiates the adapter's
generics at their constraints and collapsed query data to `any`. The narrowing contracts
(`DocReturnItem`, `GetReturn`, `FindReturn`, `SearchReturn`, `VexQueryOptions`) now live in
`api/types.ts` and are shared with the server functions so both sides narrow identically, and
`find`/`search` gained array-vs-paginated overloads so callers no longer hand-narrow a union.

Relationship and upload fields now generate `Id<"target">[]` instead of a static
`Id<CollectionSlug>[]`. That literal target slug is what lets `RelationshipTargetOf` recover the
target and a populated field resolve to `Doc<target>[]` rather than a union of every registered
document type.

**Admin UI.** `VexAccessContext`, `VexAuthContext`, and `usePermission` land in
`@vexcms/react`, and `AdminSidebar` filters collections, globals, and media collections with
`scope: "any"` so a section stays visible when the caller may read at least one of its documents.

BREAKING CHANGE: the globals mutation `globals.update` is renamed `globals.upsert`. The Convex
endpoint, the server function (`upsertGlobal`), and the client wrapper all move together —
replace any `api.vex.globals.update` reference with `api.vex.globals.upsert`.
