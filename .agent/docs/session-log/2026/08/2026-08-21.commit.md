fix(access): enforce adminPanel gate, authorize updates on stored doc

**The admin panel was never authorized.** `admin/[[...path]]/page.tsx` checked only for a
session token, and `adminPanel` appeared in no enforcement path at all — so any authenticated
caller reached the full panel regardless of the matrix, and `adminPanel: { access: false }` did
nothing. Adds `canAccessAdminPanel()` to core (which spells the subject and action once, rather
than leaving them to be hand-typed at each call site), an `UnauthorizedView` to `@vexcms/react`,
and a server-side gate that runs before the panel renders, so a rejected caller never receives
the admin shell and the collection and global names it would leak.

**`update` authorized against the caller's payload.** It passed `args.data` — the patch — to
`hasPermission`, where `get`, `find`, and `remove` all pass the fetched document. A
per-document rule such as `update: ({ data }) => !data.src.includes("example.com")` could
therefore be satisfied by the request body rather than by the row being protected: send a
permitted value for the guarded field and the write lands on a document you were never allowed
to touch. It now fetches the stored row and authorizes against that. `deleteMedia` had the
mirror-image defect — it passed no document at all, which made per-document delete rules
unsatisfiable rather than exploitable.

**RBAC gained a single switch.** `defineAccess` accepts `enabled` (default `true`) and
`hasPermission` folds `!access.enabled` into its existing "not configured" short-circuit.
Because the flag rides inside the resolved config object, the server guards and the admin UI
move together — unlike commenting `access` out of `vex.config.ts`, which disabled only the
server half, since the sanitized client config strips `access` and the UI imports the matrix
directly.

**The proxy failed open.** Its `catch` returned `NextResponse.next()`, so any error verifying
the session — Convex unreachable, a timeout — served every guarded route unauthenticated. It
now redirects. A missing cookie still goes to sign-in and clears the stale cookie; an
unverifiable session goes to `/unauthorized` with cookies intact, since the session is probably
fine and signing everyone out during an outage would be wrong. `/` and `/unauthorized` are
exempt, without which failing closed would loop during exactly the outage it handles.

**Permission-gated controls did not reflect the check.** `CollectionListView` passed
`disabled={canCreate}`, disabling the button precisely when the caller could create. Fixing the
inversion alone changed nothing visible, because `Button`'s base class carried only `disabled:*`
variants and Base UI renders an `<a>` with `aria-disabled` when `nativeButton={false}`; the
added `aria-disabled:*` variants are what grey the control and block the click. Bulk delete is
now gated in both list views, which previously offered it and let the server reject it.

**Lint covers the workspace and reports no errors.** `packages/react` and `packages/next` were
excluded from the only ESLint block that installs the TypeScript parser, so every file in them
failed to parse and was never linted; `no-undef` is now off for all TypeScript, where it only
ever fired on globals the compiler already validates. With the noise gone, the ~137 real JSDoc
failures were fixed across 38 files — comments only, no code touched — along with the remaining
eleven errors. Documenting the code surfaced its own findings: `pushSchemaStandalone` claimed to
run `convex deploy` when it only runs `dev --once`, `VexAccessContext` claimed an undefined
access config denies every check when it allows, and every export in `core/src/schema/migrate.ts`
is an unimplemented stub. `packages/cli/src/schema/generateSchema.ts` is deleted outright: dead
scaffolding, excluded from its own test run, superseded by core's `generateVexSchema`.
