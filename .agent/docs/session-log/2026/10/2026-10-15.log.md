  per-axis handles (right = width `ew-resize`, bottom = height `ns-resize`, corner =

  controls, drag cursor locked for the whole drag, width clamped to the editor.
- Image popover: new "Upload" tab creating a REAL media document through the same
  `generateUploadUrl`/`createMediaDocument` mutations the upload field uses, with alt
  text (required when the media collection requires it — new `mediaAltRequired` on the
  editor contract), drop-zone, spinner `Button isPending`, outside-click close via
  `composedPath`, "Insert image" tooltip, image button wraps with toolbar groups
  (`Toolbar trailing` slot), toolbar top corners rounded.
- Richtext editor state fixes: external `value` sync into Plate (version swaps now
  update the editor) with normalized-echo suppression; `useResetWhenSaved` defers every
  post-save `form.reset()` in both edit views until the live row reflects the save —
  kills the autosave loop that minted alternating versions endlessly.
- Live preview for `/posts/[slug]`: client `PostContent` + session-gated
  `posts.getBySlugPreview`; `useSitePreviewMode` extracted to `apps/test/src/lib`;
  `Container` uses the app's server-safe `cn` (the `@vexcms/react` barrel is
  `"use client"`).
- Versioning rework (developer-approved design): `unpublishShared` is now
  demote-and-promote — no history row written; the newest published version is demoted
  (status→draft, `publishedAt` REMOVED — only explicit unpublish strips the "was live"
  stamp) and the previous published version's snapshot is promoted onto the live row in
  place (same `_id`, its `publishedAt`, still published); no predecessor → document
  goes offline with `vex_publishedAt` cleared. New `vex_activeVersion` pointer on live
  rows (single field, one patch per operation; history rows never touched) drives the
  history dropdown's Active marker. Publish/Save Draft enabled while viewing an old
  version — verbatim republish re-stamps that version (`markVersionPublished`),
  verbatim restore makes it the current draft, neither writes a row; saveDraft's
  bootstrap snapshot deduped against existing published history. Unpublish now opens a
  confirmation AlertDialog naming the promoted version (or "go offline"); purge sends
  update (promotion) vs delete (offline).

### Decisions made
- `vex_publishedAt` keeps meaning "was ever live" when superseded; explicit unpublish
  removes it (developer rule). Reader survey confirmed nothing filters on it.
- Pointer lives on the live row only — rejected any per-version-row writes.
- Unpublish return stays `string` (modal computes the promotion target client-side;
  server re-derives authoritatively).
- Scroll-position persistence designed, deferred to backlog with `localStorage` over a
  cookie; richtext video support assessed and backlogged (Plate doesn't limit media —
  our integration is image-only by choice for now).

### Problems hit

  timeline), so unpublish/publish cycles grew versions 110→112 with no edits —

- Dialog test needed a `vex/versions:listVersions` fake + `vex_versions` table in the
  react test kit (nested api paths resolve as `vex/versions:*`, not `vex:*`).
- Plate normalizes on `setValue` (ids, merged leaves), so echo suppression had to
  record `editor.children` post-apply, compared with `CONSTRAINT_COMPARATORS.eq`
  (Convex sorts object keys; JSON.stringify false-negatives).
