### Follow-up — richtext autosave loop
- Root cause: autosave's post-save `form.reset()` ran before the live row caught up, briefly reverting fields to pre-save values; the new `PlateEditorField` external-value sync applied that revert and Plate's `onValueChange` echoed it back as a dirty edit → autosave saved V1, subscription restored V2, editor echoed again → endless alternating versions.
- Fix A (`richtext-plate`): `handleChange` drops echoes whose content equals the value the sync effect just applied; sync also skips same-content values.
- Fix B (`@vexcms/react`): new `useResetWhenSaved` defers every post-save reset in `CollectionEditView`/`GlobalEditView` until the live row reflects the save (or the server stored a normalized value), and only resets if the form still holds exactly the saved changes. Regression tests in `useResetWhenSaved.test.tsx`.
- Also: `posts/[slug]` now live-preview aware (`PostContent` + `posts.getBySlugPreview`); `useSitePreviewMode` extracted to `apps/test/src/lib`; `Container` uses the app's server-safe `cn`.

### Follow-up — unpublish rework (demote-and-promote), version re-promotion, active-version pointer
- `unpublishShared`: no longer appends a history row. Demotes the newest published version row (status→draft, `publishedAt` removed — explicit unpublish strips the "was live" stamp; being superseded never does) and promotes the previous published version's snapshot onto the live row in place (same `_id`, its `publishedAt`, still published). No predecessor → document goes offline (live row → draft, `vex_publishedAt` removed). Reader survey: nothing filters on `vex_publishedAt` (status gates everything); display-only.
- Publish/saveDraft promote-in-place already existed server-side (`markVersionPublished`, `publishFromVersion`); client gating hid them. Publish/Save Draft now enabled while viewing an old version (`viewedVersion !== null` bypasses `matchesPublished`/`isDefaultValue`).
- `saveDraft`: verbatim restore (`restoredFrom` + no edits) writes no history row; draft-bootstrap snapshot skipped when history already holds that exact published content.
- New live-row system field `vex_activeVersion` (pointer to the mirrored version; one patch per operation, history rows untouched) — schema emitted via `versionFieldsToVexSchema`, stamped by create/saveDraft/publish/unpublish, drives the dropdown's Active marker (fallback: newest row).
- Unpublish confirmation `AlertDialog` in both edit views, naming the promoted version (or "go offline"); versions loaded only while open; server re-derives the target. Purge: update (promotion) vs delete (offline).
