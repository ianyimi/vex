fix(auth): isolate Better Auth cookies per app, fix stale-cookie deletes

**Per-app auth cookie prefix.** Browsers share one cookie jar across every
`localhost` port. Another Better Auth app on :3007 issues
`__Secure-better-auth.session_token`; the proxy read that name first, failed
`getSessionWithUser`, and on redirecting to sign-in deleted this app's own fresh
session cookie, so every sign-in bounced back to the form until site data was
cleared. Each app now sets `advanced.cookiePrefix` from a new
`AUTH_COOKIE_PREFIX` constant (`vex-test`, `vex-www`; scaffolds get one derived
from the project name via `{{AUTH_COOKIE_PREFIX}}`, substituted in
`updatePackageName`). `proxy.ts` and `getSessionToken()` read the session with
Better Auth's `getSessionCookie(…, { cookiePrefix })` instead of literal names
(AP-022). Changing only the reader would not be enough: `getSessionCookie` also
prefers the `__Secure-` name.

**Secure-prefixed cookie deletion.** `redirectToSignIn` deleted
`__Secure-…session_token` without `Secure`, which browsers reject, so on https
the proxy could never clear a stale session cookie (seen on vexcms.dev). It now
expires that name with `secure: true`.

Mirrored to `templates/base-nextjs` and `templates/marketing-site`; the
scaffolder integration test asserts the prefix marker is resolved. Renaming the
cookie signs every existing session out once.

**Collection default sort.** `defineCollection`'s default
`admin.table.defaultSort.field` was `_createdAt`, a field Convex never writes;
it is now `_creationTime`.

**Admin field classes.** Every `ADMIN_FIELDS` entry in
`fields/constants.ts` gains `class: "data"`, the start of G step 6's field
classification (data vs layout fields).

**Launch planning.** ADR-016 records the localization storage model (B2).
The launch plan records C as shipped, D and G as partial, B2 decided, and
folds A's remainder into I. `post-v0.1.0-plan.md` gains the cross-feature seams
table (what changes shape before 0.1.0 vs deferred). The G, D and B3 specs are
expanded to match.
