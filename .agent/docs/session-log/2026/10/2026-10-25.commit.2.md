release: 0.1.0-alpha.27 — versions & drafts, richtext, field pass, react-free core

Merges `dev` into `master`. `master` is at 0.1.0-alpha.21 (#39, 2026-09-20); this
publishes every package at 0.1.0-alpha.27. It covers 23 commits: live preview follow-ups,
versioning & drafts (#44), a React-free `@vexcms/core`, the richtext field, the field
input consistency pass, and an auth cookie fix. The alpha.22–.26 release commits on `dev`
are already published to npm; this PR brings their changes and alpha.27 to `master`.
Every changeset is `patch` (pre mode), including the breaking ones listed below.

**Versioning & drafts.** Opt in per collection or global with `versions: { drafts: true }`.
A versioned document is one published row with a stable `_id`, at most one draft row
(`vex_publishedId`), and an immutable snapshot per content state in `vex_versions`. The
schema gains `vex_status`, `vex_publishedAt`, `vex_publishedId`, the `by_status` /
`by_published` indexes, and `draftStatus` / `indexDraftStatus` index options; unique fields
are checked among published documents only. `versionsApi()` registers `saveDraft`,
`publish`, `unpublish`, `listVersions`, `getVersionSnapshot` and `deleteVersion`, gated by
the new `saveDraft`, `publish`, `unpublish`, `deleteVersions` and `readDrafts` permissions.
`saveDraft` is one endpoint for collections and globals. `get`/`find`/`search` take
`drafts: true`. Unpublish demotes and promotes: the previous published snapshot is
restored onto the live row in place, with no new history row. The `vex_activeVersion`
pointer drives the history dropdown's Active marker. The admin gains `DraftToolbar`,
`useAutosave` and `VersionHistoryDropdown` (view, restore, republish, delete).
`NextAdminPage` preloads with the draft args, and `vex dev` no longer runs the automatic
status backfill (call `backfillStatus`).

**Richtext.** `richtext()` with a root `editor:` adapter contract implemented by
`@vexcms/richtext-plate`: inline images through the media collection, resize/crop, and
upload from the editor.

**Field input consistency pass.** New data fields: `email()`, `textarea()`, `json()`. New
layout fields that store nothing: `tabs()`, `collapsible()`, `row()`, `ui()`, all
flattened by `getDataFields()`. `admin.condition` works on every field and is enforced on
the server. Input masks: `admin.mask` per field and `fields.inputMasks` project defaults.
`min`/`max` take `number | [number, string]`, and `admin.width` takes any CSS width.
Experimental extension points: per-field and per-type component overrides and
contributions, plus `blocks`/`array` action lists. The admin reflows with the form column
(container queries plus a measured compact mode). Arrays and blocks gain item actions and
Collapse/Expand all, blocks can be copied and pasted across documents and collections, and
the relationship field was overhauled. After a failed save the admin opens the first
errored tab and focuses the first invalid field. `updatedAt` is now a date field. Fixed: an
edit inside an array or block was dropped on save.

**Live preview.** Globals are previewable. Preview URLs resolve on the server (`{ server }`
resolvers with `ctx` and a read-only `vex` api) and carry the preview params, and preview
settings can live in root `admin.livePreview.collections`/`.globals` maps. A `url` may be
a literal path. `useLivePreviewDocumentQuery` covers singleton reads. The selected
breakpoint persists per resource, and the split re-measures when the preview opens. Config
callbacks receive a typed `vex` api, and `ctx` is typed from the generated `DataModel`
without type parameters. `validate()` throws a `ConvexError` instead of returning a string.
The floating `LivePreviewIndicator` is gone.

**Packages and size.** `@vexcms/core` no longer depends on React (peer: `convex` only;
about 70 MB fewer install dependencies). Zod is imported as a namespace, so the
`@vexcms/core` bundle shrinks from about 90 KB to 46 KB gzipped.

**Admin and scaffold fixes.** Dashboard cards and breadcrumbs show `admin.icon`. The admin
theme no longer leaks onto the public site after "View site" (marketing template), and the
unauthorized page no longer flashes the wrong theme. Better Auth cookies are isolated per
app with a `cookiePrefix`, and the stale `__Secure-` cookie is now actually deleted.
`defaultSort` defaults to `_creationTime`. The www build self-hosts the Geist font.

**Docs.** New guides: versioning & drafts, conditional fields and input masks, admin
customization. New field pages: email, textarea, json, tabs, collapsible, row, ui. Every
field page is updated for the new APIs, and the roadmap is synced across the docs site,
www and its seed.

BREAKING CHANGE: Client wrappers (`get`, `find`, `search`, `create`, `update`, `remove`,
global and version wrappers, `VexQueryOptions`) moved from `@vexcms/core/client` to
`@vexcms/react/client`. `LucideIconName` is now `IconName` (re-run `vex generate`), and
`CellComponentProps.row` is `{ original }`. `useCollectionForm`/`useGlobalForm` are
replaced by `useFieldsForm({ fields })`. `versions.saveDraft` args are a
`{ collection, id, … } | { global, data }` union, and `upsertGlobal` on a versioned global
writes the published row. `LivePreviewProvider` takes no props: mount `VexConfigProvider`
at the app root. Field `validate()` throws a `ConvexError` instead of returning a string.
`array()` drops `labels`. `min`/`max` drop `{ value, error }`. `admin.width` drops
`"half"`/`"full"`. `FieldAdminConfigInput`/`FieldAdminConfig` take
`<TCollectionSlug, TComponent>`, and the per-type admin types that only added `condition`
are removed. Existing scaffolds: add `advanced.cookiePrefix` and update `proxy.ts` and
`serverUtils.ts` (this signs users out once).
