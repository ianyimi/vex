feat(core,react)!: richtext field and promote-in-place unpublish

**Richtext field end to end (spec 2026-10-13-richtext-field, steps 1-6).**
Core gains the locale-agnostic `RichTextDocument` node types, the
framework-agnostic `VexEditorAdapter`/`VexEditorComponentProps` contract
(typed through `ComponentHKT`, re-exported React-bound from @vexcms/react),
a root `editor:` key on the client config, and the `richtext()` field —
factory, `v.array(v.any())` validator, shallow Zod input schema with a
plain-text `required` check, `richTextToPlainText`, conditional
`RichTextDocument` import in generated types, and `VexStorageConfigError`
on an unknown `mediaCollectionSlug`. @vexcms/react registers the field
(Input with a visible configuration error when no editor is configured,
plain-text excerpt Cell, sorting-disabled columnDef) and wires inline
images from the existing media primitives (`find`/`search` queries,
`generateUploadUrl`, `createMediaDocument` + `media.getUrl` so stored URLs
replace blob URLs). @vexcms/richtext-plate drops all four `@ts-nocheck`
files, types against core, exports `plateEditor`/`RichText` from the root,
and lazy-loads both components so `vex.config.ts` never evaluates platejs
inside Convex functions (its jotai dependency reads `import.meta`).
apps/test dogfoods: `posts.body` is `richtext({ mediaCollectionSlug })`,
`editor: plateEditor()`, and a live-preview-aware `/posts/[slug]` route
(`PostContent` + session-gated `posts.getBySlugPreview`).

**Richtext editor UX.** Image resize grew per-axis handles — right edge
width-only (`ew-resize`), bottom edge height-only (`ns-resize`), corner
proportional (`nwse-resize`, Shift frees the ratio) — with crop-not-stretch
via an `aspectRatio` node prop honored by editor and static renderer,
"Reset ratio"/"Original size" controls, a drag-locked cursor, and width
clamped to the editor. The image popover closes on outside click
(`composedPath`, so self-removing buttons don't false-trigger), gains an
Upload tab that creates a real media document with alt text (required when
the collection requires it — new `mediaAltRequired` contract prop) and a
spinner Button, and the toolbar's image button wraps with the button groups
(`Toolbar trailing` slot). Upload failures toast for 10s with the server
message. EditorContainer no longer duplicates the host field's label and
description.

**Edit-form save stability.** `PlateEditorField` syncs external `value`
changes into the Plate editor (version swaps now update the editor) while
suppressing the normalized echo Plate emits on `setValue`; new
`useResetWhenSaved` defers every post-save `form.reset()` in
CollectionEditView/GlobalEditView until the live row reflects the save.
Together these kill the autosave feedback loop that endlessly minted
alternating versions, and keystrokes typed mid-save stay dirty instead of
being discarded.

**Promote-in-place unpublish and version re-promotion.** `unpublishShared`
no longer appends a history row: it demotes the newest published version
(status → draft, `publishedAt` removed — only an explicit unpublish strips
the "was live" stamp; being superseded never does) and promotes the
previous published version's snapshot onto the live row in place (same
`_id`, its `publishedAt`, still published); with no predecessor the
document goes offline and `vex_publishedAt` is cleared. A new
`vex_activeVersion` pointer on versioned live rows (single field; history
rows never touched) drives the history dropdown's Active marker. Publish
and Save Draft are enabled while viewing an old version: verbatim republish
re-stamps that version via `markVersionPublished`, verbatim restore makes
it the current draft, neither writes a history row; `saveDraft`'s
draft-bootstrap snapshot is deduped against existing published history.
Unpublish now opens a confirmation dialog naming the version that will be
promoted (or that the document goes offline); the ISR purge sends an update
for promotions and a delete only when going offline.

**Test infra.** Every `vitest.config.ts` sets `pool: "threads"` — vitest's
default fork workers outlive a crashed main process and convex-test's
real-setTimeout scheduler spins the orphans at full CPU; threads die with
the process (testing standards updated). The react test kit gains a
`vex_versions` table and a `vex/versions:listVersions` fake for the
unpublish dialog; core's test schema gains `vex_activeVersion`.

BREAKING CHANGE: unpublish no longer records a "taken down" history row and
no longer keeps the unpublished content live-but-draft. It now swaps the
live row's content to the previous published version (staying published)
or, with none, takes the document offline and clears `vex_publishedAt`.
Repeated unpublish/publish cycles no longer grow version history.
