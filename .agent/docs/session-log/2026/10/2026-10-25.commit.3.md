feat(core,react)!: backend-neutral query args — where, withIndex, VexError

Implements spec B3 (Steps 0–9) plus its polish pass. Public `api/*` signatures no longer
expose Convex builder types (ADR-015).

**`where` replaces `filter`.** `find` and `search` take `where`, built with the same builder
as access rules (`eq`, `neq`, `gt`, `gte`, `lt`, `lte`, `and`, `or`, `not`), with fields
named directly instead of `q.field(...)`. `withIndex` keeps its call shape; `range` is now
typed from the generated index declarations (`VexWithIndex`, `QueryIndexFieldsFor`) rather
than the Convex data model. Compilers live in `api/queryArgs.ts`
(`withIndexToConvexQueryIndex`, `whereToConvexQueryFilter`, `andConvexQueryFilters`).
`limit: 0` now explicitly behaves like an omitted limit (`.collect()`); the old "defaults to
100/20" comments were wrong.

**Serializable `where`.** `where` also accepts a plain `VexWhereNode` object, so a filter can
be saved or sent over the wire. `whereToNode` converts a builder callback; `validateWhereNode`
checks an untrusted node (shape, operator, field name, `WHERE_NODE_LIMIT` /
`WHERE_DEPTH_LIMIT`, non-empty `and`/`or`) and throws `VexError` `INVALID_WHERE` with a path.
The client `find`/`search` in `@vexcms/react` take `where` in either form (callbacks are
converted by `whereArg` before sending; `usePaginatedQuery` passes it too). A `where` on a
field the caller cannot read drops those documents, so it cannot probe hidden values.

**Access rules split into `withIndex` + `where`.** The `constraints` callback is gone. A rule
object maps 1:1 onto `find`'s arguments: `withIndex` (query actions only; a static
`{ name, range }` or a function of the caller) and `where` (callback or plain node), with the
per-document `filter` unchanged. `evaluateQueryConstraint` runs both halves; a malformed
static `where` is validated there and denies instead of crashing. On mutation actions
`withIndex` is typed `WithIndexOnMutationError`, so the editor explains the mistake instead
of reporting "expected undefined". `createAccessQueryBuilder` and its builder types are
deleted; apps, templates, seeds and `@vexcms/react/testing` fixtures use the new shape.

**Field index object form.** A field's `index` takes a name or
`{ name, additionalFields?, draftStatus? }`, declaring compound indexes led by the field and
replacing `indexDraftStatus`. One resolver, `resolveCollectionIndexes`, now feeds the schema
generator, `vex generate`, access validation, the draft-status lookup and `defineCollection`.
Field-level indexes win over same-named collection entries, duplicate names throw, and
`additionalFields` may name the injected `updatedAt`. Field factories take the field key as
an optional second generic (`text<"articles", "slug">`). `vex.types.ts` now also lists
collection-level indexes in `IndexFieldsBySlug` (apps/test gains `by_slug_title`); apps/www's
generated files, stale since before this work, are regenerated.

**`VexError`.** Throw it from a field's `validate()` and other user code instead of
`ConvexError`; it extends `ConvexError`, so the admin receives the same structured data.

**Internal renames (Decision 15).** `Access…` constraint internals become `Query…`
(`compileQueryConstraints`, `queryConstraintTypes`, `pickConvexQueryIndex`,
`statusQueryConstraint`, …); Convex-typed internals move to `access/convexTypes.ts` and are no
longer exported from `@vexcms/core`. `deepEqual` is replaced by the exported `valuesEqual`,
used by `prepareEdit`, `saveDraft` and the six React/Plate call sites.

**Tooling.** `create-vexcms`'s `OAuthProvider` type now matches its provider data, and
`scripts/scaffold-smoke.d.mts` types the smoke helper; both were tsc errors at HEAD. The spec's
Verify commands use `pnpm -r typecheck` (`pnpm -r exec tsc --noEmit` was unrunnable).

**Docs.** ADR-015; local-api and access-control guides, field pages and the drafts guide
updated for `where`/`withIndex`, the index object form and `limit: 0`; README access example
now uses `where` only for predicates an index range cannot express. Changeset covers both
breaking areas.

**Other sessions.** Launch-plan B3 step count update and the new `commit-release` skill ride
along (P-016: one commit per run).

Templates: base-nextjs `access.ts` and marketing-site `pages.ts` mirrored in-step; the
developer's guest `fields` rule in apps/test is test-only and not mirrored.

BREAKING CHANGE: `find`/`search` take `where` instead of `filter`
(`where: (q) => q.eq("published", true)`). Access rules replace `constraints` with
`withIndex: { name, range } | (caller) => …` and/or `where`; `withIndex` is not allowed on
create/update/delete. A field's `indexDraftStatus: true` becomes
`index: { name, draftStatus: true }`; field-level indexes now win over same-named
collection-level ones, and two fields declaring one index name throw. Field factories'
`TFieldMeta` generic moves to third position. `IndexRangeFn`, `AccessFilterFn`, `QueryIndex`,
`CONSTRAINT_COMPARATORS` and the constraint compilers are no longer exported; use
`valuesEqual` for value equality.
