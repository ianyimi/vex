release: 0.1.0-alpha.30 — build-time telemetry, Plate 53, covered-route isolation, root action hides

Merges `dev` into `master`, moving it from `0.1.0-alpha.21` to `0.1.0-alpha.30`. The range holds 42
commits. Release commits `0.1.0-alpha.22` through `0.1.0-alpha.29` are already on `dev`, and those
versions were published to npm from `dev`. `0.1.0-alpha.30` is new in this PR and covers the five
commits after `b2526fb release: 0.1.0-alpha.29`.

**Already released on `dev` (alpha.22–alpha.29).** Live preview for singletons and globals, with
preview URLs resolved on the server. Versions and drafts: history, publish, unpublish, draft reads
and the unified versions API. `@vexcms/core` became React-free, and its client wrappers moved to
`@vexcms/react/client`. The `richtext()` field shipped, and unpublish now promotes in place. The
field input consistency pass and backend-neutral query args (`where`, `withIndex`, `VexError`) both
landed. Packages were reorganized into domain folders. The list view and the edit view were
overhauled (slots, actions menu), and the `commitTs` field was added. Finally, live-demo admin
content and auth-safe lists shipped, along with Better Auth cookie isolation per app. Each of these
has its own `release:` commit and CHANGELOG section.

**Build-time telemetry (new).** `@vexcms/cli` sends one anonymous event from `vex dev` (once per
process) and from `vex deploy`. The event describes the config's shape (types, counts, flags), never
names or values. `create-vexcms` sends one `create` event per scaffold. Telemetry is off in CI and
whenever `DO_NOT_TRACK=1` or `VEX_TELEMETRY_DISABLED=1` is set. The new
`vex telemetry enable|disable|status [--json]` command manages the per-machine choice. The new core
option `server.telemetry.hideLogs` hides only the reminder line. A telemetry failure never fails a
command. The private `@vexcms/telemetry` package is bundled in, so consumers never install it.
Documented in `guides/telemetry.mdx`.

**CLI fix: `.env.local` for `src/` configs.** `loadConfig` used to resolve `.env.local` and the
placeholder `convex/vex.schema.ts` from the config file's directory. As a result, every
`src/vex.config.server.ts` project ran without its env. Both are now resolved from the project root.

**Rich text on Plate 53.** `platejs` and every `@platejs/*` dependency moved to 53.x. Blockquotes
are now containers: the toolbar wraps and unwraps blocks, and flat quotes saved under 52 are
converted on load without dirtying the form. `RichText` renders bulleted and numbered lists again
and no longer nests lists or links inside a `<p>`, which fixes hydration errors. The sticky toolbar
reads `--vex-form-sticky-top`.

**Admin isolated from covering routes.** The root `@auth` sign-in modal used to hijack the URL that
admin URL readers saw. The list view, tabs field, top nav and sidebar now freeze to their last admin
values while the route is covered, and list URL writes are dropped. The unsaved-changes guard lets
the "Sign in" link through. This adds the new optional `FrameworkComponents.useIsRouteCovered` and
`useSearchParams`, and the `COVERING_ROUTE_LINK_ATTRIBUTE` export. `@vexcms/next` implements them as
`useNextIsRouteCovered` and `useNextSearchParams`. The sign-in return URL now carries the full query
instead of only `?view=`.

**Config fixes.** Root `{ id, hidden: true }` entries in `admin.components.blocks.itemActions`,
`blocks.headerActions` and `array.itemActions` now hide built-ins. Before, `defineConfig()` dropped
them. When `pageSizeOptions` is unset, a custom `admin.view.pageSize` now appears in the page-size
picker.

**Live demo hotfix.** The `roles` field in `apps/www`'s auth schema is now `input: false`, so a
client can no longer set it. This app is private and ships no package changes.

**Changesets by package** (alpha.30):
- `@vexcms/core`: `core-telemetry-hide-logs`, `page-size-options-include-custom`, `root-action-hide-directives`
- `@vexcms/react`: `admin-covered-route-url-state`, `richtext-plate-53`
- `@vexcms/next`: `admin-covered-route-url-state`
- `@vexcms/richtext-plate`: `richtext-plate-53`
- `@vexcms/cli`: `cli-telemetry-and-env-local`
- `create-vexcms`: `create-vexcms-telemetry`
- `@vexcms/better-auth`, `@vexcms/file-storage-convex`: dependency bumps only

BREAKING CHANGE: the breaking changes in this range all shipped in alpha.22–alpha.29. Each one's
migration is in that version's CHANGELOG section:
- `@vexcms/core` is React-free, and client wrappers moved to `@vexcms/react/client`.
- Preview URLs are resolved on the server.
- The versions API changed with versions and drafts part 4.
- The query args changed to backend-neutral `where`/`withIndex`.
- Packages moved into domain folders.
- The edit and list views were overhauled.

`0.1.0-alpha.30` itself is non-breaking.
