release: 0.1.0-alpha.29 — live-demo admin content, auth-safe lists, list & edit view overhauls, where/withIndex query args

`master` is at 0.1.0-alpha.21; this PR takes every published package to **0.1.0-alpha.29** —
36 commits on `dev`, of which seven are release commits (alpha.22 through alpha.28) whose
contents are already published to npm. New to npm in alpha.29: the www live-demo admin content
work's package-side changes — auth-safe list loading, array-stored filter matching, the
root sign-in modal + proxy template changes, and admin chrome fixes. `pnpm version:packages`
has already been run, so the tree carries the bumped package.jsons and CHANGELOGs ready for
the `release:` commit. This message supersedes the unmerged alpha.28 release message
(`2026-11-02.commit.3.md`); its range summary is folded in below.

**Live demo + auth-safe lists (alpha.29, b714992).** `apps/www` gains `testimonials`,
`products`, and `leads` collections (seeded 200/10/60) with read-only anonymous access, row and
bulk actions, and a "Won" preset view, so the public demo admin has real list content. On the
package side: `PaginationResult` gains `viewerId` (the identity each page was read as), and the
new public `AuthTransitionProvider`/`useAuthTransition` (`@vexcms/react`) let
`usePaginatedQuery`/`useVexListQuery` drop pages read as a stale identity during sign-in/out,
keep rows on screen while a query errors, and recover from `InvalidCursor`.
`normalizeArrayStoredWhere` fixes `eq`/`neq`/empty filters on `select`/`relationship`/`upload`
fields (stored as arrays regardless of `hasMany` — `?filter=(status.eq.won)` used to match
nothing). Templates move the intercepting sign-in modal to the app root (`app/@auth`) so it
covers `/admin` too, `proxy.ts` no longer gates `/admin` (the route's own fail-closed check
with a full-deep-link `redirectTo` is the whole story), and Convex providers pass
`expectAuth: hasSessionCookie()` so anonymous visitors' sockets resume. `AdminTopNav`'s sign-in
return URL keeps the active `?view=`; `ListViewToolbar` aligns its first control. A provenance
sweep (AP-024) scrubbed spec-step/decision references from ~300 files.

**Versioning & drafts (alpha.22–24).** A real draft/publish workflow across core, react and
next: draft writes, the publish API/UI, version history with restore, unpublish, and draft
reads (`readDrafts`), unified behind one versions API. Autosave never touches the live
document; unpublish promotes in place (alpha.25).

**Live preview follow-ups (alpha.22–23).** Preview settings for globals and a root
`admin.livePreview` map, with preview URLs resolvable server-side; origin-allowlisted and
session-cookie-gated per request.

**React-free core (alpha.24).** `@vexcms/core` no longer imports React — the client wrappers
moved to `@vexcms/react/client`.

**Richtext field (alpha.25).** `richtext()` lands on the Plate.js package
(`@vexcms/richtext-plate`), with inline images from the media library.

**Field input consistency pass, parts 1–2 (alpha.26–27).** New `email()`, `textarea()` and
`json()` fields; the non-stored layout fields `tabs()`, `collapsible()`, `row()` and `ui()`;
conditional fields enforced on client and server alike; input masks; the block clipboard; and
Better Auth cookie isolation per app.

**Backend-neutral query args (alpha.28, 4d504e7).** Public `api/*` signatures drop Convex
builder types (ADR-015). `find`/`search` take `where` — the same builder as access rules,
fields named directly — or a serializable `VexWhereNode` (`validateWhereNode`, `VexError`
`INVALID_WHERE`). Access rules replace `constraints` with `withIndex` + `where` halves mapping
1:1 onto `find`'s arguments. Fields declare compound indexes via the
`index: { name, additionalFields?, draftStatus? }` object form.

**Domain-folder refactor + app form (alpha.28, f837f20).** Core's `src/api/` dissolves into
per-domain `*/api/` folders with the shared pipeline in `src/db/`; react reorganizes into
mirrored feature folders with the public export surface snapshot-checked. The old
`createFieldInput`/`components/form/` layer is replaced by the TanStack-based app form at
`@vexcms/react/form`; admin field components pair as `<Type>FieldAdmin`/`<Type>FieldCell`.

**Edit-view overhaul (alpha.28, 30b4c10).** Eight `admin.components.edit` slots plus
`BUILTIN_CONTRIBUTION_IDS.edit` render every built-in header action as a replaceable
contribution; rare actions live in the ⋯ `DocumentEditActionsMenu`. Duplicate document, an
unsaved-changes navigation guard (with a Next.js back/forward blocker), collection URLs at
`/admin/collections/<slug>`, live-preview nested-frame guard and mobile bottom sheet.

**List-view overhaul + commitTs (alpha.28, b937b2b).** A URL-driven, server-prerendered
`CollectionListView`: search, sort, an AND/OR filter builder with a per-field-type
`FilterInput` registry, column visibility/order/pinning/resizing, page size, density, a
resizable peek panel, row and bulk actions. `admin.view`/`admin.views` replace the removed
`admin.table`; shared saved views live in a new `vex_views` table, local views in localStorage.
Admin preferences collapse into two `basePath`-scoped cookies read server-side.
`find`/`search` cap total counts at `countLimit` (`totalDocsCapped`). The new `commitTs()`
field type stamps Convex's own commit timestamp; the injected `updatedAt` uses it, and values
are Unix-ms at every public boundary.

**Fixes along the way.** Better Auth cookies isolated per app; admin theme leak; form
label/description/field spacing; richtext-plate's case-only renames re-recorded so Linux CI
builds; lazy `JsonEditorView` stubbed in `JsonFieldDisplay` tests (b2ddb3a, test-only).

**Changesets by package** (the 4 changesets `changeset version` consumed into the unpublished
alpha.29; alpha.22–28 changesets are already on npm — the alpha.28 set is enumerated in
`2026-11-02.commit.3.md` and each package's CHANGELOG):

- `@vexcms/core` — array-stored-where-filters, auth-transition-list-identity
- `@vexcms/react` — admin-signin-return-and-toolbar, auth-transition-list-identity
- `@vexcms/next` — admin-signin-return-and-toolbar
- `create-vexcms` — root-auth-modal-and-proxy
- `@vexcms/cli`, `@vexcms/better-auth`, `@vexcms/file-storage-convex`, `@vexcms/richtext-plate`,
  `www` — dependency bumps only (lockstep `fixed` group)

BREAKING CHANGE: alpha.29 itself contains no breaking change. The breaking changes in this
PR's range all shipped in alpha.22–28, already published to npm; the combined migration list
is in `2026-11-02.commit.3.md` and the per-package CHANGELOGs. Headlines: `find`/`search` take
`where` instead of `filter`; access rules replace `constraints` with `withIndex`/`where`;
`@vexcms/core/convex` is removed (import from `@vexcms/core/server`); `<Type>FieldInput` →
`<Type>FieldAdmin` and `components/form/` → `@vexcms/react/form`; collection admin routes move
to `/admin/collections/<slug>` (no redirect — use `adminHref`); `DraftToolbar` is removed in
favor of `admin.components.edit` slots; `admin.table` is removed (use
`admin.view`/`admin.views`) and list-view exports are renamed without aliases; `ThemeScript`
imports from `@vexcms/react/server`; `updatedAt` is a `commitTs()` field; `VIEW_ACTIONS` rules
are boolean-only; field-permission maps also hide unlisted system/`ui()` fields; 10 client
helpers gain their `use` prefix; core is react-free (client wrappers in
`@vexcms/react/client`).
