release: 0.1.0-alpha.28 — list & edit view overhauls, where/withIndex query args, commitTs field, domain-folder core

`master` is at 0.1.0-alpha.21; this PR takes every published package to **0.1.0-alpha.28** —
32 commits on `dev`, of which six are release commits (alpha.22 through alpha.27) whose
contents are already published to npm. Only the alpha.28 content — backend-neutral query
args, the codebase-conventions refactor, the edit-view overhaul, and the list-view
overhaul + `commitTs` — is new to npm; `pnpm version:packages` has already been run, so the
tree carries the bumped package.jsons and CHANGELOGs ready for the `release:` commit.

**Versioning & drafts (alpha.22–24).** A real draft/publish workflow across core, react and
next: parts 1–4 land draft writes, the publish API/UI, version history with restore, unpublish,
and draft reads (`readDrafts`), unified behind one versions API. Autosave never touches the
live document; unpublish promotes in place (alpha.25). Singleton documents overlay correctly in
live preview.

**Live preview follow-ups (alpha.22–23).** Preview settings for globals and a root
`admin.livePreview` map, with preview URLs resolvable server-side (`{ server }` resolvers that
may read the database); origin-allowlisted and session-cookie-gated per request.

**React-free core (alpha.24).** `@vexcms/core` no longer imports React — the client wrappers
moved to `@vexcms/react/client`, making core safe for any Convex client.

**Richtext field (alpha.25).** `richtext()` lands on the 3,219-line Plate.js package
(`@vexcms/richtext-plate`), with inline images from the media library.

**Field input consistency pass, parts 1–2 (alpha.26–27).** New `email()`, `textarea()` (with
character counter) and `json()` (CodeMirror) fields; the non-stored layout fields `tabs()`,
`collapsible()`, `row()` and `ui()`; conditional fields (`admin.condition`) enforced on client
and server alike; input masks with project-wide defaults; the block clipboard; and Better Auth
cookie isolation per app (alpha.27 fix).

**Backend-neutral query args (alpha.28, 4d504e7).** Public `api/*` signatures drop Convex
builder types (ADR-015). `find`/`search` take `where` — the same builder as access rules (`eq`,
`gt`, `and`, `or`, …), fields named directly — or a serializable `VexWhereNode` validated by
`validateWhereNode` (`VexError` `INVALID_WHERE`). Access rules replace the `constraints`
callback with `withIndex` + `where` halves mapping 1:1 onto `find`'s arguments. Fields declare
compound indexes via the `index: { name, additionalFields?, draftStatus? }` object form,
resolved by one `resolveCollectionIndexes`. `VexError` is throwable from user `validate()`.

**Domain-folder refactor + app form (alpha.28, f837f20).** Core's `src/api/` dissolves into
`collections/api/`, `globals/api/`, `versions/api/`, `media/api/` with the shared pipeline in
`src/db/`; react reorganizes into mirrored feature folders with every importer rewritten and
the public export surface snapshot-checked. The old `createFieldInput`/`components/form/` layer
is replaced by the TanStack-based app form at `@vexcms/react/form` (`useAppForm`, `AppForm`,
per-type `forms/*Field.tsx`); admin field components pair as `<Type>FieldAdmin`/`<Type>FieldCell`.
A 20-finding regression audit against the pre-refactor tree is fixed with tests.

**Edit-view overhaul (alpha.28, 30b4c10).** Eight `admin.components.edit` slots plus
`BUILTIN_CONTRIBUTION_IDS.edit` render every built-in header action as an ordinary, replaceable
contribution; rare actions live in the ⋯ `DocumentEditActionsMenu` with progressive collapse.
Duplicate document (`vex.duplicate`, fresh item ids, versioned duplicates land as drafts), an
unsaved-changes navigation guard (including a Next.js back/forward blocker), collection URLs at
`/admin/collections/<slug>`, a live-preview nested-frame guard and mobile bottom sheet, and
dark-mode focus-ring fixes across apps and templates.

**List-view overhaul + commitTs (alpha.28, b937b2b).** The collection list is a URL-driven,
server-prerendered `CollectionListView`: search, sort, an AND/OR filter builder with a
per-field-type `FilterInput` registry, column visibility/order/pinning/resizing, page size,
density, a resizable peek panel, row and bulk actions. `admin.view`/`admin.views` replace the
removed `admin.table`; shared saved views live in a new `vex_views` table
(`listViews`/`saveView`/`removeView`, gated by `VIEW_ACTIONS`, org-scoped), local views in
localStorage with a cookie index. Admin preferences collapse into two `basePath`-scoped cookies
read server-side for a correct first paint. `find`/`search` cap total counts at `countLimit`
(`totalDocsCapped`) instead of collecting the whole set. The new `commitTs()` field type stamps
Convex's own commit timestamp; the injected `updatedAt` uses it, `stampCommitTsFields` replaces
`stampUpdatedAt`, and values are Unix-ms at every public boundary.

**Fixes along the way.** Better Auth cookies isolated per app with stale-cookie deletes
(a4b9d68); admin theme no longer bleeds into the main site; form label/description/field
spacing normalized across every field type (a2441a0, react); richtext-plate's case-only
component renames re-recorded via `git mv` so Linux CI builds (aa9f68d), with
`scripts/vercel-build-check.mjs` now checking tracked-path casing.

BREAKING CHANGE: (alpha.28; the alpha.22–27 breaking changes below the rule are already
published.) `find`/`search` take `where` instead of `filter` (`where: (q) => q.eq("published",
true)`); access rules replace `constraints` with `withIndex: { name, range } | (caller) => …`
and/or `where` (`withIndex` is not allowed on create/update/delete); `indexDraftStatus: true`
becomes `index: { name, draftStatus: true }`; field factories' `TFieldMeta` generic moves to
third position; `IndexRangeFn`, `AccessFilterFn`, `QueryIndex`, `CONSTRAINT_COMPARATORS` and
the constraint compilers are no longer exported (use `valuesEqual`). `@vexcms/core/convex` is
removed — import the same names from `@vexcms/core/server`; `<Type>FieldInput` components are
renamed `<Type>FieldAdmin`; `createFieldInput` and the `components/form/` exports are removed
in favor of `@vexcms/react/form`; `InputComponentProps` is removed — use `FieldComponentProps`
or `FieldControlProps`. Collection admin routes move from `/admin/<slug>` to
`/admin/collections/<slug>` with no redirect — use `adminHref`; `DraftToolbar` is removed —
customize the edit header via `admin.components.edit` slots. `admin.table` is removed — move
its keys to `admin.view`/`admin.views`; list-view exports are renamed without aliases
(`composeViewWhere` → `composeSavedListViewWhere`, `parseListParams` → `parseListViewUrlState`,
`BulkDeleteModal` → `DataTableBulkDeleteModal`, `CreateDocumentModal` →
`ListViewCreateDocumentModal`, `ListViewTabs` → `SavedListViewTabs`, `ListPeek` →
`ListViewPeek`); `CollectionListViewProps` loses `initialData`/`initialQueryError`/
`initialViews`/`initialPeekDoc`; `ThemeScript` imports from `@vexcms/react/server`; `updatedAt`
is a `commitTs()` field (`stampUpdatedAt` → `stampCommitTsFields`); the list URL `cols=`
grammar gains `:w<width>`/`:pl`/`:pr`/`:h` suffixes (old links still parse); `VIEW_ACTIONS`
rules are boolean-only (`ViewPermissionCheck` — field maps and constrained-query objects now
fail typecheck and fail closed at runtime); field-permission maps that list only some fields
now also hide unlisted system and `ui()` fields; 10 client helpers gain their `use` prefix
(`create`→`useCreate`, `update`→`useUpdate`, `remove`→`useRemove`,
`updateGlobal`→`useUpdateGlobal`, `saveDraft`→`useSaveDraft`, `publish`→`usePublish`,
`unpublish`→`useUnpublish`, `deleteVersion`→`useDeleteVersion`, `saveView`→`useSaveView`,
`removeView`→`useRemoveView`); `Button` icon+label content is no longer space-between by
default. — Already on npm (alpha.22–27): core is react-free (client wrappers import from
`@vexcms/react/client`); the versions & drafts API surface; preview-globals config shape;
richtext field; field-input pass renames. See each package's CHANGELOG for those migrations.
