### What was built
- **Plate 53.** The catalog moves `platejs` and every `@platejs/*` to 53.x. The spec's Step 6 now holds the full list of 52 → 53 breaking changes, each probed against 53.5.2 and marked with its resolution.
- **Blockquote toggle.** `Toolbar.tsx`'s `BlockButton` calls `toggleBlock(type, { wrap: true })`, because 53 quotes are containers of paragraphs.
- **Quotes saved under 52.** New `editor/wrapFlatBlockquotes.ts` converts flat 52 quotes on the editor's initial value.
- **Front-end lists.** `RichText` configures `BaseListPlugin` with `renderIndentListStatic`.
- **Valid static markup.** `ParagraphElementStatic` renders a `<div>` for list items, and `LinkElementStatic` renders its `SlateElement` `as="a"`. This removes the `<p><ul>` / `<p><div>` hydration errors on the front end and in the peek panel; links stay inline.
- **Sticky toolbar.** The toolbar's `top` reads `--vex-form-sticky-top`. The four admin form scroll areas (`CollectionEditView`, `GlobalEditView`) set it to `-1rem` to cancel their `pt-4`.
- **Tests.** Stored-value compatibility tests (`RichText.test.tsx`, `PlateEditorField.test.tsx`) run a real 52-saved `posts.body` fixture.
- **Flaky react test.** `DataTablePageSizeSelect.test.tsx` now waits for the option with `findByRole` (a load-sensitive race the developer hit in a full turbo run).
- **Bookkeeping.** Launch-plan progress note for D step 6; changeset `richtext-plate-53`.

### Decisions made
- The sticky offset is a host-declared CSS variable, not a hardcoded negative `top`. The adapter can't know the host's padding, and removing `pt-4` from the scroll area would also move the sticky sidebar.
- Static list items render a styled `<div>`, not a `<p>`. A `<p>` cannot contain the `<ul>` wrapper.

  - Regression test in `useListViewUrlState.test.tsx`. Live repro (a fresh signed-out browser context, `?filter=(title.eq.Post%25207)`, then Sign in) keeps the filter chip and the single row behind the modal.
