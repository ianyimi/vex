feat!: golden use-case fixes, vex deploy, contributor workflow, alpha.37

**`vex deploy` passthrough.** `vex deploy [--cwd <dir>] [convex deploy flags…]` forwards every flag it doesn't own to the final `convex deploy` (`--cmd`, `--preview-create`, …) through the new `parseArgs` helper; `--cwd` now actually runs from `<dir>`. Interim auto-migration pushes strip `--cmd`/`--cmd-url-env-var-name` so a custom build runs once. `convex deploy` has no timeout (was 120s); other `convex` calls keep 120s. New `guides/deployment.mdx`; both templates ship a `vex:deploy` script and point their READMEs at it instead of a three-step `npx convex deploy` recipe.

**Library fixes from the golden use-case run-throughs.** `indexedOwnerCheck`/`ownerPredicateCheck`/`indexedEqCheck` resolve indexes through `resolveCollectionIndexes` (`AccessResourceRef.indexes`), so a relationship's automatic `by_<field>` index is visible without a hand-written `index`. `buildThemeCss` takes `scope: { selector }` for a region-scoped palette. `useLivePreviewQuery`/`useLivePreviewDocumentQuery` no longer need an `as never` cast. `runVexReactSuite`'s `custom[].Component` accepts a real `*FieldAdmin` export (pinned by `testing/index.typecheck.ts`). `convex/schema.ts` imports the `user` table from the generated `vex.schema.ts` in both apps and both templates; the regenerated user tables gain Better Auth's `by_email_name`/`by_name`/`by_userId` indexes.

**Raw server calls require `config`.** `PublishedSlugsServerArgs.config` and `GenericQueryServerParams.config` are no longer optional; every server JSDoc example passes `config` and points at `vexServerApi()`'s bound functions, which thread it already.

**Scaffolder hygiene.** The template `env.mjs` skips validation inside the Convex runtime (`CONVEX_CLOUD_URL`), which broke every push once a project registered an admin component. `--port` rewrites `.env.example`; the generated auth secret lands only in `.env.local`; `_gitignore` negates `.env.example`; `packageManager` is set only when `npm_config_user_agent` names one; the passkey pin is mirrored to npm `overrides`/yarn `resolutions`; `--bare` drops the `seed` script. `marketing-site/src/vexcms/api.ts` moves to `base-nextjs`.

**Contributor workflow.** `CONTRIBUTING.md`, PR template, `SECURITY.md`, `CODE_OF_CONDUCT.md`, labels, and issue config rewritten around `dev` as the PR base; `pr-checks.yml` (Conventional-Commit title via `scripts/check-pr-title.mjs`, forks must target `dev`), `labeler.yml`; `ci.yml` also runs on PRs to `dev`. New docs `dev/contributing.mdx`, `dev/testing-and-code-style.mdx`, `guides/testing.mdx`; `github-review` skill.

**Docs.** Relationship, select, access-control, admin-customization, auth, conditional fields, local API, quickstart, theming and roadmap pages updated for the above; launch-kit L review, golden use-case playbooks and the use-case backlog land under `.agent/docs`. Release audit: added `.changeset/server-api-config-required.md` (the `config` tightening had none) and fixed `publishedSlugs`' JSDoc example, which omitted `config` and no longer type-checked. Template diff left as advisory (orphans are base-only files; marketing seed content intentionally not mirrored).

**Release.** Packages versioned locally to `0.1.0-alpha.37` (`pnpm version:packages`: CHANGELOGs, `package.json`s, `pre.json`, `base-nextjs` pins `~0.1.0-alpha.37`) so the `dev` → `master` merge publishes directly with no bot version PR. The `release`/`commit-release` skills, commit checklist and `release-and-versioning.md` standard now offer this as an opt-in **local** mode beside the default CI version PR. `react-testing-kit-camel` allows a `.typecheck` sibling.

BREAKING CHANGE: raw `@vexcms/core/server` calls (`find`, `get`, `search`, `publishedSlugs`) must pass `config`; use `vexServerApi()`'s bound functions, which supply it.
