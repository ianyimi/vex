### What was built
- `packages/telemetry` (`@vexcms/telemetry`, private, bundled into `@vexcms/cli` and `create-vexcms` via tsup `noExternal`). The root entry has no runtime `@vexcms/core` import. The `@vexcms/telemetry/config` subpath carries `anonymizeConfig`.
- Settings live at `$XDG_CONFIG_HOME/vexcms/telemetry.json`. Enablement precedence is `DO_NOT_TRACK` → `VEX_TELEMETRY_DISABLED` → CI → stored → default on. `projectId` is salted per machine.
- The payload is flat and path-based (`c3.f4.b1`, block definitions `k<n>` with `paths[]`, `i` for an array row, `t` for a tab). `outcome` is ok, or failed with stage and errorCode. Bodies are capped at 512KB, with `fitTelemetryEvent` truncating oversize payloads.
- First-run notice plus a two-line per-run reminder. `VEX_TELEMETRY_DEBUG` and `VEX_TELEMETRY_ENDPOINT` are honored.
- `@vexcms/cli`: `vex telemetry enable|disable|status [--json]`. `vex dev` sends after the first push (10s timeout). `vex deploy` sends and awaits it (1.5s). Config is passed as a lazy factory, so telemetry never fails a command.
- `@vexcms/cli` fix: `loadConfig({ configPath, projectDir })` loads `.env.local` and the placeholder schema from the project root. It used to use the config file's directory, which broke env loading for every project whose config lives in `src/`.
- `create-vexcms` sends a `create` event (ok or failed). Its tsconfig moved to bundler resolution, `@vexcms/core` became a type-only devDep, and `tsup.config.ts` is new.
- `@vexcms/core`: `defineServerConfig`'s `server.telemetry.hideLogs` hides only the per-run reminder.
- `apps/test` receiver: `telemetryEvents` + `telemetryProjects` collections, `convex/telemetry/{ingest,deriveTelemetryProject}.ts`, and `POST /telemetry/events` in `convex/http.ts`. Admins get read-only access and saved views. Declared views include Recently Active, Failing Setups, Most Collections/Globals and Custom Hooks. The endpoint is in `.env.local`, which is not committed.
- Public docs: `apps/docs/.../guides/telemetry.mdx`. `scripts/verify-scaffold.mjs` and `scripts/vex-dev.mjs` set `VEX_TELEMETRY_DISABLED=1`.
- Commit run: the docs sweep added a `vex telemetry` section to `packages/cli/README.md` and a Telemetry section to `packages/create-vexcms/README.md`. It also ticked the delivered M sub-items in the launch plan.

### Decisions made
- `anonymizeConfig` imports runtime values from `@vexcms/core`, so it moved to the `/config` subpath. That keeps a `create-vexcms` install, which has no `@vexcms/core`, from resolving a runtime import (AP-025).
- The spec's 32KB body cap was a guess: `apps/test`'s real payload was ~148KB. The cap is now 512KB, and `fitTelemetryEvent` truncates before dropping anything (AP-026).
- The payload uses flat path-based keys (`c3.f4.b1`), not the spec's original `collection1`/`field1` numbered names. Spec and spec-tasks carry the implementation corrections.
- `hideLogs` silences output only. No project-config switch disables telemetry; opting out is per machine or per env var.
- Deferred to backlog: linking telemetry snapshots to issue reports, and the array-membership (`contains`) filter operator that `telemetryProjects.fieldTypes` views need.
- The receiver lives in `apps/test` until Step 10 picks its final home.
