fix: media collection lookups, draft preview flashes, session hint

**Media collections in every core lookup.** `find`, `get`, `search`, `remove` and
`populateDocs` resolved a collection's config from `config.collections` only, so media slugs
were treated as unknown: an edited image's `updatedAt` skipped the commitTs ns→ms conversion
and reached the admin media list as a raw `bigint` ("Cannot convert a BigInt value to a
number"), and the media list's bulk delete threw "No collection registered with slug". The new
internal `findCollectionConfig` in `db/documents.ts` searches `collections` and
`mediaCollections`; `update`'s hand-rolled two-list lookup now uses it too. Found in the LI-22
D7 re-run on alpha.33; regression tests cover `get`, `search` and `remove`. Needs alpha.34 to
reach scaffolds.

**Session hint replaces an unreadable cookie check.** `convex.tsx`'s `hasSessionCookie()`
looked for Better Auth's `session_token` in `document.cookie`, but that cookie is `httpOnly`,
so the check was always false: the Convex socket never started paused for auth, signed-in
admins and preview iframes sent their first queries anonymously, and the UI flashed
anon-role results. `hasSessionHint()` now reads a `<meta name="vex-session">` presence marker
that the admin layout emits when `getToken()` resolves and that Draft Mode pages always emit.
It is a timing hint only (it never grants access; every query is still authorized from the
JWT). Applied to both apps and the `base-nextjs` template.

**Draft Mode preview without flashes.** `posts/[slug]` gets the same Draft Mode branch as
`[slug]`: it server-fetches `posts.getBySlugPreview` with the editor's token instead of 404ing
a never-published post. Both pages pass `draftMode` down so `PageContent`/`PostContent` pick
the preview query on their first client render (no hydration mismatch, no `WelcomePage` /
not-found flash), and both use `placeholderData: keepPreviousData` across query-key changes.
`PostContent` renders `NotFoundContent` instead of a blank 200 when no post resolves.
`NotFoundContent` and `AdminNotFound` are now vertically centered.

**D1 announcement guard.** The seeded 0.1.0 post carries explicit `PLACEHOLDER — replace
before D1` copy plus the post-launch roadmap list, and `reinit` skips re-patching it once it has
been published from the admin, so a reseed can no longer unpublish the live announcement.
`scripts/check-announcement-placeholder.mjs` fails while a placeholder remains; it is the last
D1 step before publishing.

**Smaller fixes.** `apps/www` page and post metadata share `buildDocumentMetadata`.
`sync-labels.mjs` exits 2 with a one-line diagnostic when `gh` is missing or a call fails.
`posts.getBySlug` uses the plain-object args form in both apps. The `host-app-providers-fixed-roles`
naming rule now allows a colocated `.test.tsx` per provider, like its `components/` and `ui/`
siblings, so the new `convex.test.tsx` files pass `harness struct --check`.

**Docs and planning.** `n-runthrough.md` records the D7 re-run. The dependency review adds the
Dependabot triage (297 alerts, 23 to address) and a proposed `dependabot.yml`; the launch plan
requires the dependency-upgrades spec before L; the backlog records the D4 vs dependency-upgrades
conflict and the admin error boundary that a Convex outage cannot reach. LI-22 is marked done.

Template sync: the provider, admin layout, `[slug]` page, `PageContent` and `NotFoundContent`
changes are mirrored into `base-nextjs`/`marketing-site`. Not mirrored: the `posts/[slug]`
changes (neither template has posts), the www seed and announcement script (vexcms-specific),
and the www `metadata.ts` refactor.
