feat(telemetry,cli,core,test): add opt-out build-time telemetry

**Anonymous build-time telemetry (launch-plan M).** The new private workspace package
`@vexcms/telemetry` is bundled into `@vexcms/cli` and `create-vexcms` through tsup
`noExternal`, so neither published package has to resolve it at install time. Its root entry
imports `@vexcms/core` for types only. `anonymizeConfig` lives on the
`@vexcms/telemetry/config` subpath because it needs core's runtime
`ADMIN_FIELDS`/`ADMIN_CUSTOM_SUBJECTS`, and a `create-vexcms` install never has core.

**Settings and payload.** Settings live in `$XDG_CONFIG_HOME/vexcms/telemetry.json`.
Enablement checks `DO_NOT_TRACK`, then `VEX_TELEMETRY_DISABLED`, then CI detection, then the
stored choice, and defaults to on; env vars can only turn it off. `projectId` is a sha256 of
a per-machine salt and the project path. The anonymized config is a flat, path-based payload
(`c3.f4.b1`, block definitions `k<n>` with `paths[]`, `i` for an array row, `t` for a tab).
It holds types, counts, allowlisted booleans and enum literals, never names, labels,
defaults or free strings. Every event carries `outcome`: `ok`, or `failed` with a `stage`
and an `errorCode` from `classifyTelemetryError`.

**Size cap and output.** Bodies are capped at 512KB. `fitTelemetryEvent` empties
per-resource arrays and sets `config.truncated` before anything is dropped. The spec's 32KB
guess would have silently dropped `apps/test`'s 148KB payload. The first run prints a
one-time notice, and later sends print a two-line reminder. `VEX_TELEMETRY_DEBUG=1` prints
the event instead of sending it; `VEX_TELEMETRY_ENDPOINT` overrides the receiver.

**CLI.** `vex telemetry enable|disable|status [--json]` is new; `status --json` prints the
exact payload without sending it. `vex dev` sends one event per process after the first
Convex push, with a 10s timeout. `vex deploy` awaits its event for up to 1.5s. A
`resolveConfig`, `loadConfig` or `generateSchema` failure sends a `failed` event before
rethrowing. Telemetry receives the config as a lazy factory, so a telemetry error never fails
a command.

**Fix: `.env.local` for `src/` configs.** `loadConfig(configPath)` loaded `.env.local` and
created the placeholder `convex/vex.schema.ts` relative to the config file's directory. Every
project with a `src/vex.config.server.ts` therefore ran without its env. `loadConfig` now
takes `{ configPath, projectDir }` and resolves both from the project root. `generate`, `dev`
and `deploy` pass the root, and `loadConfig.test.ts` covers the case.

**create-vexcms.** Each run sends one `create` event, `ok` or `failed` at stage `scaffold`.
It records framework, template, `--bare`/`--monorepo`, auth choices as booleans plus a
provider count, and the git/install flags. The tsconfig moves to `bundler` resolution, a new
`tsup.config.ts` bundles telemetry, and `@vexcms/core` becomes a type-only devDependency.

**Core.** The new `defineServerConfig` option `server.telemetry.hideLogs` (default `false`)
hides only the per-run reminder. `VexConfig.telemetry` is always resolved. No
project-config switch disables telemetry; opting out is per machine or per env var.

**Receiver in `apps/test`.** New collections: `telemetryEvents`, an append-only raw log, and
`telemetryProjects`, one row per `projectId` derived by `deriveTelemetryProject`. Events
arrive through `convex/telemetry/ingest.ts` and `POST /telemetry/events` in
`convex/http.ts`, which answers 413, 400 or 204 and reads no IP headers. Admins can read the
collections and use saved views; nobody can write through the admin. The declared views are
Recently Active, Failing Setups, Uses Drafts, Uses RBAC, Query-Constraint Access, Largest
Apps, Most Collections, Most Globals, Next.js, TanStack and Custom Hooks. The receiver stays
here until spec Step 10 chooses its final home and sets `DEFAULT_TELEMETRY_ENDPOINT`.

**Testimonials rating sort.** `testimonials.rating` in `apps/test` and `apps/www` declares
`index: "by_rating"` with `admin.enableSorting`. `apps/test`'s generated schema and types
include the index. `apps/www`'s generated files still need a `vex dev` run.

**Docs and scripts.** The new `guides/telemetry.mdx` lists every field sent, with a real
payload. The `packages/cli` README documents `vex telemetry`, and the
`packages/create-vexcms` README documents the `create` event and opt-out.
`scripts/verify-scaffold.mjs` and `scripts/vex-dev.mjs` set `VEX_TELEMETRY_DISABLED=1`, so
repo-internal runs never report. Template sync mirrored nothing: the receiver is
vexcms-internal, neither template ships `testimonials`, and existing drift belongs to
launch item N.

**Changesets.** `patch` changesets (alpha pre-mode) for `@vexcms/core` (`hideLogs`),
`@vexcms/cli` (telemetry, `vex telemetry`, the `.env.local` fix) and `create-vexcms` (the
`create` event). `@vexcms/telemetry` is private and gets none.
