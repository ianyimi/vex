# Handoff — VexCMS: Convex field-type coverage + field storage override (pre-0.1.0)

## Context

VexCMS is an Apache-2.0, TypeScript code-first headless CMS on Convex. TypeScript config files in
the project generate both the Convex schema and a real-time, role-based Next.js admin panel. It
is pre-0.1.0 (alpha on npm) with one maintainer. The GitHub repo is **public**, and `.agent/` is
tracked in it.

Before anything else: run `harness state`, then read `.agent/docs/harness-guide.md` and
`.agent/AGENTS.md`. The launch order lives in `.agent/docs/product/v0.1.0-launch-plan.md`
(task order, items 13–28) and `.agent/docs/product/v0.1.0-final-sprint.md` (§ 3b holds a ready
prompt per item). Follow the launch coordination board's rules in
`.agent/docs/product/launch-coordination.md`. Another session works on other launch items in
parallel, so take board locks for shared files.

## What to work on

**FT, Convex field-type coverage** (launch plan item 18; final sprint § 3b, "FT"). Add Vex
fields for the four Convex validator shapes that have none: `v.int64`, `v.bytes`, `v.record`,
and an object union as a single field. `v.any` and nested `v.object` are already covered by
`json()` (`packages/core/src/fields/json/validator.ts`) and `group()`
(`packages/core/src/fields/group/validator.ts`); don't rebuild them. Verify against the code which
shapes are genuinely uncovered before designing.

**Field storage override, to be decided in the interview.** A field option that stores a
different validator than the field's default, e.g. a `select()` stored as `v.string()`, or a
`number()` stored as `v.int64()` (bigint). It's described in `.agent/docs/product/backlog.md`
§ "Field storage override". The developer is open to including it before 0.1.0. Ask first
whether it ships with FT (one spec; `v.int64` might then come through `number()` instead of a new
field), ships as its own spec right after FT, or stays in the backlog.

## Decisions + constraints

- Use the `dev-spec` skill (interview, then spec), then implement with the `implement` skill.
- Mirror the closest shipped field type end to end: core validator, type generation, schema
  generation, React input + list cell, docs page.
- Missing field types block projects that use them from migrating to VexCMS, which is why this
  ships before 0.1.0.
