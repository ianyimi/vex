feat(core,react,next,better-auth,create-vexcms,www,test): run-through fixes, Draft Mode preview, disableCreate, static admin icons

The alpha.32 run-through (LI-19) found defects the tests missed. This fixes
them per the developer's decisions D1–D7, lands the public-presence release
notes draft, and carries docs and harness bookkeeping from the PP and QP
sessions.

**Admin error handling.** `DocumentSaveAction` caught nothing, so a failed
save looked like a successful one. It and six sibling sites (unpublish, row
delete, bulk delete, media delete, upload dropzone, upload form) now catch
the error and show one toast; the upload paths pass `errorToast: false` to
`useVexMutation` so a failure is not reported twice.

**Create dialog.** Fields scroll inside `ListViewCreateDocumentModal` and
read-only fields are left out.

**`disableCreate` (D2).** A new top-level collection flag, default `false`.
It hides every admin create entry point (list "+ New", `?createNew=true`,
the relationship picker's Create tab, `EmptyInput`'s Create button,
Duplicate) and makes the `vex:create` endpoint reject; `create()` called
directly from `@vexcms/core/server` still works. `@vexcms/better-auth`
sets it on every auth collection. Users arrive through sign-up; an
admin-made user row has no account or password.

**Generic auth merge.** `mergeAuthCollections` used to do
`{ ...authCol, ...userCol }`, so a project's own `users.ts` replaced the
adapter's whole `admin` object and dropped its settings. `defineCollection`
now keeps its raw input under a non-enumerable `COLLECTION_INPUT`, and the
merge deep-merges the two inputs and calls `defineCollection` once:
- Plain objects merge recursively; arrays, functions and plain values take
  the project's value; a project `undefined` never overwrites.
- Fields still follow the locked-field rule.
- `meta` is no longer dropped.
- A collection without the raw input (a spread copy) throws
  `VexAuthConfigError`.

The adapter gives the user collection short default columns (name, email,
roles/role, banned, createdAt). Generated schema and types for apps/www and
apps/test are byte-identical before and after.

**Draft Mode preview (D3).** A never-published page previewed as a 404. New
`createVexDraftModeRoute`, `LIVE_PREVIEW_COOKIE` and
`DRAFT_MODE_BYPASS_COOKIE` (`@vexcms/next/livePreview`):
- The apps' `/api/vex/live-preview` route checks the session and enables
  Draft Mode. `?disable=1`, or a signed-out request carrying a `redirect`,
  turns it off. Every redirect stays same-origin.
- `proxy.ts` hands `?vexLivePreview=1` off to that route unless both the
  marker cookie and Next's `__prerender_bypass` are present.
- `[slug]` skips `notFound()` while Draft Mode is on. Outside Draft Mode it
  stays prerendered.

**Admin icons back in the bundle.** On-demand icon loading (from the
tree-shakeable-packages commit) made every admin icon flash its placeholder
on refresh. `AdminLayout` now mounts an internal `IconComponentsProvider`
with `lucide-react`'s full `icons`, so `Icon` renders real SVG on the
server and on hydration. The `/admin` bundle grows; public pages keep
on-demand loading and `IconNodeProvider`.

**JSON editor fallback.** The textarea shown while CodeMirror loads now
carries `aria-required`. A slow chunk load had made the apps/test json-field
contract test fail intermittently ("marks the control as required").

**Media.** `@vexcms/file-storage-convex` media fields gain labels, and image
uploads store width/height measured in the browser (`measureImageDimensions`,
passed through core's media args).

**Theme script.** `buildThemeInitScript` (`@vexcms/react/server`) plus a
local `"use client"` `ThemeScript` in each app and template remove React's
dev-only script-tag error on 404 pages. The script is still in the server
HTML, so the theme still applies with no flash.

**CLI.** `loadConfig` filters the oidc-provider deprecation warning (D4;
upgrading Better Auth is in the backlog).

**Scaffolds.**
