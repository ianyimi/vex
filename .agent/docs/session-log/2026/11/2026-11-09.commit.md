fix(core): share COLLECTION_INPUT across duplicate core copies

The www Vercel deploy failed in `convex deploy`. Convex analyzes each pushed
module, and loading `footers.js` threw
`VexAuthConfigError: Auth collection "user" carries no raw defineCollection() input`.

Convex's bundler puts two copies of `@vexcms/core` in the same bundle. The app's
own imports resolve to core's source, while `@vexcms/better-auth`'s dist imports
resolve to core's dist. The adapter built the auth collections with the dist
copy's `defineCollection`, which stored the raw input under the dist copy's
`Symbol()`. `mergeAuthCollections` came from the source copy and read the
source copy's `Symbol()`, which is a different symbol, so it found nothing.

`COLLECTION_INPUT` is now `Symbol.for("vexcms.collectionInput")`. Every copy of
core shares the same key, so the merge works however many copies a bundle
holds. Published projects can also end up with duplicate installs.

Reproduced locally by bundling every non-node `apps/www/convex` module with
Convex's own esbuild options (`conditions: ["convex", "module"]`, splitting,
minified identifiers) and importing the output. `footers.js` threw before the
change and loads after. apps/test's bundle also loads.
