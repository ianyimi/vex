release: 0.1.0-alpha.31 — roles hardening, drafts out of sitemaps, admin accessibility pass, template re-sync

Merges `dev` into `master`, moving it from `0.1.0-alpha.21` to `0.1.0-alpha.31`. The range holds 44
commits. Release commits `0.1.0-alpha.22` through `0.1.0-alpha.30` are already on `dev`, and those
versions were published to npm from `dev`. `0.1.0-alpha.31` is new in this PR and covers
`910f2e7 feat: land launch infrastructure, a11y quality pass and public presence` (plus the
`232c03d hotfix: protect auth roles` follow-through).

**Already released on `dev` (alpha.22–alpha.30).** Live preview for singletons and globals with
server-resolved preview URLs; versions and drafts (history, publish, unpublish, draft reads, unified
versions API); React-free `@vexcms/core` with client wrappers in `@vexcms/react/client`; the
`richtext()` field and promote-in-place unpublish; the field input consistency pass;
backend-neutral query args (`where`, `withIndex`, `VexError`); domain-folder packages; list and edit
view overhauls and the `commitTs` field; live-demo admin content and auth-safe lists; build-time
telemetry, Plate 53, covered-route isolation and root action hides. Each has its own `release:`
commit and CHANGELOG section.

**Roles hardening (core, better-auth, create-vexcms).** Before, Better Auth wrote any `roles` value a
caller sent on `/sign-up/email` or `/update-user` straight onto the user row, so a visitor could
sign up as admin. Scaffolded `user.additionalFields.roles` now carries `input: false`.
`defineServerConfig` backs it with `assertRolesFieldNotClientWritable`: `VexAuthAdapter` gains
optional `clientWritableUserFields`, `betterAuthAdapter()` fills it from merged user fields where
`input !== false`, and a client-writable `access.userRolesField` throws `VexAuthConfigError` at
config time (`vex dev`). Documented in `guides/auth.mdx` and the better-auth README.

**Drafts out of sitemaps (core).** `vexServerApi`'s bound `publishedSlugs` dropped the bound
config/auth, so draft-only rows in `versions.drafts` collections reached `sitemap.xml` and
`generateStaticParams`. It now threads them into `find` like the other bound operations.

**Admin accessibility pass (react, richtext-plate).** WCAG 2.2 AA / APG fixes: sidebar actions,
multi-select chips, pagination, date/time pickers, resizable panels and data-table labels get
correct names, roles and keyboard support; data-table column resize is keyboard-operable
(arrows, Home/End) and capped at 90% of the container; array fields, timestamps, media and
relationship inputs and the richtext toolbar gain accessible names and status regions; dialogs set
initial focus; `ThemeProvider` applies the stored theme before paint in client-only renders.

**Templates (create-vexcms).** `base-nextjs` and `marketing-site` re-synced from `apps/test` and
`apps/www`: production-only CSP and security headers, root `not-found` pages, drafts and live
preview on marketing-site `pages`, and a session button in the site header. Template versions
synced to `~0.1.0-alpha.31`.

**Apps and repo (private, no package changes).** Live-demo hardening in `apps/www` (read-only access
suite, anonymous-user purge cron, proxy-attested auth rate limits via `AUTH_PROXY_SECRET`, `/tour`,
`/privacy`, Speed Insights), jsx-a11y/axe/Lighthouse/Nu CI gates, and public-presence files
(issue forms, labels, CONTRIBUTING, CODE_OF_CONDUCT, SECURITY, FUNDING, docs roadmap/compare/
accessibility pages).

BREAKING CHANGE: the large breaking changes in this range shipped in alpha.22–alpha.29; each
migration is in that version's CHANGELOG section (React-free core and `@vexcms/react/client`,
server-resolved preview URLs, versions API, `where`/`withIndex` query args, domain-folder packages,
edit/list view overhauls). alpha.31 adds one config-time check: if `access.userRolesField` names a
field end users can write through the auth adapter, `defineServerConfig` now throws
`VexAuthConfigError`. Migration: add `input: false` to that field in
`authSchema.user.additionalFields` (and the matching entry passed to `betterAuth()`), then redeploy.
