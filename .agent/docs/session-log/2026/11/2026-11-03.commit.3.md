feat(richtext-plate,react,next): upgrade to Plate 53, isolate admin from covering routes

**Plate 53.** The pnpm-workspace catalog moves `platejs` (53.5.2) and every
`@platejs/*` dependency to the 53 major, each at its latest 53.x; Plate
versions packages independently. `tsc` passed with zero source changes, so
every 52 → 53 break is runtime-only. They are recorded, probed and resolved
in the richtext spec's Step 6. The developer verified it live and Step 6 is
done.

**Blockquotes are containers.** `@platejs/basic-nodes` 53 stores a quote as
`blockquote > p`. `Toolbar.tsx`'s `BlockButton` now calls
`toggleBlock(type, { wrap: true })`; the old retag could turn a quote on but
never off. `createPlateEditor` does not normalize its initial value, and
toggling off a flat quote saved under 52 deleted its text. The new
`wrapFlatBlockquotes` converts those quotes on load. Plate's
`shouldNormalizeEditor` was rejected because it emits the normalized
document on mount, which dirties the form and autosaves on open.

**Static renderer.** `@platejs/list` 53.3.13 moved the indent-list
`<ul>/<ol><li>` wrapper into the React-only `ListPlugin`. `RichText` now
configures `BaseListPlugin` with `renderIndentListStatic`, so bullets render
on the front end again. Two markup fixes go with it: `ParagraphElementStatic`
renders a list item as a styled `<div>`, and `LinkElementStatic` renders its
`SlateElement` `as="a"`. Together they remove the `<p><ul>` / `<p><div>`
hydration errors on rendered pages and in the list-view peek panel, and links
stay inline.

**Sticky toolbar.** `position: sticky` pins below a scroll container's
padding, so the toolbar stuck 16px low under the admin form's `pt-4`. Its
`top` now reads `--vex-form-sticky-top`. `CollectionEditView` and
`GlobalEditView` set it to `-1rem` on all four form scroll areas.

**Intercepting routes no longer interfere with the admin.** The root `@auth`
sign-in modal is a Next intercepting route. It swaps the URL while the admin
stays mounted underneath, so every URL reader in the admin read the modal's
URL instead: the list dropped its filter, view and search and loaded the
wrong rows, a top-level tabs field reset, and the sidebar lost its active
collection.

New optional `FrameworkComponents.useIsRouteCovered`. `@vexcms/next`
implements it as `useNextIsRouteCovered`: true while `usePathname()` is
outside the configured `basePath`, never with `basePath: "/"`. While covered:
- `useLastUncoveredValue` keeps the last admin value in
  `useListViewUrlState`, `AdminTopNav` and the tabs field;
- `NextAdminLayoutClient` keeps the last admin pathname;
- list URL writes are dropped, so Escape closing the modal no longer also
  closes the peek panel or writes onto the modal's URL;
- the `Cmd/Ctrl+B` sidebar shortcut stands down.

`useNextNavigationBlocker` lets links marked `COVERING_ROUTE_LINK_ATTRIBUTE`
(the "Sign in" button) through. It also treats a `popstate` that lands back
on its own sentinel as a return, so closing the modal over a dirty edit view
no longer asks Stay/Leave.

**Sign-in return URL.** It now carries the page's full query (filter, sort,
search, view, tab, peek), not just `?view=`. The developer decided this,
reversing the alpha.29 rule; the page itself handles a URL the new identity
can't see. The query comes from the new optional
`FrameworkComponents.useSearchParams` (`useNextSearchParams`), which is
SSR-safe and follows shallow `nuqs` writes.

**Read-only blocks.** `BlocksField`'s "Collapse all"/"Expand all" stay
enabled on a read-only field, matching arrays. The change came from another
agent session.

**Tests.** `richtext-plate` gains a vitest setup (jsdom).
- `RichText.test.tsx` and `PlateEditorField.test.tsx` run a real 52-saved
  `posts.body` fixture through 53: rendering, quote conversion, no change on
  open, valid nesting.
- `useListViewUrlState.test.tsx` and the `AdminTopNav` shell suite cover the
  covered-route freeze and the full-query return URL.
- The blocker tests cover the covering-route link and the return-onto-sentinel
  case. Its existing back-press tests now move history the way a real back
  press does.
- `DataTablePageSizeSelect.test.tsx` waits with `findByRole`, fixing a
  load-sensitive race.

**Docs.** `guides/framework-adapters.md` gains Step 11 on covering routes,
and its Step 10 `redirectTo` wording is corrected. The launch plan marks D
step 6 done. Changesets: `richtext-plate-53`, `admin-covered-route-url-state`.
