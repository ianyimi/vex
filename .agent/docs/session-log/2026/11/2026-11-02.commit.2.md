docs(roadmap,www): release-audit drift fixes — access-rule wording, shipped statuses

Release audit for 0.1.0-alpha.28 (master..dev) found three roadmap surfaces drifted
from shipped code.

**Access-rule wording.** `{ constraints }` rules were removed by the backend-neutral
query args work (4d504e7) in favor of `withIndex` ranges and `where` predicates, but
docs `roadmap.md` (two Shipped lines), the www `Roadmap` block config, and three
`convex/seed.ts` passages (Lock bullet, access-control Split block body + bullet)
still described access rules as "constraints". All now name `withIndex`/`where`.

**Shipped statuses.** The edit-view overhaul (30b4c10) and list-view overhaul
(b937b2b) left stale in-progress/planned entries behind: `roadmap.md` gains a Shipped
"Edit-view overhaul" line (replacing the 🔄 "Edit-view improvements" entry — guard,
duplicate document, and duplicate block all shipped) and drops the completed
"Data-table integrity pass" (launch plan § A ✅, covered by the shipped DataTable and
List views lines); the www seed flips "Edit-View Overhaul" and "Data-Table Integrity
& Config Honesty" to shipped and its production-ready FAQ now counts the edit-view
overhaul as landed (remaining: field input consistency pass, then the responsive
pass); the Roadmap block config flips "Versioning & Drafts" (shipped since alpha.24)
from in-progress to shipped.

The seed's edit-view description drops "a validation summary that jumps to the
failing field" — never built (no such surface exists in @vexcms/react); the
slots/actions-menu sentence replaces it. These www copy changes are marketing-only
and not mirrored to templates.
