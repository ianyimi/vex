# 2026-11-25-adopt-existing-tables — Spec

## Overview

Launch plan item 19 (ADOPT, `v0.1.0-final-sprint.md` § 3b), after FT (item 18) shipped the last
four validator shapes. Two deliverables: a docs guide for adopting an existing Convex table today
(collection slug = table name, `timestamps: false`, no drafts, every Convex validator mapped to the
field that describes it), and a CLI warning when `convex/schema.ts` hand-writes a table or index
that the generated schema also defines. Agent-implemented (developer delegated, 2026-11-25).

Verified before design (2026-11-25): `syncSchemaImports` never replaces a hand-written table. It
added a generated export only when the name appeared nowhere in `schema.ts`
(`schemaContent.includes(name)`), so a hand-written `posts: defineTable(...)` silently won and the
generated `posts` was never wired. The same substring test skipped a new table whose name only
appeared inside another identifier, a field or a comment (`tags` vs a `tags:` field, `team` vs
`teamMember`). The templates rely on hand-written tables on purpose: `vex_globals`, the five orgs
tables (literal keys) and `[TABLE_SLUG_ACCOUNTS]` (computed key).

## Design Decisions

1. **Warn only when the copies differ** (developer). A literal hand-written key that matches a
   generated table warns only when fields or indexes differ by name or definition. Why: the
   marketing template and `apps/www` hand-write a `vex_globals` identical to the generated one;
   warning on every collision would print on every run of every scaffold.
2. **Comparison is textual and normalized**: comments, whitespace, quote style, trailing commas,
   field/index order, `v.float64()`≡`v.number()`, `v.nullable(x)`≡`v.union(x, v.null())`. Why: no
   code evaluation (no side effects, no alias/env setup), and these are the spellings the generator
   and Prettier actually produce. Other equivalent spellings show as different (documented).
3. **Two collision kinds.** `"table"`: a hand-written `defineTable` (or unreadable value) under a
   generated table's name. `"index"`: `.index(...)` chained onto the imported generated table
   reusing a generated index name — Convex's codegen rejects it ("Duplicate index name", convex
   1.49 `cli/codegen_templates/dataModel.js`). This is the "index of the same name" case from the
   launch prompt.
4. **Key-based wiring** (developer). A generated table counts as listed only when it is a
   `defineSchema` key. Why: fixes the substring false positives; the parser exists for the warning
   anyway.
5. **Computed keys resolve for wiring, never for the warning** (developer: skip computed keys in
   the warning). `[X]` resolves when `X` is a string literal, a local `const`, or an
   `export const` in a module `schema.ts` imports by name (resolved through the CLI's existing jiti
   resolver, `createResolver`, which honours tsconfig `paths`). Why: without it, key-based wiring
   would add a duplicate `account` entry to every scaffold (all hand-write
   `[TABLE_SLUG_ACCOUNTS]`). Unresolvable keys and spreads fall back to the old substring test, so
   nothing is ever added twice.
6. **Once per table per process** (developer). Keyed by schema path + table; reprints when the
   text changes or after the collision clears and returns. Why: `vex dev` re-syncs on every
   config save, and `generateAndWrite` calls `syncSchemaImports` twice per run.
7. **Never modify hand-written entries.** The CLI warns; the user swaps. Mirrors INIT's rule
   (final-sprint § 3c: "Never modify existing Convex tables or schema entries").
8. **Guide at `guides/adopt-existing-tables.mdx`** (developer), title "Adopt an existing Convex
   table", URL `https://docs.vexcms.dev/guides/adopt-existing-tables/`. The Guides sidebar is
   autogenerated, so `astro.config.mjs` is untouched (no lock).
9. **Template `account` index drift → backlog only** (developer). The templates' hand-written
   `account` has 2 of the generated table's 5 indexes.

Mirrors: `traceImports.ts` (jiti `esmResolve` for import specifiers), the existing regex-based
`addToImport`/`removeFromImport` text editing in `generateSchema.ts`, the field pages' "Storage
override" sections (linked, not duplicated).

## Out of Scope

- Generating a collection from an existing `defineTable` (AD-2), a table name different from the
  slug (AD-1), read-only collections (AD-4), a raw-validator field (AD-3).
- Changing the templates' or apps' hand-written tables (backlog).
- Auto-replacing a hand-written table with the generated import.
- Evaluating `schema.ts` to compare real `TableDefinition`s.
- Fixing `select.mdx`'s stale "stores `v.array(v.string())`" line (backlog).

#### packages/cli/src/lib/schemaSource.ts

```ts
/**
 * Text-level reader for `convex/schema.ts` and the generated `vex.schema.ts`.
 *
 * `syncSchemaImports` uses it to tell which tables `schema.ts` already lists, and
 * to compare a hand-written table against the generated table of the same name.
 * Nothing here evaluates the user's code: it reads source text, skipping strings
 * and comments, so it sees literal keys and literal `defineTable({...})` calls only.
 */

/** Docs page linked from every collision warning. */
export const ADOPT_GUIDE_URL = "https://docs.vexcms.dev/guides/adopt-existing-tables/";

/** One top-level entry of the `defineSchema({ ... })` object. */
export type SchemaEntry =
  /** `posts,` — the imported generated table. */
  | { kind: "shorthand"; name: string }
  /** `posts: <value>` or `"posts": <value>`. */
  | { kind: "property"; name: string; value: string }
  /** `[TABLE_SLUG_POSTS]: <value>` — the key is an expression, not a name. */
  | { kind: "computed"; key: string; value: string }
  /** A spread (`...tables`) or anything else that names no table by itself. */
  | { kind: "opaque" };

/** The parts of a `defineTable(...)` call the collision check compares. */
export interface TableShape {
  /** Field name → compacted validator source (`v.optional(v.string())`). */
  fields: Map<string, string>;
  /** Index name → compacted definition, across `.index`, `.searchIndex` and `.vectorIndex`. */
  indexes: Map<string, string>;
}

/** How a hand-written table differs from the generated one, by name. Every list is sorted. */
export interface TableDiff {
  fieldsOnlyInSchema: string[];
  fieldsOnlyGenerated: string[];
  fieldsChanged: string[];
  indexesOnlyInSchema: string[];
  indexesOnlyGenerated: string[];
  indexesChanged: string[];
}

/** A table or index in `schema.ts` that the generated schema also defines. */
export type SchemaCollision =
  /**
   * `schema.ts` defines the table by hand and the definitions differ. Convex uses
   * the hand-written one. `diff` is `undefined` when the hand-written value is not a
   * readable `defineTable({...})` call, so the two can't be compared.
   */
  | { kind: "table"; table: string; diff: TableDiff | undefined }
  /**
   * `schema.ts` chains indexes onto the imported generated table, and some share a
   * name with a generated index. Convex rejects duplicate index names.
   */
  | { kind: "index"; table: string; indexes: string[] };

const IDENTIFIER_CHAR = /[\w$]/;

/**
 * Index just past the string or comment that starts at `index`, or `index` itself
 * when none starts there.
 *
 * @param text - Source text.
 * @param index - Position to test.
 * @returns The first position after the string or comment.
 */
function skipStringOrComment(text: string, index: number): number {
  const char = text[index];
  if (char === "/" && text[index + 1] === "/") {
    const end = text.indexOf("\n", index);
    return end === -1 ? text.length : end;
  }
  if (char === "/" && text[index + 1] === "*") {
    const end = text.indexOf("*/", index + 2);
    return end === -1 ? text.length : end + 2;
  }
  if (char === '"' || char === "'" || char === "`") {
    let cursor = index + 1;
    while (cursor < text.length && text[cursor] !== char) {
      cursor += text[cursor] === "\\" ? 2 : 1;
    }
    return Math.min(cursor + 1, text.length);
  }
  return index;
}

/**
 * Drops comments and whitespace and turns single-quoted strings into
 * double-quoted ones, so two sources that differ only in formatting compact to
 * the same text. One space survives between two identifier characters
 * (`export const`), and string contents are kept as written.
 *
 * @param text - Source text.
 * @returns The compacted source.
 */
function compact(text: string): string {
  let out = "";
  let index = 0;
  let gap = false;
  while (index < text.length) {
    const char = text[index]!;
    const isComment = char === "/" && (text[index + 1] === "/" || text[index + 1] === "*");
    if (isComment || /\s/.test(char)) {
      // Whitespace and comments separate tokens; keep one space only where two
      // identifier characters would otherwise merge (`export const`).
      index = isComment ? skipStringOrComment(text, index) : index + 1;
      gap = true;
      continue;
    }
    if (gap && IDENTIFIER_CHAR.test(char) && IDENTIFIER_CHAR.test(out[out.length - 1] ?? "")) {
      out += " ";
    }
    gap = false;
    const next = skipStringOrComment(text, index);
    if (next !== index) {
      const inner = text.slice(index + 1, next - 1);
      out += char === "'" && !inner.includes('"') ? `"${inner}"` : text.slice(index, next);
      index = next;
      continue;
    }
    out += char;
    index++;
  }
  return out;
}

/**
 * Position of the bracket closing the `(`, `{` or `[` at `open`.
 *
 * @param text - Source text.
 * @param open - Position of the opening bracket.
 * @returns The closing bracket's position, or `-1` when it never closes.
 */
function findClose(text: string, open: number): number {
  let depth = 0;
  let index = open;
  while (index < text.length) {
    const next = skipStringOrComment(text, index);
    if (next !== index) {
      index = next;
      continue;
    }
    const char = text[index]!;
    if (char === "(" || char === "{" || char === "[") depth++;
    else if (char === ")" || char === "}" || char === "]") {
      depth--;
      if (depth === 0) return index;
    }
    index++;
  }
  return -1;
}

/**
 * Splits compacted text at its depth-0 commas — the entries of an object
 * literal body or the arguments of a call.
 *
 * @param text - Compacted source between the brackets.
 * @returns The non-empty parts, trimmed.
 */
function splitTopLevel(text: string): string[] {
  const parts: string[] = [];
  let depth = 0;
  let start = 0;
  let index = 0;
  while (index < text.length) {
    const next = skipStringOrComment(text, index);
    if (next !== index) {
      index = next;
      continue;
    }
    const char = text[index]!;
    if (char === "(" || char === "{" || char === "[") depth++;
    else if (char === ")" || char === "}" || char === "]") depth--;
    else if (char === "," && depth === 0) {
      parts.push(text.slice(start, index));
      start = index + 1;
    }
    index++;
  }
  parts.push(text.slice(start));
  return parts.map((part) => part.trim()).filter((part) => part.length > 0);
}

/**
 * Normalizes a compacted validator so equivalent spellings compare equal:
 * trailing commas go, `v.float64()` becomes `v.number()` and `v.nullable(x)`
 * becomes `v.union(x,v.null())` (Convex treats each pair as the same validator).
 *
 * @param validator - Compacted validator source.
 * @returns The normalized source.
 */
function normalizeValidator(validator: string): string {
  let text = validator.replace(/,(?=[)}\]])/g, "").replace(/\bv\.float64\(\)/g, "v.number()");
  const nullable = "v.nullable(";
  for (let at = text.indexOf(nullable); at !== -1; at = text.indexOf(nullable)) {
    const open = at + nullable.length - 1;
    const close = findClose(text, open);
    if (close === -1) break;
    text = `${text.slice(0, at)}v.union(${text.slice(open + 1, close)},v.null())${text.slice(close + 1)}`;
  }
  return text;
}

/**
 * Reads the `.index(...)`, `.searchIndex(...)` and `.vectorIndex(...)` calls in
 * compacted source.
 *
 * @param code - Compacted source of a table expression (or its chain).
 * @returns Index name → normalized definition, prefixed by the index kind.
 */
function readIndexes(code: string): Map<string, string> {
  const indexes = new Map<string, string>();
  const pattern = /\.(index|searchIndex|vectorIndex)\(/g;
  for (let match = pattern.exec(code); match !== null; match = pattern.exec(code)) {
    const open = match.index + match[0].length - 1;
    const close = findClose(code, open);
    if (close === -1) break;
    const [nameSource = "", ...rest] = splitTopLevel(code.slice(open + 1, close));
    const name = /^"([^"]*)"$/.exec(nameSource)?.[1] ?? nameSource;
    indexes.set(name, `${match[1]}:${normalizeValidator(rest.join(","))}`);
    pattern.lastIndex = close;
  }
  return indexes;
}

/**
 * Lists the top-level entries of the `defineSchema({ ... })` object.
 *
 * @param props - Input props.
 * @param props.source - Source text of `convex/schema.ts`.
 * @returns The entries in source order, or `undefined` when the file has no
 *   `defineSchema({` object literal (e.g. `defineSchema(tables)`).
 */
export function readSchemaEntries(props: { source: string }): SchemaEntry[] | undefined {
  const code = compact(props.source);
  const match = /\bdefineSchema\(\{/.exec(code);
  if (match === null) return undefined;
  const open = match.index + match[0].length - 1;
  const close = findClose(code, open);
  if (close === -1) return undefined;

  return splitTopLevel(code.slice(open + 1, close)).map((entry): SchemaEntry => {
    if (entry.startsWith("[")) {
      const keyClose = findClose(entry, 0);
      if (keyClose !== -1 && entry[keyClose + 1] === ":") {
        return { kind: "computed", key: entry.slice(1, keyClose), value: entry.slice(keyClose + 2) };
      }
      return { kind: "opaque" };
    }
    const quoted = /^"([^"]+)":([\s\S]*)$/.exec(entry);
    if (quoted) return { kind: "property", name: quoted[1]!, value: quoted[2]! };
    const named = /^([A-Za-z_$][\w$]*):([\s\S]*)$/.exec(entry);
    if (named) return { kind: "property", name: named[1]!, value: named[2]! };
    if (/^[A-Za-z_$][\w$]*$/.test(entry)) return { kind: "shorthand", name: entry };
    return { kind: "opaque" };
  });
}

/**
 * Reads the fields and indexes of a `defineTable({ ... })` expression.
 *
 * @param props - Input props.
 * @param props.source - Source text of the table expression, chained indexes included.
 * @returns The table's shape, or `undefined` when it holds no `defineTable({` object
 *   literal or the object has an entry that isn't `key: validator` (a spread).
 */
export function readTableShape(props: { source: string }): TableShape | undefined {
  const code = compact(props.source);
  const match = /\bdefineTable\(\{/.exec(code);
  if (match === null) return undefined;
  const callOpen = match.index + match[0].length - 2;
  const objectOpen = callOpen + 1;
  const objectClose = findClose(code, objectOpen);
  const callClose = findClose(code, callOpen);
  if (objectClose === -1 || callClose === -1) return undefined;

  const fields = new Map<string, string>();
  for (const entry of splitTopLevel(code.slice(objectOpen + 1, objectClose))) {
    const field = /^(?:"([^"]+)"|([A-Za-z_$][\w$]*)):([\s\S]+)$/.exec(entry);
    if (!field) return undefined;
    fields.set((field[1] ?? field[2])!, normalizeValidator(field[3]!));
  }
  return { fields, indexes: readIndexes(code.slice(callClose + 1)) };
}

/**
 * Splits the generated `vex.schema.ts` into its exported tables.
 *
 * @param props - Input props.
 * @param props.source - Generated schema source.
 * @returns Export name → the table expression's source text.
 */
export function readGeneratedTables(props: { source: string }): Map<string, string> {
  const code = compact(props.source);
  const tables = new Map<string, string>();
  const pattern = /\bexport const ([A-Za-z_$][\w$]*)=/g;
  const matches = [...code.matchAll(pattern)];
  matches.forEach((match, position) => {
    const start = match.index! + match[0].length;
    const end = matches[position + 1]?.index ?? code.length;
    tables.set(match[1]!, code.slice(start, end).replace(/;\s*$/, ""));
  });
  return tables;
}

/**
 * Names present in `a` and missing from `b`, sorted.
 *
 * @param a - The map whose keys are listed.
 * @param b - The map the keys are checked against.
 * @returns The sorted names.
 */
function keysMissingFrom(a: Map<string, string>, b: Map<string, string>): string[] {
  return [...a.keys()].filter((key) => !b.has(key)).sort();
}

/**
 * Compares a hand-written table with the generated table of the same name.
 *
 * @param props - Input props.
 * @param props.schema - The hand-written table from `schema.ts`.
 * @param props.generated - The generated table.
 * @returns The differences, or `undefined` when the two match.
 */
function diffTables(props: { schema: TableShape; generated: TableShape }): TableDiff | undefined {
  const { schema, generated } = props;
  const diff: TableDiff = {
    fieldsOnlyInSchema: keysMissingFrom(schema.fields, generated.fields),
    fieldsOnlyGenerated: keysMissingFrom(generated.fields, schema.fields),
    fieldsChanged: [...schema.fields.keys()]
      .filter((key) => generated.fields.has(key) && generated.fields.get(key) !== schema.fields.get(key))
      .sort(),
    indexesOnlyInSchema: keysMissingFrom(schema.indexes, generated.indexes),
    indexesOnlyGenerated: keysMissingFrom(generated.indexes, schema.indexes),
    indexesChanged: [...schema.indexes.keys()]
      .filter((key) => generated.indexes.has(key) && generated.indexes.get(key) !== schema.indexes.get(key))
      .sort(),
  };
  return Object.values(diff).some((names) => names.length > 0) ? diff : undefined;
}

/**
 * Finds the tables and indexes `schema.ts` writes by hand that the generated schema
 * also defines. Only literal keys are checked: a computed key (`[TABLE_SLUG_X]`)
 * can't be named from text, so it is never reported.
 *
 * - `posts: defineTable({...})` with a generated `posts` → a `"table"` collision,
 *   unless the two definitions match (fields and indexes by name, validators
 *   compared after formatting is normalized).
 * - `posts: posts.index("by_slug", ...)` (indexes chained onto the import) → an
 *   `"index"` collision for each chained name the generated table also has.
 * - `posts,` and `posts: posts` are the import itself, never a collision.
 *
 * @param props - Input props.
 * @param props.entries - `readSchemaEntries` output for `schema.ts`.
 * @param props.generatedTables - `readGeneratedTables` output for the generated schema.
 * @returns One collision per affected table, in `schema.ts` order.
 */
export function findSchemaCollisions(props: {
  entries: readonly SchemaEntry[];
  generatedTables: ReadonlyMap<string, string>;
}): SchemaCollision[] {
  const collisions: SchemaCollision[] = [];
  for (const entry of props.entries) {
    if (entry.kind !== "property") continue;
    const generatedSource = props.generatedTables.get(entry.name);
    if (generatedSource === undefined || entry.value === entry.name) continue;
    const generated = readTableShape({ source: generatedSource });
    if (generated === undefined) continue;

    if (entry.value.startsWith(`${entry.name}.`)) {
      const duplicates = [...readIndexes(entry.value.slice(entry.name.length)).keys()]
        .filter((name) => generated.indexes.has(name))
        .sort();
      if (duplicates.length > 0) {
        collisions.push({ kind: "index", table: entry.name, indexes: duplicates });
      }
      continue;
    }

    const schema = readTableShape({ source: entry.value });
    if (schema === undefined) {
      collisions.push({ kind: "table", table: entry.name, diff: undefined });
      continue;
    }
    const diff = diffTables({ schema, generated });
    if (diff !== undefined) collisions.push({ kind: "table", table: entry.name, diff });
  }
  return collisions;
}

/**
 * Builds the warning text for one collision.
 *
 * @param props - Input props.
 * @param props.collision - The collision to describe.
 * @param props.schemaFile - Display path of the hand-written schema (`convex/schema.ts`).
 * @param props.generatedFile - Display path of the generated schema (`convex/vex.schema.ts`).
 * @returns A multi-line message for `logger.warn`.
 */
export function formatSchemaCollision(props: {
  collision: SchemaCollision;
  schemaFile: string;
  generatedFile: string;
}): string {
  const { collision, schemaFile, generatedFile } = props;
  if (collision.kind === "index") {
    const names = collision.indexes.map((name) => `"${name}"`).join(", ");
    return [
      `${schemaFile} adds index ${names} to the generated "${collision.table}" table, and ${generatedFile} already defines ${collision.indexes.length === 1 ? "an index" : "indexes"} with that name.`,
      "Convex rejects duplicate index names. Remove or rename the hand-written .index(...) call.",
      `See ${ADOPT_GUIDE_URL}`,
    ].join("\n");
  }

  const lines = [
    `${schemaFile} defines table "${collision.table}" by hand, and ${generatedFile} generates a different "${collision.table}" table. Convex uses the hand-written one; the generated table is not wired in.`,
  ];
  if (collision.diff === undefined) {
    lines.push("  The hand-written table is not a plain defineTable({...}) call, so the two can't be compared.");
  } else {
    const rows: [string, string[]][] = [
      [`fields only in ${schemaFile}`, collision.diff.fieldsOnlyInSchema],
      [`fields only in ${generatedFile}`, collision.diff.fieldsOnlyGenerated],
      ["fields with different validators", collision.diff.fieldsChanged],
      [`indexes only in ${schemaFile}`, collision.diff.indexesOnlyInSchema],
      [`indexes only in ${generatedFile}`, collision.diff.indexesOnlyGenerated],
      ["indexes with different definitions", collision.diff.indexesChanged],
    ];
    for (const [label, names] of rows) {
      if (names.length > 0) lines.push(`  ${label}: ${names.join(", ")}`);
    }
  }
  lines.push(
    `Describe these differences in the "${collision.table}" collection, then replace the hand-written entry with the generated import. See ${ADOPT_GUIDE_URL}`,
  );
  return lines.join("\n");
}
```

```ts
 * Collision warnings already printed by this process, keyed by schema path and
 * table. `vex dev` re-runs the sync on every config change; a warning prints
 * again only when its text changes, or after the collision went away and came back.

/**
 * Resolves a computed `defineSchema` key to the table name it holds, when that
 * name is a string literal: `["posts"]`, a `const` in `schema.ts`, or an
 * `export const` in a module `schema.ts` imports by name.
 *
 * @param props - Input props.
 * @param props.key - Source of the key expression, between the brackets.
 * @param props.schemaPath - Absolute path of `convex/schema.ts`.
 * @param props.schemaContent - Source of `convex/schema.ts`.
 * @returns The table name, or `undefined` when the key isn't a literal the CLI can follow.
 */
function resolveComputedKey(props: {
  key: string;
  schemaPath: string;
  schemaContent: string;
}): string | undefined {
  const { key, schemaPath, schemaContent } = props;
  const literal = /^"([^"]*)"$/.exec(key);
  if (literal) return literal[1];
  if (!/^[A-Za-z_$][\w$]*$/.test(key)) return undefined;

  const constValue = (source: string, name: string, exported: boolean) =>
    new RegExp(
      `${exported ? "\\bexport\\s+" : "\\b"}const\\s+${name.replace(/\$/g, "\\$")}\\s*(?::[^=]+)?=\\s*(["'\`])([^"'\`$]*)\\1`,
    ).exec(source)?.[2];

  const local = constValue(schemaContent, key, false);
  if (local !== undefined) return local;

  for (const match of schemaContent.matchAll(/import\s+(?:type\s+)?\{([^}]*)\}\s*from\s*["']([^"']+)["']/g)) {
    for (const specifier of match[1]!.split(",")) {
      const [imported, localName = imported] = specifier.trim().split(/\s+as\s+/);
      if (localName?.trim() !== key || !imported) continue;
      try {
        let resolved = createResolver(schemaPath).esmResolve(match[2]!, { parentURL: schemaPath }) as string;
        if (resolved.startsWith("file://")) resolved = new URL(resolved).pathname;
        return constValue(readFileSync(resolved, "utf-8"), imported.trim(), true);
      } catch {
        return undefined;
      }
    }
  }
  return undefined;
}

/**
 * Warns about tables and indexes `schema.ts` writes by hand that the generated
 * schema also defines, once per table per process (see {@link printedCollisionWarnings}).
 *
 * @param props - Input props.
 * @param props.schemaPath - Absolute path of `convex/schema.ts`.
 * @param props.entries - `readSchemaEntries` output for it.
 * @param props.vexContent - Generated schema source.
 * @param props.outputRelPath - The generated schema's configured path (`/convex/vex.schema.ts`).
 */
function warnSchemaCollisions(props: {
  schemaPath: string;
  entries: readonly SchemaEntry[];
  vexContent: string;
  outputRelPath: string;
}) {
  const collisions = findSchemaCollisions({
    entries: props.entries,
    generatedTables: readGeneratedTables({ source: props.vexContent }),
  });
  const current = new Set<string>();
  for (const collision of collisions) {
    const key = `${props.schemaPath}\0${collision.table}`;
    current.add(key);
    const message = formatSchemaCollision({
      collision,
      schemaFile: "convex/schema.ts",
      generatedFile: props.outputRelPath.replace(/^\//, ""),
    });
    if (printedCollisionWarnings.get(key) === message) continue;
    printedCollisionWarnings.set(key, message);
    logger.warn(message);
  }
  for (const key of printedCollisionWarnings.keys()) {
    if (key.startsWith(`${props.schemaPath}\0`) && !current.has(key)) printedCollisionWarnings.delete(key);
  }
}
```

#### apps/docs/src/content/docs/guides/adopt-existing-tables.mdx

``````mdx
---
title: Adopt an existing Convex table
description: Point a VexCMS collection at a Convex table that already holds data, without migrating it — a collection whose slug matches the table, every Convex validator mapped to the field that describes it.
---

If your Convex app already has a table full of documents, a VexCMS collection can take it over
without moving or rewriting any data. You describe the table with fields until the schema VexCMS
generates matches the `defineTable` you wrote by hand, then swap one for the other. Your existing
queries and mutations keep working, because the table, its documents and its index names stay the
same.

This guide assumes VexCMS already runs in your app: `vex dev` starts and `/admin` loads (see the
[quickstart](/guides/quickstart/)). Try it first on a dev deployment that holds a copy of your
data (`npx convex export`, then `npx convex import` into the dev deployment).

## How adoption works

- **The collection's `slug` is the table name.** There is no option to point a collection at a
  table with a different name, so the slug must match the `defineSchema` key exactly.
- **`vex dev` generates the table into `convex/vex.schema.ts`.** As long as `convex/schema.ts`
  still defines the table by hand, Convex keeps using your hand-written definition and the
  generated one is not wired in.
- **`vex dev` compares the two.** When they differ, it prints which fields and indexes differ, so
  you know what to change before you swap.
- **When you swap, Convex checks every document.** On the next push, Convex validates each
  existing document against the generated table. A document that doesn't fit fails the push and
  is named in the error. Nothing is written, so your data is safe either way.

## 1. Define the collection

```ts title="src/vexcms/collections/posts.ts"
import { defineCollection, text } from "@vexcms/core"

export const posts = defineCollection({
  slug: "posts", // the existing table's name
  timestamps: false,
  admin: { useAsTitle: "title" },
  fields: {
    title: text({ required: true }),
    // …one field per column, see the table below
  },
})
```

Add it to `collections` in `vex.config.ts`, and give it access rules like any other collection
(see [access control](/guides/access-control/)).

**`timestamps: false`.** By default every collection carries an `updatedAt` field
(`v.optional(v.commitTs())`) with a `by_updatedAt` index, and VexCMS stamps it on every write.
Turning timestamps off keeps the table's shape as it is.

**No drafts.** Leave `versions.drafts` off. Drafts add four `vex_` fields, and published reads
filter on `vex_status`, which no existing document has yet. To turn drafts on later, follow
[Migrating off a hand-rolled status field](/guides/versioning-and-drafts/#migrating-off-a-hand-rolled-status-field),
which stamps every existing document as published.

## 2. Map each validator to a field

Fields are optional unless you set `required: true`. So a bare validator becomes a field with
`required: true`, and `v.optional(x)` becomes the field for `x` with no `required` option.

| Convex validator | VexCMS field | Notes |
| --- | --- | --- |
| `v.string()` | `text()` | `textarea()`, `email()`, `url()` and `color()` store `v.string()` too. Pick the one with the input you want. |
| `v.number()`, `v.float64()` | `number()` | A millisecond timestamp can use [`date()`](/fields/date/), which also stores `v.number()`. |
| `v.int64()` | `number({ schema: { validator: "int64" } })` | Values are `bigint`. See [storage override](/fields/number/#storage-override). |
| `v.boolean()` | [`checkbox()`](/fields/checkbox/) | |
| `v.bytes()` | [`bytes()`](/fields/bytes/) | Values are `ArrayBuffer`. |
| `v.any()` | [`json()`](/fields/json/) | |
| `v.object({ … })` | [`group({ fields: { … } })`](/fields/group/) | Map each property the same way, recursively. |
| `v.record(v.string(), x)` | [`keyValue({ value: … })`](/fields/key-value/) | `value` is the field for `x`. |
| `v.record(v.id("t"), x)` | `keyValue({ keys: { collection: { slug: "t" } }, value: … })` | `t` must be a collection. |
| `v.union(v.object({ kind: v.literal("a"), … }), …)` | [`variant({ discriminator: "kind", variants: { … } })`](/fields/variant/) | An object union whose members share a literal key. Each `variants` key is that literal. |
| `v.union(v.string(), v.number())` | `variant({ variants: { label: text(), amount: number() } })` | A primitive union. Members must have distinct runtime kinds. |
| `v.id("t")` | `relationship({ collection: { slug: "t" }, schema: { validator: "id" } })` | `t` must be a collection. For a media collection, use `upload({ to: "t", schema: { validator: "id" } })`. See [storage override](/fields/relationship/#storage-override). |
| `v.array(v.id("t"))` | `relationship({ collection: { slug: "t" }, hasMany: true })` | The default storage. |
| `v.union(v.literal("a"), v.literal("b"))` | `select({ options: […], schema: { validator: "literal" } })` | A single option stores a bare `v.literal("a")`. See [storage override](/fields/select/#storage-override). |
| `v.array(v.union(v.literal("a"), …))` | `select({ options: […], hasMany: true })` | The default storage. |
| `v.string()` holding one of a known set | `select({ options: […], schema: { validator: "string" } })` | Editors get a dropdown; stored values may still be off the list. |
| `v.array(x)` | [`array({ items: … })`](/fields/array/) | `items` is the field for `x`. |
| `v.array(v.object({ … }))` | `array({ items: group({ fields: { … } }) })` | The generated validator adds `id: v.optional(v.string())` to each item. Existing items still validate, because the key is optional, but `vex dev` lists the field as different until you swap. |
| `v.nullable(x)`, `v.union(x, v.null())` | the field for `x` with `nullable: true` | See [nullable values](/fields/text/#nullable-values). |

### When no field matches exactly

A few shapes have no field that stores exactly the same validator:

- `v.null()` on its own.
- `v.id("_storage")`, or an id into a table that isn't a VexCMS collection.
- An object union whose members share no literal key.
- A union whose members share a runtime kind, such as `v.union(v.literal("a"), v.string())`.
- An array of objects without the `blockType` key that [`blocks()`](/fields/blocks/) stores. Don't
  use `blocks()` for an existing column: it requires keys your documents don't have.

For these, pick a field whose validator accepts every value already stored. `json()` stores
`v.any()`, which accepts anything. `text()` stores `v.string()`, which accepts any id. The
generated table is then looser than yours: the swap still works, and `vex dev` keeps listing
that field as different until you swap.

## 3. Keep your indexes

Your existing functions call `withIndex` with your index names, so declare each one under the
same name:

- **One field:** `index: "by_slug"` on the field.
- **Several fields:** `index: { name: "by_author_status", additionalFields: ["status"] }` on the
  first field, or a collection-level entry:
  `indexes: [{ name: "by_author_status", fields: ["author", "status"] }]`.
- **Search indexes:** `searchIndex: { name: "search_title", filterFields: [] }` on a `text()`,
  `textarea()` or `email()` field.

VexCMS adds some indexes of its own:

- Every `relationship()` field gets `by_<fieldKey>`, unless the field declares its own `index`
  (as `author` does above) or the collection lists an index with that name.
- When another collection has a relationship to this one, the collection gets a search index on
  its `useAsTitle` field, unless that field declares its own `searchIndex`.

An index that only the generated table has is safe: Convex builds it from the existing documents
when you push. An index that only your table has must be declared, or any function that uses it
breaks.

differs, the CLI prints a warning like this one:

```txt
[vex] convex/schema.ts defines table "posts" by hand, and convex/vex.schema.ts generates a different "posts" table. Convex uses the hand-written one; the generated table is not wired in.
  fields only in convex/schema.ts: legacyFlag
  fields with different validators: author
  indexes only in convex/schema.ts: by_author
Describe these differences in the "posts" collection, then replace the hand-written entry with the generated import. See https://docs.vexcms.dev/guides/adopt-existing-tables/
```

- **Fields only in `convex/schema.ts`:** add a field for each one. If you don't, every document
  that holds the field fails validation.
- **Fields only in `vex.schema.ts`:** a field VexCMS added. It's safe when it's optional;
  otherwise, existing documents fail validation.
- **Different validators:** match the mapping table above, or accept a looser validator (see
  [When no field matches exactly](#when-no-field-matches-exactly)).
- **Indexes:** see [Keep your indexes](#3-keep-your-indexes).

When the warning is gone, or only lists differences you've decided to accept, delete the
hand-written `posts: defineTable(...)` entry from `convex/schema.ts`. The next `vex dev` adds
`posts` to the import from `./vex.schema` and to `defineSchema`. Then Convex validates every
existing document against the generated table.

The warning prints once per table per `vex dev` session, and again only when the difference
changes. It also fires when an index chained onto an imported generated table
(`posts: posts.index("by_slug", …)`) reuses a generated index's name, because Convex rejects
duplicate index names.

### What the comparison can't see

- **Computed keys.** The CLI reads `convex/schema.ts` as text, so a key like
  `[TABLE_SLUG_POSTS]: defineTable(…)` is never compared. Use a literal key (`posts:`) while you
  adopt the table.
- **Equivalent spellings.** Field order, whitespace, quotes, trailing commas,
  `v.float64()` versus `v.number()` and `v.nullable(x)` versus `v.union(x, v.null())` are treated
  as equal. Other spellings of the same validator show up as different.

table with a different name. Both are part of **Brownfield adoption** on the
[roadmap](/roadmap/).
``````
