00 — HOW TO READ THIS
Three rules that resolve every ambiguity.
Tokens decide colour

If a surface, text, or border colour is named in this document it is a semantic token. Any hex you see here is documentation of the theme document's values, never something to type into a component. Code-pane colours are the one exception and live in @theme, not in the theme record.

Fields decide content

Every element below maps to a field on its block. Nothing is hand-authored per page. Where a design wants a list, it is an array(group{…}); where it wants emphasis inside prose, it does without — there is no rich text.

Every block stands alone

Each block owns its own vertical padding and its own container. Two of any block stacked in any order must read correctly, on a page this document never describes. Section B is therefore normative; section C is only a seed order.

Specimens in this document render dark. The marketing site is dark by default (a light theme is one admin edit away and every specimen below is token-only, so it survives the swap). Specimens are drawn at desktop proportions; the spec rows beneath each one carry the mobile and tablet values.

01 — LAYOUT & VERTICAL RHYTHM
One container, one rhythm, three breakpoints.
BREAKPOINTS
Mobile < 640 · tablet 768–1024 (md/lg) · desktop ≥ 1280 (xl). Nothing changes above xl except centring.
CONTAINER
mx-auto w-full max-w-[1280px] px-5 md:px-8 xl:px-10 — 20 / 32 / 40px gutters. Prose-only sections nest a second measure: max-w-[46rem] (736px), never wider, so body copy stays at 62–72 characters.
SECTION PADDING
Standard block: py-14 md:py-20 xl:py-28 (56 / 80 / 112px). Quiet blocks (Stats, compact Hero): py-10 md:py-14 xl:py-16. CTA is the only block that gets py-16 md:py-24 xl:py-32. Adjacent blocks never collapse padding — the double gap is intentional and is what makes 80px of whitespace read as structure.
SECTION SEAMS
No block paints its own background except Stats and CTA (bg-card, full-bleed, border-y border-border). Everything else sits on bg-background. Max two surfaces visible per scroll — that is the "1–2 background colours" rule.
GRID & GAPS
Card grids: gap-4 md:gap-5 xl:gap-6 (16 / 20 / 24px). Text-to-element stacks use a 4px scale: 8 / 12 / 16 / 24 / 40. Heading-to-subheading is always 16px; subheading-to-content is always 40px on desktop, 28px below md.
SECTION HEADER
One pattern, every block that has heading + subheading: left-aligned, max-w-[36rem], h2 then subheading in text-muted-foreground, 40px above the content. Centred section headers are used only in FAQ and CTA. When subheading is blank the gap drops from 40px to 32px — the h2 does not grow to compensate.

03 — MOTION
Two keyframes, one easing, one blessed loop.

Everything below uses the shipped AnimatedGroup / AnimatedItem / TextEffect kit. No section adds a new keyframe except the two declared here, and no element animates on scroll — entrances fire on mount, which keeps every block a server component.

/* globals.css — the only additions to the shipped kit */

@keyframes livepulse {          /* the one decorative loop: In-progress dot */
  0%, 100% { opacity: 1; }
  50%      { opacity: 0.35; }
}

.live-dot { animation: livepulse 2s var(--ease-emphasized) infinite; }

/* stagger contract — set on the group, read by each item */
.reveal-group > * { --reveal-delay: calc(var(--reveal-stagger, 60ms) * var(--i, 0)); }

@media (prefers-reduced-motion: reduce) {
  .item, .live-dot, .reveal-group > * { animation: none !important; }
  /* reduced motion is a full stop, not a shortened duration:
     final state is painted immediately, opacity 1, no blur, no translate */
}
ENTRANCE BUDGET
Above the fold only. Hero (full) animates: badge 0ms → h1 by word 80ms + 40ms/word → subheading 280ms → CTA row 380ms → install row 460ms. Hero (compact) animates h1 and subheading only, 0 / 100ms, no word split. Every other block on the page renders static — a page whose sixth section fades in on mount is a page that flashes on refresh.
INTERACTION
transition-colors duration-[180ms] ease-[var(--ease-emphasized)] on every interactive surface. Background and border colour and opacity only — never width, never scale, never a shadow change. Active state is translate-y-px. Accordion and mobile sheet use tw-animate-css height/opacity utilities at 200ms.
FOCUS-VISIBLE
Global: outline-2 outline-offset-2 outline-ring plus ring-[3px] ring-ring/28 on filled controls. Never removed, never restyled per block, and it must be visible against both bg-background and the code-pane surface.

LAYOUT
Standard padding py-14 md:py-20 xl:py-28, container, left section header at max-w-[36rem], 40px above the grid. Grid grid-cols-1 md:grid-cols-2 xl:grid-cols-3. Instead of a gap the grid is a hairline mesh: wrapper gap-px bg-border border border-border rounded-md overflow-hidden, each cell bg-background p-6. That is the deviation from the sourced Tailark card grid and it is deliberate: 1px seams read as precision tooling, and they remove six drop shadows that dark mode is not allowed to have.
CARD INTERIOR
Icon frame 32px, border border-border rounded-sm, Icon size-4 text-primary centred, 16px above the title. Title 17px/600 (xl:text-lg) text-foreground. Description 14px/1.6 text-muted-foreground, 8px above, no measure cap (the cell is the measure), text-wrap: pretty. Cells stretch to the tallest in the row; content is top-aligned. This is the one place ember appears six times on a page — permitted because the icon is 16px and monochrome elsewhere.
ICONS
Lucide names, verified against icons: Wand · ShieldCheck · Radio · Lock · Boxes · LayoutGrid. Blank or unresolvable icon: the 32px frame is dropped entirely (not left empty) and the title moves to the top of the cell. A mixed array — some icons, some not — is a valid state and looks intentional because titles stay top-aligned.
STATES
Cards are not links and take no hover. If a future href field is added, hover is bg-accent on the cell and nothing else — no lift, no border colour change.
EMPTY & OVERFLOW
1 item: one full-width cell — acceptable, because the mesh border makes it read as a panel rather than a stranded card. 2 items at xl: two cells, third column empty; do not centre. 12 items: 4 rows of 3, no pagination, no "show more". Blank subheading: header gap 32px. A three-line h2 is fine — max-w-[36rem] makes it likely and the 40px gap below is fixed.

LAYOUT
Standard padding, container, left section header. Two panes: one shared frame — border border-border rounded-md overflow-hidden — split grid xl:grid-cols-[1fr_1px_1fr] with a bg-border seam, so the pairing reads as one artefact rather than two cards. Bar h-10, bg-card border-b border-border px-3.5, flex items-center justify-between gap-3. Left: label as 11px/500/+0.08em uppercase — text-primary on the authored pane, text-muted-foreground on every other pane (that single colour difference is the whole "hand-written vs generated" signal); then filename in mono 12px text-muted-foreground truncate. CODE BODY
Surface bg-[--color-code-bg] (a non-theme @theme token, §D) — code stays dark in both themes on purpose. p-4 mobile / px-4 py-[18px] desktop, mono 12.5px desktop and 12px mobile, leading-[1.7], tab-size: 2. No line numbers — they add 40px of noise and nothing is ever referenced by line. No traffic-light dots.
LONG LINES
Never wrapped, never truncated: the pre is overflow-x-auto overscroll-x-contain with white-space: pre, and each pane scrolls independently. The scrollbar is styled thin with a --color-code-border thumb and only occupies space when needed. Panes cap at max-h-[560px] (420px below md) and then scroll vertically inside the frame; the frame itself never grows past that, so a 400-line paste cannot destroy the page rhythm. Mandatory grid guard: the split is grid-cols-[minmax(0,1fr)_1px_minmax(0,1fr)] and both pane columns carry min-w-0. Without it a 1fr track resolves to minmax(auto,1fr), the pre's longest line sets the min-content width, the columns overflow the frame, and overflow-x-auto never engages — the code is clipped instead of scrolling. Same guard on the tab-mode panel and on the Split media: "code" column. Horizontal scroll containers get tabindex="0" and a role="region" label so keyboard users can reach them.
CAPTION
Optional caption sits outside the frame, 12px below, 13px/1.55 text-muted-foreground, aligned to its own pane's column. If no pane has a caption the row is not rendered. If one of two has one, the other column stays empty — captions are per-pane annotations, not a shared footer.
3+ PANES
Tabs from @vexcms/react, one TabsTrigger per pane using label. The TabsList replaces the chrome bar inside the same frame: h-10 bg-card border-b border-border px-2, triggers 13px/500 rounded-sm px-3 py-[5px], rest text-muted-foreground, hover text-foreground, selected bg-background text-foreground with a 1px bg-primary underline via inset shadow. The active pane's filename moves to the right end of the list. Tab panels are all rendered server-side and hidden with hidden, so switching costs no request; the frame takes the tallest pane's height to stop the page jumping. One pane: the frame renders alone, full width, no tabs. Zero panes: the block renders nothing at all, not an empty frame.

Magic UI's code-comparison supplies the shiki-in-a-server-component approach and the two-pane frame; its next-themes hook is dropped (shiki is invoked once with the dark theme because the pane is always dark), its filename-bar icons are dropped, and its diff highlighting is not used — this section compares two files, not two revisions.

Build a minimal shiki theme whose scopes point at the five code colours above rather than shipping a stock theme: comment → dim · keyword, storage.type, constant.language, support.type.primitive → key · entity.name.function, entity.name.type, support.class → ident · string, constant.numeric → string · punctuation, meta.brace → punct · everything else → code-fg. Five colours is the whole palette: ember appears only on keywords, which is why a config file reads as ember-accented and a generated type file reads as almost entirely neutral — the visual argument of the CodeShowcase section.
FONTS
next/font/google — Geist (400/500/600/700/800) as --font-sans, Geist_Mono (400/500) as --font-mono, both display: "swap". The theme record's fontFamily string is the fallback stack applied as a custom property, so an editor can change the family without a redeploy. Mono is enabled with font-feature-settings: "ss01" 1, "calt" 1.
BASE LAYER
::selection → bg-primary/22, colour inherited. Prose links inside text field output: text-primary, underline-offset-4, decoration-current/40 → full on hover. scroll-behavior: smooth only outside reduced motion. A skip to content link in the layout, visually hidden until focused, sits above the sticky header.

Coherent at every step.
01
Theme + @theme tokens. Load the theme record, apply the 32 properties server-side, add §19 to globals.css. Verify a dark/light swap on a bare page before any block exists — every later step assumes it.
02
Chrome: Header + Footer. Sticky behaviour, mobile sheet, wrapping footer row. Now every route has a frame and nothing looks unfinished.
03
Hero, both variants. Build compact first (it is the simpler shape and unblocks the two interior pages), then full with the install row and the decorative background. At the end of this step all three routes render a real page-header.
04
CodeShowcase. The hardest and most important block, and the source of the shared pane primitive Split needs. Do the shiki server pass, the pane chrome, the copy button, the long-line scroll, and the tab mode here — not in a later refactor.
05
CTA, then Features. CTA is 30 minutes and closes all three pages. Features gives home and /features their body. Home is now shippable: hero → features → code → CTA reads as a complete site.
06
Stats, HowItWorks, FAQ. Three independent, low-risk blocks that finish the home page. Stats first — it is the only other bg-card band and it validates the surface rhythm.
07
Split. Reuses step 4's pane. Build code, then none, then image with its fall-through. Completes /features.
08
Roadmap. Last, because it is the only block with real branching logic and it blocks nothing else. Statuses and grouping before the tab filter; the page must be correct with JS disabled first.
09
Seed, then audit. Run the idempotent seed. Then four passes: theme swap to light on all three pages; prefers-reduced-motion; keyboard-only traversal including the code panes' scroll regions; and a fresh-scaffold check with the media library emptied — no section may look broken.
21 — DEVIATIONS
Everywhere I left the brief.
Features card grid
Tailark Mist features/two uses gapped cards with shadow. Replaced by a 1px hairline mesh (gap-px bg-border). Reason: dark mode is forbidden shadows, so gapped cards lose all separation there; the mesh reads identically in both modes and suits sharp radii.
Hero background
The sourced hero-section/five radial gradients are replaced by a token-derived hairline grid plus one bg-primary/10 blur. Reason: the originals bake in palette colours and break on a theme swap; the design system also bans gradients on chrome. Its logo row is dropped as instructed (no customer logos exist, and none may be designed for).
FAQ is two columns
Veil faqs/two centres the header over a narrow accordion. Split into header-left / accordion-right. Reason: it gives the support link a home, holds answers at a 68ch measure, and stops the centred-heading pattern from appearing three times on one page.
Timeline → rail
Origin UI's timeline dots-and-lines are replaced by border utilities and a mono index. Reason: its radix-ui Slot.Root had to go anyway (converted to concrete elements, no Base UI render prop needed), and a horizontal four-up rail suits a four-step install flow better than a vertical timeline, which implies duration.
Roadmap group order
Rendered In progress → Planned → Exploring → Shipped, not the brief's Shipped-first order. Reason: the brief itself says In progress is the most interesting bucket and Shipped is skimmed. Putting 15 shipped rows above the 2 rows people came for buries the news. Statuses, labels, and claims are unchanged.
Dark primary ink
Dark-mode primaryForeground is near-black, against the design system's "white on the primary button, never gray" rule. Reason: white on oklch(68% 0.178 40) is 2.6:1 and fails AA at any size. Near-black is 6.0:1. The rule's intent — never muddy grey ink on orange — is preserved.
Code panes stay dark
Pane surfaces come from fixed @theme tokens, not the theme record, so they do not follow a light theme. Reason: the brief permits code-pane colours as additional non-per-theme tokens; it also means shiki highlights once at build with one theme and the client ships nothing. A light theme therefore shows dark code panes — deliberate, and consistent with the design system's "code blocks are the hero visual".
CodeShowcase chrome
Magic UI's next-themes dependency, filename icons, and diff highlighting are all dropped; a shared frame with one seam replaces two separate cards, and the authored pane's label is the only element carrying text-primary. Reason: this section compares two files, not two revisions, and the label colour is a cheaper "human vs machine" signal than any badge.
Footer sitemap
Mist footer/three's labelled multi-column groups are replaced by a single wrapping row. Reason: links is one flat array with no group field — column headings would be content the CMS cannot store.
Copy tightened
Two additions, no factual change: a Features section header ("Built for the way you already work." / "Familiar collection patterns, with the generation step done for you.") and a HowItWorks heading ("From empty directory to live content."), because both blocks require heading and the brief supplies only their card copy. FAQ answers are phrased to keep versioning, drafts, live preview, and rich text explicitly unshipped, and the licence is stated as Apache-2.0 throughout — including in the design system's own README, which says MIT and is wrong.
Not designed
No pricing, blog, changelog, testimonials, comparison table, logo wall, star count, or download figure — and no empty slot where one could go. Quartz was not opened or referenced.
