# Docs Site & README Conventions

- Starlight sidebar (`apps/docs/astro.config.mjs`): Introduction, Roadmap, Guides/
  (`.mdx`/`.md`), Fields/ (autogenerated from the fields content dir), and the API
  Reference injected by `typeDocSidebarGroup` — never hand-list `api/*` slugs; the plugin
  owns that group.
- **starlight-typedoc is ENABLED and multi-package.** `astro.config.mjs` documents all
  currently-implemented library packages as entry points: `@vexcms/core`, `@vexcms/react`,
  `@vexcms/next`, `@vexcms/better-auth`, `@vexcms/file-storage-convex`. `@vexcms/richtext-plate`
  is intentionally excluded until it has real exports. Add a new package's `src/index.ts`
  to the `entryPoints` array when it's ready to document.
- **Resolve strategy, not packages strategy.** TypeDoc compiles all entry points as ONE
  program via `apps/docs/tsconfig.typedoc.json` (globs every documented package's `src`,
  excludes tests/fixtures/`convex`/`dist`). Do NOT switch to `entryPointStrategy:"packages"`
  — per-package compilation of this generic-heavy source produces thousands of
  cross-program type-identity errors, and the repo's `dts:false` (tsup) leaves no `.d.ts`
  to resolve against. See ADR-001.
- **Zero-warning contract is ENFORCED:** `typeDoc.treatWarningsAsErrors: true` in the
  starlightTypedoc options. Any broken `{@link}`, undocumented referenced type, unknown tag,
  or bad `@example`/`@param` fails `pnpm --filter docs build`. Keep it green.
- `apps/docs/src/content/docs/api/**` is GENERATED output (gitignored). Never hand-edit or
  link to specific generated slugs from config.
- Field doc pages (`apps/docs/src/content/docs/fields/<name>.mdx`, kebab-case): summary →
  use cases → basic usage (from the config fn's JSDoc) → options table (from
  `<Type>FieldInput`) → defaults block → 2-3 examples. Field config JSDoc IS the primary
  reference; pages curate it.
- Package READMEs (`packages/*/README.md`): description, quick start, features, key
  exports table, peer dependencies, links. READMEs teach; JSDoc/TypeDoc are reference.
- Hand-written docs content files are kebab-case `.mdx`/`.md` under
  `apps/docs/src/content/docs/` (the generated `api/` subtree is exempt).
