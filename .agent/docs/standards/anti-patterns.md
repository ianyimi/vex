# Anti-Patterns

Corrected agent mistakes. Append-only: `- AP-NNN (YYYY-MM-DD, seen Nx) rule`. Never compact.

- AP-001 (2026-08-12, seen 1x) Never default a type parameter to `Record<string, never>` — its `keyof` is a string index signature that poisons mapped-type intersections (collapses sibling unions to `never`); default optional record generics to `{}`.
- AP-002 (2026-08-12, seen 1x) Never assert an inline object type just to read a property (`(x as { y: string }).y`), including in test fixtures — use a named const with a one-line reason or a real `in`/`typeof` guard.
- AP-003 (2026-08-12, seen 1x) Never constrain a registry-map `infer` to the ENTRY type (`infer D extends VexDocument` on a slug→doc map) — the constraint describes the map, not its values; a failed `extends` silently collapses the whole registry to its fallback with errors surfacing far from the cause.
- AP-004 (2026-08-21, seen 1x) Never gate a mapped-type value on a conditional whose `extends` side references a type parameter that may lack an inference candidate (e.g. `A extends TSubjects[S]["queryAction"]` while those generics are being inferred from the same object literal) — the conditional DEFERS, supplies no contextual type, and every implicitly-typed callback param silently becomes `any`. Order closed built-in unions first so only names that exist because the parameter was supplied reach the parameter-dependent branch.
- AP-005 (2026-08-21, seen 1x) Never rely on a `Partial<Record<union, V>>` generic bound to reject typo'd keys — an all-optional target is a weak type, so TypeScript errors only when the object shares ZERO keys with it; one valid entry beside a garbage key passes silently. Enforce key-exactness with an intersected `{ [K in Exclude<keyof T, union>]: never }` map, and add a concrete `Partial<Record<union, V>>` constituent so the completion engine has a resolvable contextual type (a bare type parameter offers no completions).
- AP-006 (2026-08-21, seen 2x) A type parameter that appears in an interface BODY makes its default part of the bare type's supertype contract — defaulting it narrow (`TOrgSlug = undefined`, `TCustomActions = {}`) silently breaks assignability for every concrete instantiation carrying a real value. Default body-visible params to their full bound and pin with a concrete→bare assignability test.
- AP-007 (2026-08-21, seen 1x) Registry augmentation keys fail SILENTLY on mismatch — a one-character emitter/consumer drift (`CustomActionsBySlugs` vs `CustomActionsBySlug`) resolves the registry to its fallback with zero errors. Emission tests must assert the exact member name (`not.toContain` the drifted spelling). And empty registry entries emit `{}`, never `never`: `keyof never` is `string | number | symbol`, which detonates every downstream `extends Record<…, string>` constraint.
- AP-008 (2026-08-21, seen 1x) Never union a whole feature action-set (`DraftAction`) into a shape-specific position — `QueryAction` already carried `readDrafts`, so `QueryAction | DraftAction` only added the MUTATION-shaped draft verbs to every query position. Compose verb unions by shape (`Exclude<DraftAction, QueryAction>`), not by feature.
- AP-009 (2026-08-21, seen 2x) Spec test blocks must be complete copy-paste implementations — real imports, real fixtures, exact expected values, written against the target file's actual harness. Comment placeholders standing in for fixtures shipped twice and both times produced non-working tests the developer had to skip.
- AP-010 (2026-08-30, seen 4x) A `@ts-expect-error` whose comment admits it does not understand the error ("Lucide Icon names match here, unknown lsp error", ×3) is an unread bug report. All three marked the same real defect — two same-named types that had silently diverged — and hid it for weeks. If the reason cannot be stated precisely, the directive is not ready to be written; diagnose first. Corollary: after any type-level fix, `TS2578: Unused '@ts-expect-error'` is a signal to read, not noise to suppress.
- AP-011 (2026-08-30, seen 1x) Never leave a "temporary" build-config disable without an expiry condition that something checks. `dts: false, // Temporarily disable DTS to fix CPU issue` sat in all 7 packages while `package.json` advertised `types: "./dist/index.d.ts"` — every published tarball resolved to `any`, and nothing failed because no test consumes the built artifact the way a consumer does. Pair any such flag with a gate that fails when the promise it breaks is still being made.
- AP-012 (2026-08-30, seen 3x) Never write an acceptance criterion that cannot pass. Three spec steps demanded `git diff --exit-code pnpm-lock.yaml` after removing a dependency and after repointing specifiers to `catalog:` — both necessarily rewrite the lockfile, so the gate could only ever fail. Write the invariant that actually holds and can be measured: the lockfile only SHRINKS (0 insertions) and no `-version: X` pairs with a `+version: Y` for the same package. A criterion is part of the deliverable; if it has never been executed, it is a guess.
- AP-013 (2026-08-30, seen 2x) Never conclude a gate works because it exited 0 — prove it by making it FAIL. `strict-peer-dependencies=true` in `.npmrc` is silently ignored by pnpm 10: a plain install PRINTED `✕ unmet peer` and still exited 0, and it went unnoticed because every scratch test had also passed `--strict-peer-dependencies` on the CLI, testing the flag rather than the config. The same run shipped a `--sweep` selector whose filter emptied the check list, so it exited 0 having run zero checks. Both were caught only by deleting a rule and requiring exit 1. Any new gate needs a negative test in its verify block.
- AP-014 (2026-08-30, seen 1x) Never assert current state from an artifact that records a past or pruned run. `node_modules/.modules.yaml` reported `ignoredBuilds: []` and that was written into a spec as "nothing in the tree needs a build script"; the file carried a `prunedAt` stamp and a fresh install blocked SEVEN (core-js, esbuild x2, msw x2, sharp, unrs-resolver). Re-derive from a clean run before stating a fact about the tree.
- AP-015 (2026-08-30, seen 1x) Never claim a guarantee broader than the mechanism delivers. "Nothing in this repo can silently move" was written on the strength of pinning the catalog, which pins DIRECT dependencies only — a measured lockfile-less resolve floated ~250 transitive packages. State the scope the mechanism actually covers and name what still carries the rest (here: the committed lockfile, hence `--frozen-lockfile` in CI).
- AP-016 (2026-08-30, seen 1x) Widening a `peerDependency` from exact to a range changes what pnpm INSTALLS locally, not just what consumers see: an unsatisfied peer is auto-installed at the range's maximum, landing a second copy beside the catalog-pinned one. `packages/react` declared none of its 7 peers as devDependencies, so a from-scratch resolve produced `@tanstack/react-query` at both 5.101.2 and 5.102.8 and `docs#build` failed with `TS2322` on `relationship/Input.tsx` — structurally identical types from two module identities. Any peer-range change must be validated by a lockfile-less resolve plus a build, not by an incremental install (see P-014).
- AP-017 (2026-08-30, seen 1x) Never identify one artifact among many by a key they all share. A verification script located each package's tarball with `readdirSync(dir).find(f => f.includes(pkg.version))`, but all 8 packages carry the same version, so every iteration re-read the FIRST tarball and cheerfully attributed `create-vexcms`'s dependencies to five other packages. Isolate per item (one output directory each) and assert the expected count instead of pattern-matching a shared name.
- AP-018 (2026-09-02, seen 3x) Never name a root cause from a plausible mechanism — instrument until something names the writer. A `select` opened below the fold threw the page 1341px, and three consecutive "fixes" landed on real but innocent mechanisms: Base UI's `modal` scroll lock, `alignItemWithTrigger`'s deliberate page scroll, and a global `scroll-behavior: smooth`. Each was defensible, each was verified only by re-measuring the symptom, and none was the writer; the developer had to revert all three. The actual cause needed a stack trace on the real component: cmdk `scrollIntoView`s its highlighted item in a mount-time layout effect, while a floating popup still sits unpositioned at the end of `<body>`. A fix whose evidence is "the symptom moved" is a guess — require the call site.
- AP-019 (2026-09-02, seen 2x) Never trust a browser-tool probe without first proving the probe can see the page. Prototype patches installed via the automation tool run in an ISOLATED JS world (`window.next` undefined), so two "zero forensics logs" results were false negatives that misdirected the whole investigation; the page bundle has to mirror instrumentation into the DOM to be readable. Compounding it, `page.click` scrolls the target into view over CDP before clicking, which manufactured a phantom −570px delta. Assert the instrumentation is live (a sentinel value read back through the same channel) and drive interactions in-page before believing any measurement.
- AP-020 (2026-09-02, seen 5x) Never accept typecheck + build as evidence that a scaffolded template works — only running the scaffold finds template defects. Five shipped while every gate was green: `turbopack.root` pinned to the app dir broke `--monorepo` builds, a base `page.tsx` collided with the marketing home on `/` and won, a fail-closed proxy matcher sent public routes to sign-in, `anyApi` discarded types the generated `api` already had, and `<img src={uploadField}>` set `src` to a Convex document id. Template changes need a real scaffold run in every supported mode as the acceptance gate.
- AP-021 (2026-09-02, seen 2x) An unquoted glob in a package.json script is evaluated by whichever shell the package manager picked, so the file set silently differs per platform. `eslint packages/*/src/**/*.{ts,tsx}` on macOS (bash) expanded the braces and collapsed `**` to ONE directory level — 163 files, 0 errors — while on Linux CI (dash, no brace expansion) the pattern failed to match, passed through literally to eslint, and minimatch expanded `**` recursively: 115 errors in files the developer's machine had never linted, including every file sitting directly in `src/` and everything nested 2+ levels deep. A local gate that disagrees with CI is not a gate. Quote every glob (`eslint "packages/*/src/**/*.{ts,tsx}"`) so the tool does its own expansion identically everywhere, and treat "CI fails but it passes locally" as evidence the two are running different inputs, not as CI flakiness.
