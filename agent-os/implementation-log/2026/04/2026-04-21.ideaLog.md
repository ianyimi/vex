## Deviations from spec

- `collections/typeGen.ts` → `collections/interfaceGen.ts` — renamed because `interfaceGen` better describes what it does (generates TypeScript interfaces, not just types)
- **Config split**: Spec had `SchemaConfigInput.typesOutputPath` / `SchemaConfig.typesOutputPath` nested under `config.schema`. Developer created separate `TypesConfigInput`/`TypesConfig` at `VexConfigInput.types` / `VexConfig.types`. Default output path for `vex.types.ts` is `/src/vex.types.ts` (placed next to `vex.config.ts`), not `/convex/vex.types.ts`
- **Select fields in interfaces**: Spec said defer typed select option types to a future spec. Developer implemented it now — `collectionConfigToInterface` generates `type StatusOption = "draft" | "published"` subtypes and uses the option type name (or `{FieldKey}Option`) as the field type
- **`schema/migrate.ts` added out-of-scope**: CLI lib (`packages/cli/src/lib/generateSchema.ts`) already imports `diffSchema`, `makeFieldsOptional`, `addRemovedFieldsAsOptional`, `planMigration` from `@vexcms/core`. Stubs satisfy these imports without requiring `@ts-nocheck` on the CLI lib
- **ESLint disable comments in `generateVexTypes`**: Generated `vex.types.ts` files include `/* eslint-disable perfectionist/sort-union-types */` etc. at the top to suppress sort-order lint errors on auto-generated code
- **`packages/cli/src/schema/generateSchema.ts` NOT deleted**: Spec said to delete this stale stub. Still present
